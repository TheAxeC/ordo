## What to build

When the step is done, `/paper edit <main.tex> <edits file>` exists as `paper`'s thirteenth mode, as ADR 0062 decides with the rulings of Open item G, and every page, figure and count of the repository that lists `paper`'s modes holds it.

### 1. `skills/academic/paper/templates/apply_tex_patch.py`

- A new op kind `fill_gap`, with the fields `op_id`, `kind`, `block_id`, `old_hash`, `marker`, `occurrence`, `roadmap_item_ids` and `rationale`, and `answer` in place of `new_text`.
  - `marker` is one gap marker: a text that starts with `[GAP:`, ends with `]`, holds `[GAP:` once and holds no `]` before its last character. Any other `marker` is a `validation` problem.
  - `occurrence` is a whole number from 1, not a boolean: the place of that marker among its occurrences in the old block, counted from the block's start. A missing, zero, negative or non-integer `occurrence`, and one above the number of occurrences in the block, are each a `validation` problem.
  - `answer` is a string that is not blank and holds no blank line. Any other `answer` is a `validation` problem.
  - A `new_text` on a `fill_gap` op is a `validation` problem, so the writer cannot send a block of its own.
  - The script builds the new block itself: the old block with that one occurrence of `marker` replaced by `answer`, every other byte as it was. The replacement is a plain string splice, so a backslash or a gap marker in `answer` stands in the output as written and is never replaced again.
  - Several `fill_gap` ops may name one block, each on a different occurrence of the old block. They are all built on the old block, so one op's answer does not shift another's occurrence. An op of another kind beside a `fill_gap` op on one block is a `validation` problem, as is a second op of another kind on a block, as now.
  - `old_hash` and the hash checks are those of every op. The apply report and the self-check treat the built block as the op's new text.
  - A `fill_gap` op does not count toward the block ratio of `structural_flags()`, since it changes nothing but its marker. The heading and section checks hold for it: a `fill_gap` on `\section{[GAP: title]}` is `structural`, exit 3, as any rewritten heading is.
- A new option `--allowed-blocks <file>`.
  - The file holds one line per block: the block id, then one or more op kinds, separated by spaces, such as `B0012 fill_gap` or `B0008 replace_block`. A blank line is skipped.
  - A line of any other form, a kind that is not one of the four, a block named on two lines, a block id the manifest does not hold, and a file that cannot be read are each a usage error printed on standard error that names the line or the file, with exit 2 and the base untouched.
  - With the option, an op on a block the file does not name, and an op of a kind its block's line does not name, are each a `validation` problem naming the op and the block, listed with every other validation problem. This holds under `--check-only` too.
  - With the option, the block ratio is not a structural flag, since the file already confines the patch to the blocks the session found; the heading and section checks stay.
  - Without the option, the script behaves as it does now, `fill_gap` accepted on any block.
- The docstring lists the new op kind with its fields, the several `fill_gap` ops on one block, the option, the file's form, the new problems, the new usage errors and the ratio rule, in the places where it lists the others; line 32's one-op sentence is rewritten to the new rule.

### 2. `skills/academic/paper/templates/anchorize_tex.py`

- A new option `--find '<text>'`: the script prints one line per place a block holds the text, `<block id>` alone, in the manifest's order, and writes no manifest. A manifest standing beside the file is left as it was.
  - The search is exact except that a run of spaces, tabs and line breaks in the text, and in the block, matches any such run, and whitespace at the text's two ends is dropped (Open item G (3)). A blank line ends a block, so no text is found across one.
  - A block that holds the text twice gives two lines, so the session counts places by lines.
  - The text is read as written: a quote, a backslash or a brace in it is matched as that character.
  - A text found nowhere prints nothing and exits 0.
- A second option `--marker '<marker>'`, only with `--find`: each line then reads `<block id> <occurrence>`, the occurrence being the place, among the marker's occurrences in the block counted from 1, of the occurrence that stands inside that place of the text. A text that does not hold the marker once is a usage error, exit 2.
- `--find` with an empty or blank text, `--marker` without `--find`, and `--find` with `--print-blocks` are each a usage error printed on standard error, exit 2.
- Its docstring lists the options, what they print, the whitespace rule and that `--find` writes nothing.

## Cases

`apply_tex_patch.py`:

- `fill_gap` applied: a block `Funded by [GAP: funding statement].` with `marker` `[GAP: funding statement]`, `occurrence` 1, `answer` `the Example Foundation`: applied; the output block is `Funded by the Example Foundation.`, and every other byte of the file is as it was.

- Two `fill_gap` ops on one block: `Funded by [GAP: funder] under grant [GAP: grant number].` with one op per marker: both filled in one apply.
- Two `fill_gap` ops on the same occurrence of one block: rejected, `validation`, exit 2, the problem naming both ops.
- A `fill_gap` and a `replace_block` on one block: rejected, `validation`, exit 2, the problem naming the block.
- `fill_gap` with an `occurrence` above the count in its block: rejected, `validation`, exit 2, the problem text naming the occurrence and the count, the base untouched.

## Decisions taken in this brief (each reversible, none silent)

1. The file of allowed blocks is plain text, one line per block, `<block id> <kind> [<kind>]`. The session writes it and the script reads it, never the user, so it is no user-visible format.
2. `--find` writes no manifest and exits 0 whether or not a block holds the text, so it can run before or after an anchorize without changing the manifest, and an empty output is the "found nowhere" of `### edit` item 2.
3. `--marker` gives the occurrence a `fill_gap` op names, so the occurrence comes from the script, a fact, and not from the writer's count.
4. `occurrence` counts from 1 within the old block, and several `fill_gap` ops on one block are built on the old block, so a paragraph with two gaps is filled in one patch and the gap patch of Open item G (1) needs no second gap round.
5. A `fill_gap` `marker` holds one gap marker, so the op cannot stand in for a general replacement.
6. A `fill_gap` op does not count toward the block ratio, and under `--allowed-blocks` the ratio is no flag, since otherwise every item in a one- or two-block file, such as an input file holding only the authors or a short cover letter, would be the stop "A structural patch".
7. The compile fix and the `C<m>` patches of `edit` are confined to the blocks the run's patches changed, so no patch of the run reaches a block no item names.
8. The section `### edit` stands after `### response-letter`, the other mode `paper` added.

Decisions 3, 4, 5 and 6 were run on the template: `--find 'Author Name'` on a copy of `latex_article_template.tex` gives the two blocks B0008 and B0012, each holding the name once, and the file has 40 blocks, so a change of the author is two `replace_block` ops, 0.05 of the blocks, under the ratio in any case. A cover letter of one paragraph has one block, where one op is a ratio of 1.0, above 0.6, which decision 6 answers.
