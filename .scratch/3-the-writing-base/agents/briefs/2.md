## What to build

1. `skills/writing/templates/check_prose.py`, Python 3 standard library only, no PyYAML:
   - Usage: `check_prose.py [--limit '<section heading>=<words>']... <file>...`. Each file is Markdown (`.md`), LaTeX (`.tex`), or plain text (any other extension, read as Markdown without headings).
   - Output: one line per flag, `<file>:<line>: <check>: <message>`, sorted by file then line, where `<check>` is one of the names below and `<message>` quotes the text that triggered it (at most 60 characters of it).
   - Exit status: 0 when nothing is flagged, 1 when anything is flagged, 64 for a usage error (no file, a `--limit` that is not `<text>=<positive integer>`, a file that cannot be read or is not UTF-8), with the message on stderr.
   - The head docstring lists every input, every check with its rule, every error it prints and every exit status (change standard rule 14).
2. The checks, each with its name:
   - `non-ascii`: every character above U+007F that is not a letter (Unicode category `L*`), anywhere in the file, code included. An accented letter in a name passes.
   - `dash-aside`: in prose, an em dash or en dash; a spaced hyphen ` - ` inside a line (a list marker at the start of a line is not one); `--` in Markdown prose. In LaTeX, `---` anywhere in prose, and `--` with a space on either side; `--` between two digits (`3--5`, a number range) passes.
   - `history`: in prose, case-insensitive: "previously", "formerly", "was changed", "were changed", "was added", "added in", "moved from", "renamed from", "used to", "no longer", "as of", `step <number>`, and a date `YYYY-MM-DD`.
   - `section-words`: for each `--limit`, the words of the section whose heading text matches it (case-insensitive, surrounding whitespace ignored) are counted, and a count over the limit is flagged at the heading's line with the count and the limit. A section runs from its heading to the next heading of any level. Headings: Markdown `#` to `######`; LaTeX `\section`, `\subsection`, `\subsubsection` (starred forms too) and `\begin{abstract}`, which is the section "Abstract" up to `\end{abstract}`. A `--limit` that matches no heading in a file is flagged at line 1 of that file.
   - `semicolons`: over running prose (see "What counts as prose"), when semicolons times 1000 is more than 2 times the words, every semicolon line is flagged with the count and the word total.
   - `throat-clearing`: in prose, case-insensitive, each phrase of section C of the prose standard, and "This section explains", "The following covers", "Now that we", "With this setup complete".
   - `filler`, `vague` and `flagged`: in prose, each word of section A's three lists as a whole word, case-insensitive; `filler` for the banned filler words, `vague` for the vague qualifiers, `flagged` for the flagged words. The message says the word is to be checked, since section A allows temporal "just" and domain terms.
   - `equal-length`: five or more consecutive sentences of running prose (list items, headings, tables and code left out) whose word counts all lie within 2 words of each other (the longest minus the shortest is at most 2), flagged at the first sentence's line with the counts.
   - `contrast`: in prose, list items included, a sentence holding "not <1 to 4 words>, <word>" where the word after the comma is not one of and, or, nor, so, because, which, as, if, when; or "not <1 to 4 words> but <word>". A sentence counts once. When a file holds more than 2, each is flagged.
   - `colon-lists`: two consecutive paragraphs that each end with a colon and are each followed by a list, with nothing else between the first list and the second paragraph; flagged at the second paragraph's line.
3. What counts as prose:
   - Markdown: every line outside fenced code blocks (both backtick and tilde fences) and outside YAML frontmatter at the top of the file, with inline code spans removed; headings are prose for every check except `semicolons` and `equal-length`; table rows (a line starting with `|`) are prose for every check except `semicolons` and `equal-length`.
   - LaTeX: every line with comments (`%` not preceded by a backslash) removed, inline math (`$...$`, `\(...\)`) removed, and the contents of the environments `equation`, `align`, `verbatim`, `lstlisting` and `minted` (starred forms too) left out.
   - `non-ascii` reads every line, code and comments included.
4. `skills/writing/templates/check_prose.test.sh`, POSIX `sh`, in the shape of the tree's other tests: it builds its files under a scratch folder in `$TMPDIR`, removes it on exit, prints `PASS: check_prose.py scratch tests` and exits 0, or `FAIL: <case>` and exits 1.
   - A sample Markdown file and a sample LaTeX file, each with one planted violation per check (twelve checks, one `--limit` for `section-words`; for `contrast` the violation is three contrasts, and for `semicolons` enough semicolons to pass the limit); the test asserts, per check name, that the lines the script flags under that check are exactly the planted lines, and that it exits 1.
   - A clean Markdown file and a clean LaTeX file, holding for each check its near miss (an accented name, a list marker, a number range `3--5`, a hyphenated compound, a section under its limit, 2 semicolons in over 1000 words, two contrasts, four equal-length sentences, a colon-list paragraph followed by a plain paragraph, a table row with semicolons, code with an em dash in a fence, and so on); the test asserts empty output and exit 0.
   - The usage errors: no file, a bad `--limit`, a missing file, a non-UTF-8 file, each exit 64.
   - The non-ASCII characters are written with `printf` octal escapes so the test file itself stays ASCII.
   - Each assertion names its check, so turning one check off in a copy of the script turns the test red with that check's name in the `FAIL:` line.
5. `docs/dev/building.md`: the command block gains `sh skills/writing/templates/check_prose.test.sh` with a comment in the form of its neighbours, placed after the `utils/check_coverage.test.sh` line; and `docs/dev/change-standard.md`'s command block gains `sh skills/writing/templates/check_prose.test.sh 2>&1 | tail -1` in the same place. `README.md` line 46's requirements hold unchanged if the script uses no module outside the standard library; the builder rereads that line and says so.

## Cases

1. Must pass: `python3 skills/writing/templates/check_prose.py <sample.md>` with the sample's `--limit` prints, for each of the twelve checks, flags at exactly its planted lines, each `<file>:<planted line>: <check>: ...`, exit 1. The same for `<sample.tex>`.
2. Must pass: the clean Markdown and clean LaTeX files print nothing, exit 0.
3. Must refuse: no file, `--limit Abstract` (no `=`), `--limit Abstract=0`, a missing file, a non-UTF-8 file: each exit 64 with a message on stderr and nothing on stdout.
4. Must pass: `sh skills/writing/templates/check_prose.test.sh 2>&1 | tail -1` prints `PASS: check_prose.py scratch tests`, exit 0.
5. Must pass: for each check, a copy of the script with that check turned off (its function returning no flag) makes the test print `FAIL:` naming that check, exit 1. The report quotes the twelve red lines.
6. Must pass: `python3 skills/writing/templates/check_prose.py skills/writing/references/prose-standard.md` runs to completion (exit 0 or 1) and the report quotes its output; the flags it gives on the prose standard itself (which quotes the forms it bans) are listed, each with whether it is right under the rules above. No rule is loosened to silence one.

The builder's first task, before any code changes: turn every case above into a test of the step, run the tests against the unchanged tree, and note each case's result. No prototype script stands in for the tests.

When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives. The orchestrator rules on the case and resumes the builder with the ruling, and the final report carries it.

## Decisions taken in this brief (each reversible, none silent)

1. The file forms: Markdown, LaTeX and plain text, since the writing skills serve both the tree's pages and manuscripts.
2. The limits come as `--limit '<heading>=<words>'`, matched to a heading's text; the script holds no limit of its own for `section-words`. The other limits are the prose standard's numbers.
3. The output line `<file>:<line>: <check>: <message>` and the exit statuses 0, 1 and 64 follow the form of `grep -n` and of `verify.sh`'s usage status.
4. `equal-length` uses a band of 2 words over running prose with list items left out, and `contrast` counts list items and leaves out continuations. Both were run by the orchestrator, before this brief, on six real files (a prototype in the orchestrator's scratch folder, not handed to the builder):
   - `README.md`: 73 sentences, 0 contrasts, 0 runs.
   - `skills/writing/references/prose-standard.md`: 0 runs; its contrasts are the quoted examples "not a lint, a compiler" (line 14) and "not X, Y" (line 51), both in list items, so the count is 2 and nothing is flagged.
   - `docs/dev/skill-layout.md`: 0 contrasts, 0 runs.
   - research-hub `academic-paper/references/academic_writing_style.md`: with list items counted, one run at line 8 (`[7, 7, 9, 7, 9, 7, 7]`), which is a bulleted list ("- Use the most specific term available", "- Define technical terms on first use", ...); with list items left out, 0 runs. That is why list items are left out of `equal-length`.
   - research-hub `funding/2026-fwo-senior-meyfroidt/concept-note/concept-note.tex`: before continuations were left out, line 53 matched "not know, and", which is no contrast; after, 3 contrasts, at line 79 ("not the waveforms but M"), line 85 ("not a limitation to apologise for, it") and line 87 ("not the physics but the regime"), each a real binary contrast, so the file is flagged (3 is over 2). Line 87 matched both forms; a sentence counts once.
   - research-hub `funding/2026-nwo-veni-self-explaining-hospital/preproposal/veni2026.tex`: 150 sentences, 0 contrasts, 0 runs.
5. A flag is for a person to judge: `filler`, `vague`, `flagged`, `history` and `contrast` flag words the prose standard allows in some uses, and `/writing` (step 4) reports them with their line for the reader to decide. The script changes no file.
