# Step 2, the cases ruling (round 0)

The builder's first run of the brief's "Cases" found that the `dash-aside` rule flags every Markdown table separator row, so case 2 cannot pass with a clean file that holds a table. The brief `agents/briefs/2.md` still governs; these rulings replace the parts of its rules they name. Each keeps the prose standard's rule, which bans a dash used as an aside and leaves "a hyphen inside a compound word or a number range" alone (`skills/writing/references/prose-standard.md`, section 0).

1. **Table separator rows.** (a): a Markdown line made only of `|`, `-`, `:` and spaces, holding at least one `-`, is a table separator row and is not read by `dash-aside`. A data row of a table is read as before, so `--` or a spaced hyphen inside a table cell is still flagged. The clean Markdown file keeps its separator row; the forms file holds the near miss, a data row with `--`, flagged.
2. **Thematic breaks and HTML comment markers.** A Markdown line made only of three or more `-`, `*` or `_`, with optional spaces, is a thematic break and is not read by `dash-aside`. The markers `<!--` and `-->` are not read by `dash-aside`; the text between them is prose and is read by every check. The forms file holds a thematic break and a one-line and a multi-line HTML comment, each with a `--` aside inside the comment text, flagged.
3. **Number ranges with spaces.** A dash between two digits with one space on each side is a number range and passes: in LaTeX `2023 -- 31` (the date ranges of a tabular), in Markdown `2023 - 2024`. A spaced `--` or ` - ` with a letter on either side is still flagged (`Psychophysiology -- postdoctoral researcher`). The forms file holds both, in both file forms.
4. **LaTeX display math.** The prose rules also leave out `$$...$$`, `\[...\]` and the environments `gather`, `multline`, `eqnarray`, `displaymath` and `math`, starred forms too, beside the ones the brief names. Each gets a case in the forms file with a spaced hyphen inside the math, not flagged, and the same hyphen outside it, flagged.
5. **`non-ascii`.** A combining mark (Unicode category `M*`) that follows a letter or another combining mark passes, so a name typed in decomposed form passes as it does composed; a combining mark after anything else is flagged. U+2705 is flagged in every file form: the prose standard requires ASCII throughout, and the tree's allowance of it in Markdown is for the plan ledgers, which `/writing` does not check. The forms file holds a decomposed name (passes), a lone combining mark after a space (flagged) and U+2705 in a `.md` file (flagged), each written with `printf` octal escapes.

The head docstring of `check_prose.py` states each of these rules, and the rule-13 table of the report has a row for each.
