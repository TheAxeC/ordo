   - Frontmatter: `name: writing`; a `description` of one paragraph saying the skill checks a text file against the prose standard and the writing reference pages and lists each problem with its line, changing nothing, then `Triggers on:` with the phrases (such as writing, check the prose, check this draft, prose check, style check); `metadata.version: "1.0.0"`.

   - Quick start: `/writing <file>` and `/writing <file> --limit '<section heading>=<words>'`, one per line with a short comment.
   - Use instead: the neighbouring situations, each with the skill to use. A text that should be rewritten is a later writing skill's job; the table names that the rewriting skills are not built yet only if the layout allows a row for it, and otherwise leaves the row out. A plan step's review is `/refute`.
   - What it reads: the file (missing, a directory, unreadable or not UTF-8 is a refusal, the script's exit 64); the four reference pages, each with what it is read for; the `--limit` values.
   - Steps, in order:
     1. Run `python3 <this skill's folder>/templates/check_prose.py [--limit ...] <file>` and read its output and exit status. Exit 64 is a refusal that prints the script's error.
     2. For each flag the script prints, judge it against the rule it names: a `flagged`, `filler` or `vague` word is kept where prose standard section A's exemption holds (standard terminology in the text's discipline; a quoted example; a required heading such as "Quick start"), and an `equal-length` report is judged by the section's variation in `references/anti-patterns.md`.
     3. Read the text against the rules the script does not check: `references/anti-patterns.md`'s patterns judged by hand for every file; `references/academic-prose.md` and `references/judgment.md` for an academic text (a `.tex` file, or a file the user names as a manuscript, proposal or paper); the prose standard's sections 0 and A to F for every file.
     4. List each problem, in line order, as `<file>:<line>: <source>: "<text>": <the rule broken and what to change>`, where `<source>` is the script's check name for a script flag kept after step 2, and the reference page's file name without `.md` (`prose-standard`, `academic-prose`, `judgment`, `anti-patterns`) for a problem found by reading. A script flag judged a false alarm in step 2 is listed apart, under a line "Script flags kept as allowed", each with the reason.
     5. Change nothing: the file and every other file stay as they were.
   - A reference section for the output shape of step 4, with one example of each kind of line.
   - Stops: the refusal for an unreadable or non-UTF-8 file and a bad `--limit` (both the script's exit 64); no other stop.
   - Anti-patterns: at least rewriting the file, dropping a script flag without a stated reason, and listing a problem without its line.
   - Rules: one per bullet, including that the skill writes nothing and that every listed problem names its rule.
