## What to build

1. **The case rule, both copies of the change standard.** In "Scripts compute facts; judgment is read", a new bullet right after the bullet on tests, whose "costs something" names the costs that bullet lists: lost work, a broken installation, a wrong configuration accepted.
   - Ordo's page, word for word: `- A script handles a case only when that case has happened or when a wrong answer on it costs something. No brief, case or review finding adds a case on other grounds.`
   - The template copy, word for word: `- Code handles a case only when that case has happened or when a wrong answer on it costs something. No brief, case or review finding adds a case on other grounds.`
2. **Rule 15, both copies.** Rule 15 is rewritten to match item 1. It no longer lists forms of input to weigh, no longer asks for ids or keys exercised empty, duplicated and colliding, and no longer asks for concurrent paths. It keeps the clause that a value a user, a file or a script supplies is untrusted where it reaches a command, a path or generated text, and that each such place is a case. Its bold title says what the rule now holds. The builder words it.
3. **Checks match what the step changes, both copies of the change standard.** Rule 6 says that before landing the builder and the reviewer run the checks the brief names for the files the step changes, and the repository's character-set check over those files where its verify list holds one; the plan's whole verify list runs once, at landing on main. The runner sentence of "Commands and their filters" in Ordo's page, and its counterpart in the template copy, say the same. The builder words them.
4. **The small text step, defined once.** A new entry in `skills/repo-setup/templates/plan-terms.md` and the same in `docs/glossary.md`, written first, as `docs/dev/skill-layout.md` "Writing for an agent" says: **small text step**, a step whose brief changes no script, no test and no configuration file, and fewer than 20 lines in all, counted as the lines added plus the lines removed that `git diff --numstat` gives; it gets no brief check, one review and no repair round. Every other step is a full step, named so in the entry. The skills below use the term as the entry defines it.
