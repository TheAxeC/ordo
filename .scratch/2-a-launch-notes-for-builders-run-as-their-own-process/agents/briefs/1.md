## What to build

1. `skills/plan-orchestration/templates/launch.sh`, POSIX sh:
   - `launch.sh claude --cwd <dir> --model <model> --prompt <file> --report <file> --stderr <file> --exit <file> --pid <file> [--note <command> --id <file> --label <step> --parent <session id>]` starts the `claude -p` recipe detached and returns at once, writing the detached process's pid to `--pid`.
   - `launch.sh codex` takes the same options plus `--events <file>`, `--effort <effort>` and an optional `--network`, and starts the `codex exec` recipe the same way.
   - With `--note` absent or empty the builder is run with exactly the recipe's arguments, redirections and exit-file line, and no note command runs.
   - With `--note` set, the detached process runs `<note> start --launcher plan-orchestration --label <step> --harness <claude|codex> --model <model> --parent <session id> --cwd <dir> --pid <its own pid>` with stdout to the `--id` file before the builder; a failed `start` leaves the id file empty and never stops the builder; after the builder it runs `<note> end <id>` only when the id file holds an id; the builder's exit code goes to the exit file as `exit <code>` in every case.
   - `launch.sh transcript --note <command> --id <file> <path>` runs `<note> transcript <id> <path>` when the id file holds an id and does nothing otherwise.
   - Usage errors exit 64 with a usage line; the head comment says what the script does; no history.
2. `skills/plan-orchestration/templates/launch.test.sh`, in the style of `utils/pin.test.sh`: a scratch directory, stub `claude`, `codex` and note commands on `PATH` that record their arguments and standard input and exit with a code the test sets, and a wait on the exit file. It fails unless:
   - with the note empty, each builder receives exactly the recipe's arguments and prompt, its output lands in the report or event log, the exit file holds its exit code, and no note call happens;
   - with the note set, `start` is called with the arguments above (its `--pid` equal to the pid file's value), then the builder, then `end <id>`, and `transcript` passes `<id> <path>`;
   - after a failed `start` the builder still runs, `end` and `transcript` are not called, and the exit file holds the builder's exit code;
   - a usage error exits 64.
   It prints `PASS: launch.sh scratch tests` on success.
3. `docs/launch-note.md`: Ordo's interface for a launch-note command: what it is for, that it must return at once, the three calls with their arguments and what each must print or do, that a failed or empty `start` means no record, and that the plan skills name no project or path (the command lives in each repository's `.agents/plan.yaml` as `launch_note`).

## What it must do

- The files follow the change standard and the prose standard (`skills/repo-setup/templates/docs/dev/prose-standard.md`): ASCII, no history.
