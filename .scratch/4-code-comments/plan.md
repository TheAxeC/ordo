## Goal

A `code-comments` skill that reviews the comments a git diff adds or changes, by default the uncommitted changes against `HEAD`, otherwise a range `<base>..<head>`. A comment says what the code does and why, is true of the code beneath it, serves a purpose for its reader rather than restating what the code plainly shows, carries no history and no step numbers, is ASCII only, and follows sections 0, A, B, C and E of the prose standard, read where the repository keeps it. A fresh agent that changes nothing reports the findings and a fresh checking agent keeps those that hold, in one report with the false comments first; the user says which findings to apply, a fresh agent rewrites those comments in the working tree and commits nothing, and `templates/strip_comments.py` compares each rewritten C, C++ or CMake file with its version before the rewrite and puts back a file that differs in more than its comments.

### Step 1, Step 0

- Open item A (2026-10-17), closed 2026-10-17 by the user's ruling (a); step 1, one finding of the brief check (`agents/reviews/1-brief-check.md`, "Declined to judge") that the brief cannot settle, since it decides what a new script computes: ruling D7 approved `strip_comments.py` as "computing a file's text with its comments removed" and printing `equal` or `differ`. Removing comments alone leaves the spaces and line breaks around them, so deleting a trailing comment (`x = 1;   // why` becomes `x = 1;`), deleting a whole comment line, moving a comment onto its own line, or reflowing a three-line `///` block into two lines all print `differ`, and the skill would put each such rewrite back. The brief also has the script normalise whitespace outside literals, as Cathedra's `strip_comments.py`, which ADR 0014's Context cites, does.
  - (a) Approve this computation for `strip_comments.py`: each comment becomes one space; in C and C++, a backslash-newline outside a literal is deleted first, as the compiler deletes it, each run of whitespace outside a literal becomes one space, and a preprocessor directive keeps its own line; in CMake, each run of whitespace outside quoted and bracket arguments becomes one space; literals, quoted arguments and bracket arguments are kept byte for byte; `--compare` prints `equal` when the two results are the same and `differ` otherwise. Pro: deleting, moving and reflowing a comment compare `equal`, so the findings that ask for a comment to be removed or shortened can be applied; whitespace outside literals does not change what C, C++ or CMake build, and the line a directive ends on is kept. Con: a rewrite that also re-indents code or moves a line break in code compares `equal` and is kept; a rewrite that joins two tokens (`int x` to `intx`) or splits one still compares `differ`.
  - (b) Approve only what D7's words say: comments removed, every other byte kept, the results compared byte for byte. Pro: any change outside a comment, whitespace included, prints `differ`. Con: every comment deletion, move or reflow prints `differ` and is put back, so most findings that ask to remove or shorten a comment can never be applied, and cases 4, 5 and 14 of the brief expect `differ` instead of `equal`.
  - Recommendation: (a), since the skill exists to apply the findings the user picks, and whitespace in code outside literals and directive lines does not change the build. The lazy option is (b), which costs less to build and leaves the comment deletions the findings ask for impossible to apply.
- Open item B (2026-10-17), closed 2026-10-17 by the user's ruling (a); step 1, raised by its builder (agent a506da4c91c7ab7a8) at the first run of the cases, before any code, since it decides what a new script computes: under ruling A, each comment becomes one space and each run of whitespace becomes one space, so a file that starts with a comment starts with a space once the comment is stripped, and the same file without the comment does not. Cases 5 and 14 of the brief expect `equal`. The builder waits in its worktree, nothing changed.

Pro: deleting or moving a comment on a file's first or last line compares `equal`, as ruling A intends for every comment; a change of code at the start or end of a file still prints `differ`. Con: two files that differ only in blank lines or spaces at their start or end compare `equal`, which changes nothing a C, C++ or CMake build reads.
