## What to build

In `skills/plan-orchestration/templates/launch.sh`:

1. **The pid owns the builder.** The process whose pid the launch writes to the pid file leads a new session that holds the builder and everything it starts. That process lives until the builder has ended, `end` has been called and the exit file is written. Its pid is the one passed to the note's `start --pid`, alive when `start` runs.
2. **A signal ends the whole builder.** TERM, INT or HUP sent to that pid ends every process of the builder's session, then the exit file is written (`exit <128 + signal number>`) and `end` is called. KILL to that pid ends the session leader only; the land skill's sequence (TERM, then KILL two seconds later if the pid is still alive) leaves no builder process running and an exit file present.
3. **Bounded note calls.** Every call to the note command (`start`, `end`, `transcript`) is stopped when it has not returned after 3 seconds; a stopped `start` counts as a failed one (no `end` is called), and the builder, the exit file and the caller of `transcript` never wait on the note longer than that. The bound needs no command macOS lacks (no `timeout`).
4. **One launch per step.** A launch whose pid file names a live process is refused before anything starts, with a message naming the pid, exit 75.
5. **Absolute paths, visible errors.** Every path option is made absolute before any directory change, so a path resolves from the caller's directory for both harnesses; the body's own errors go to the `--stderr` file, not to `/dev/null`.
6. **A known Claude session id.** A first `claude` launch (no `--resume`) generates a session id, passes it to `claude -p --session-id <id>`, and writes it to a file named by a new option, `--session-file <file>`, before the builder starts; a resumed launch writes the id it was given.
7. **The exit file in one move.** The exit file is written to a temporary file beside it and moved into place.
8. **The usage text** names `--label <entry>/<step>` and `--session-file`.
9. **The head comment** says each of the above.

## Decisions taken in this brief (each reversible, none silent)

1. The session leader is made with a tool the platform has (for example `perl -MPOSIX -e 'setsid; exec @ARGV'`, since perl already runs the repository's ASCII check); the builder picks the tool and says why in the head comment.
2. A refused second launch exits 75 (the usual "try again later" status); 64 stays for usage errors.
3. The new option is `--session-file <file>`; it is optional, and omitted means no file is written.
4. The note-call bound is 3 seconds, as ruled (open item C); the oculus note command waits at most 2 seconds on its lock.
