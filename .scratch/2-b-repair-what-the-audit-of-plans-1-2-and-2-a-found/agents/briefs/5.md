## What to build

1. **Check mode flags the live clone.** `check_links` reports, as a problem, every link in a skill folder whose target is under `"$repo"/`, with a message naming the link and its target. Check mode fails on it.
2. **Pin mode removes only what it owns.** The cleanup removes a link only when its target is under `"$stable"/` and the tag lacks its skill, and prints one line per removed link (`pin: removed <link>, which the tag <tag> does not hold`). A link into the live clone whose skill the tag lacks is left in place and reported (`pin: <link> links into the live clone <repo>; move it away or pin a tag that holds it`), and pin mode then fails its final check, so the user sees it. A link into the live clone for a skill the tag holds is replaced, as today.
3. **A home folder holding a space.** The default skill folders are kept one per line and every loop over the folders reads them one per line, so no path is split on a space. `ORDO_SKILL_DIRS` keeps its documented form (space-separated) and may also be given one folder per line; when it holds a newline it is read one per line. The head comment and `README.md` (the paragraph at line 165) say so.
4. **A stale worktree registration.** Before `git worktree add`, the script runs `git -C "$repo" worktree prune`, so a pinned worktree deleted by hand is created again.
5. **The head comment** (lines 2-13) states the four behaviours above, wrapped at about 100 characters (line 10 is over it today).
6. **Tests.** `utils/pin.test.sh` gains a case for each item above, each red under the revert that undoes it, and closes the five untested points of the review: check mode reports a link into the worktree whose skill the tag lacks; a `$stable` that exists and is not a worktree is refused with its message; `$CLAUDE_CONFIG_DIR/skills` is linked when the variable is set; the check after linking fails when a link is wrong; a real directory is refused with the "real directory" message (the test checks the message, not only the exit status). Every case runs under a scratch `HOME` whose path holds a space, and the test never touches the real home folders.
7. **README.md**: the `pin.test.sh` bullet (line 122) says what the test now checks.

## Decisions taken in this brief (each reversible, none silent)

1. `ORDO_SKILL_DIRS` keeps its space-separated form and also accepts one folder per line; a folder whose path holds a space is given the newline form. This keeps every existing use of the variable working.
2. Pin mode leaves a live-clone link for a skill the tag lacks in place and fails, instead of removing it: a link the user made is never deleted without a word.
