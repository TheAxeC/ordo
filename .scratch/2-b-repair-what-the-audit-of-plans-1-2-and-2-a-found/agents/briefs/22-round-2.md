## The four items

1. **The apply, when main deleted or renamed a file the patch changes.** `git apply --3way` then applies nothing, prints `error: <path>: does not exist in index` and exits 1, and `git status --short` is empty (Verification 5). Add an apply mode to `back_out.sh`: `sh back_out.sh --apply <patch>`, run by `/spec` from inside the new worktree in place of the bare `git apply --3way`.
   - It runs `git apply --3way`, reads what it prints, and for each file named in a `does not exist in index` (or any other per-file) error, runs the apply again with that file excluded, until the rest applies or nothing is left.
   - For each excluded file it prints `skipped: <path>` and writes that file's part of the patch to `agents/reviews/<step>-skipped-<n>.patch` beside the patch, or one file holding all of them; say which in the report.
   - It prints `applied: <path>` for each file applied clean and `conflict: <path>` for each file left unmerged, read from `git status --porcelain -z` after the apply.
   - Exit 0 when every file applied clean, 1 when any file conflicted or was skipped, 64 on an argument it cannot use.
   - `/spec` puts these lines into the brief under a heading "The patch as applied", and the builder is told: each `conflict:` file is finished from its conflict markers, and each `skipped:` file is rebuilt from its skipped part against main's tree. The brief is committed at Steps 5, before the worktree exists, so `/spec` adds this section to the brief after the apply and before the dispatch commit of Steps 8, which carries it. `/spec` Steps 3, 6 and 8 say so.
   - Tests in `back_out.test.sh`: main deleted a file the patch changes, and main renamed a file the patch changes. In both, the other files are applied, the file is named on a `skipped:` line and its part of the patch is on disk, and the exit is 1. Each case names its revert and quotes its first `FAIL:` line.
2. **A binary file in conflict.** The builder cannot rebuild a binary from the patch, since `--binary` writes a delta or a compressed literal and the builder runs no git (Spec 2 of the review). In `--apply` mode, for each binary file left unmerged, `back_out.sh` takes the patch's copy (`git checkout --theirs -- <path>`, or what works; prove it) and prints `binary: <path>, the patch's copy taken`. The brief section of item 1 carries these lines, and `/spec` says that the builder checks each such file against main's change to it, which the brief names. A test: a binary changed on both sides ends as the patch's copy, byte for byte, with its `binary:` line. It names its revert.
3. **`back_out.sh` checks the state edit before it removes anything.** Compute the state file without the entry and check it (the other entries kept, the rest of the file byte for byte) before `remove_worktree.sh` runs; a check that fails prints `failed:` and exits 1 with the worktree, both branches and the entry kept, so a rerun after the cause is put right goes through. A comment line and a blank line directly under `dispatch:`, and between entries, are handled: the entry is removed and they are kept. Tests: a comment line under `dispatch:`, a blank line under `dispatch:`, and a state edit that cannot be made (for example the entry missing its `landing:` key after the patch is written, or a read-only state file) leaving the worktree, both branches and the entry in place, then a rerun that succeeds. Each names its revert.
4. **The takeover question.** Remove the bullet "A session taking over lists the uncommitted ledger changes by path and asks the user which are records of the session it takes over. Those become its own records; the rest are left alone." In its place: handing the plan over is a resume point. A session that stops, for a handover or a pause or at a stop, first commits the records it wrote since the last resume point, by path. So a session taking over finds no uncommitted record of the session before it, and a ledger change it did not make is listed and left alone, as the bullets above say. Make the list of resume points in the second bullet name the handover. No other bullet changes.
