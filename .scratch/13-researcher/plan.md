## Goal

The researcher skill, with six modes. `novelty` is a light check made by the session itself, with no agent started: it states the claims of an idea, searches for the closest prior work on each, and writes one page with the nearest works and their references, what each already does, what the idea adds beyond them and a verdict per claim (new, partly done or done), each cited work confirmed with `paper`'s `lookup.py`; the page is given to `paper` as a starting point and replaces none of its literature search. `idea` takes a rough sketch to research questions and claims: it works in rounds, each choice of the idea put with its options and a recommendation, runs `novelty` on each candidate claim between rounds, and writes the questions and claims into the project's `README.md`. `integrity` runs the integrity check, of the references and of the claims against each source's full text, of the numbers against the saved runs and of the figures against their traces, and the ethics check, on a finished draft. `manuscript` runs `paper`, the integrity and ethics checks, the review of `paper-review-panel`, the revision, the re-review and the final check, in the order academic-pipeline gives its stages from the writing on. The integrity check's corrections and its records sent to `paper` keep file names, script names, paths, code identifiers, job, run or exit-code language and software-operations wording out of the manuscript text, a fact from code or a log written as the scientific claim it supports. The `integrity` and `manuscript` modes are a copy of academic-pipeline's files (`research-hub/.agents/skills/academic-pipeline/`), each under its own folder and name, with the documents those files rely on taken from the same version of its public repository, changed only where a ruling of yours in the plan's Rulings says so, each with its reason; the ethics check is built from the page `paper` held for it. A file `NOTICE.md` at the repository root names the skills adapted from that repository, its author and its licence. The `research` mode of `researcher`, which takes an idea to results: the session directs the work through six named stages (Frame, Build, Baseline, Experiments, Compare, Consolidate), each with a completion criterion, and a stage can send the work back to itself or to an earlier one; each piece of code is built by a fresh agent from a written brief and read by a fresh reviewer before any job is submitted. Frame sets the question, the baseline, the metric, the limits on storage and compute, and the dataset, chosen from candidates shown with their size, licence and fit to the limits. Experiments holds one campaign or several, each with its own method. It runs the experiments, SLURM jobs among them, and when a result does not beat the baseline it diagnoses why (the dataset, the method, the implementation or the question) and proposes a new method, a change of the method or another dataset, never writing up a negative result; it stops after each such result or goes on by itself for a number of methods you set. It states where a project's code, results, logs and drafts live, in a default layout whose entry file is the project's `README.md`, with dead ends kept runnable in `code/attic/`, and one project can hold several manuscripts. An adopt mode reads a project already underway and continues from the first stage not done, counting partial or inadequate results as not done. The `full` mode runs `idea`, then `research` and `manuscript`, shows the modes it will run and the ones it leaves out, as for a review paper or for results that exist, each with its reason, and goes on after you confirm. The `research` mode holds a project to four rules: one documented command rebuilds every reported number, table and figure from the raw inputs, and names each missing prerequisite at its start; nothing computes on a cluster's login node, and every job goes through the scheduler; an idea is not shelved after a weak first attempt; and the project's notes let a new session resume without the conversation. At the end of the entry, `ordo-help` covers everything Ordo offers: the academic skills and the code skills beside the plan skills, each with what it is for and the command that starts it, and from a sentence on what you want to do it names the skill, the mode and the command.
