## What to build

When the step is done, `ordo-help` covers everything the repository's skills offer: its `skills` mode says what each skill is for, and a sentence on what the user wants to do gets the skill, the mode and the command to type.

1. The `skills` mode. Under each skill's name line `/<name>` and above its Quick start block, one line that says what the skill is for.
   - The session writes that line in the run, from the frontmatter `description` of the `SKILL.md` it has just read: one sentence of at most 25 words, holding nothing the description does not say.
   - The Quick start block stays copied line for line.
   - The Rules bullet and the Anti-patterns row on the `skills` mode are changed to allow that line and to forbid a line written from memory or from another run.
2. The sentence form, `/ordo-help <what you want to do>`, such as `/ordo-help I want to revise a paper`. The skill's text names it in plain words, "a sentence on what you want to do", and coins no new term for it.
   - "What it reads" 1 reads the argument in this order.
     - Exactly `skills`: the `skills` mode. `skills` followed by more words is a sentence.
     - A folder that holds a `plan.yaml`, alone or followed by nothing but an entry, and a project in front of an entry in the `projects:` form, as `/plan`'s "What it reads" 1 reads them: the forms of today. A folder followed by other words makes the whole argument a sentence.
     - The whole argument is the number, the title, or the number and title of a roadmap entry that has an open plan: that plan's position, as today.
     - Anything else is a sentence on what the user wants to do.
   - With no `plan.yaml` found, or with one whose required key is missing, an argument other than `skills` and a folder is a sentence and is answered; the refusals stay for the forms that read a plan.
   - For a sentence the skill finds the skills folder and reads each skill's `SKILL.md` as the `skills` mode does: its description, its Quick start block and its Use instead table.
   - It prints the skill or skills that fit, at most three, the best fit first, each with: the name, the mode, the command to type as its Quick start block writes it, and one sentence on why it fits, from the description.
   - It prints the sequence, the choices awaiting review and the plans' positions only for the forms that print them today, not for a sentence.
   - When several fit in an order of use (such as a review and then a revision), it says the order.
   - When none fits, it says so in one line and names `/ordo-help skills`.
   - An argument that is the whole number or title of a roadmap entry with no open plan, with or without its folder or project in front, is answered by what the roadmap says of the entry, in place of the refusal "No ledger folder": `/plan <entry>` for an open entry with a gate; `/roadmap add <entry>` for an entry under "Not yet specified"; one line that the entry is done, or dropped, for such an entry. A number that matches no entry gets the line that no skill fits. The row "No ledger folder" of Stops is rewritten to what remains of it, or removed when nothing remains.
   - The sentence form writes nothing, invokes no skill and starts no agent.
3. The frontmatter: the description says the two additions and stays within 1,024 characters as `docs/dev/skill-layout.md` counts them; its `Triggers on:` gains phrases for the sentence form, such as "which skill do I use for"; `metadata.version` becomes `"5.2.0"`.
4. Every section says what holds after items 1 and 2, with no sentence left that they make false.
   - The opening paragraph, Use instead, Stops, Anti-patterns and Rules.
   - The Quick start block: the `skills` line reworded, and one new line for the sentence form, placed after the `skills` line; `/ordo-help` stays the first line.
   - "What it reads": each input the sentence form reads (the skills folder, each `SKILL.md`, and the plan configuration and the roadmap when a `plan.yaml` is found), each with the form that reads it.
   - Steps: a subsection of its own for the sentence form, as `docs/dev/skill-layout.md` gives each mode one, each item ending on its completion criterion.
5. `README.md` line 22, the row of `ordo-help`, says the same two additions in the row's own style.

## Cases

- `/ordo-help skills`: expected, per skill the line `/<name>`, one line on what the skill is for, then the Quick start block copied line for line; a folder with no `SKILL.md` skipped.
- `/ordo-help I want to revise a paper`: expected, `paper` with its mode `revision` and the command as `skills/academic/paper/SKILL.md`'s Quick start writes it, and no sequence printed.
- `/ordo-help someone asked me to review a manuscript for a journal`: expected, `referee` with its command.
- `/ordo-help I want to bake bread`: expected, one line that no skill fits, naming `/ordo-help skills`.
- `/ordo-help 13` with a plan open for entry 13: expected, the plan's position, as today.
- `/ordo-help` followed by the number of an open roadmap entry with a gate and no open plan: expected, `/plan <entry>` named, and no refusal.
- `/ordo-help` followed by the number of a done entry, such as `4.A`: expected, one line that the entry is done.
- `/ordo-help <folder>/<entry>` and `/ordo-help <project>/<entry>` with a plan open: expected, the plan's position, as today.
- `/ordo-help` followed by the title of an entry with an open plan, such as `researcher`: expected, the plan's position; `/ordo-help I want to work on researcher`: expected, read as a sentence.
- `/ordo-help I want to revise a paper` in a folder where no `plan.yaml` is found: expected, the same answer as in a repository with one, and no refusal.
- `/ordo-help I want my paper reviewed and then revised`: expected, `paper-review-panel` and then `paper` with its mode `revision`, the order stated.
- `/ordo-help` with no argument, and `/ordo-help <folder>`: expected, unchanged.

## Decisions taken in this brief (each reversible, none silent)

1. The line on what a skill is for is written by the session in the run from the description it has just read, at most 25 words. The first sentence of a description cannot be copied as that line: five real cases, each the first sentence of the description and its length: `ordo-init`, 65 characters, "Set a repository up for the plan skills, by what the folder holds"; `submit`, 80, "Make a submission through a web portal from a submission sheet the user approves"; `ordo-help`, 428, a sentence that runs through every form; `grill`, 820, a sentence that lists every step. A new frontmatter key would change `docs/dev/skill-layout.md`, and a table kept in `ordo-help` would go stale with every skill added.
2. An argument that names a roadmap entry with no open plan is answered from the roadmap (`/plan <entry>`, `/roadmap add <entry>`, or that the entry is done or dropped), since ruling D33 reads everything that is not `skills`, a folder or an entry with an open plan as what the user wants to do.
3. At most three skills are printed for a sentence, so the answer stays a selection.
4. The new Quick start line stands after the `skills` line.
