## What to build

The goal's sentences, which the step is judged on:

- "`novelty` is a light check made by the session itself, with no agent started: it states the claims of an idea, searches for the closest prior work on each, and writes one page with the nearest works and their references, what each already does, what the idea adds beyond them and a verdict per claim (new, partly done or done), each cited work confirmed with `paper`'s `lookup.py`; the page is given to `paper` as a starting point and replaces none of its literature search."
- "`idea` takes a rough sketch to research questions and claims: it works in rounds, each choice of the idea put with its options and a recommendation, runs `novelty` on each candidate claim between rounds, and writes the questions and claims into the project's `README.md`."

2. `novelty`, as the goal and ruling D14 give it.
   - The session does all of it itself and starts no agent.
   - It states the claims of the idea, one sentence each, and shows them before it searches; an idea that holds no claim it can state is a stop that asks for one.
   - For each claim it searches for the closest prior work: two `lookup.py search` queries, one of the claim's own terms and one of the terms a paper that had done it would use, each a short list of key terms since arXiv joins a sentence's words by AND, and one web search. It reads the abstract, or the passage, of each candidate it will cite, in the run. A statement of what a work does rests on text read in the run, never on memory. The page names at most five nearest works per claim.
   - Each cited work is confirmed as `SKILL.md`'s Rules bullet on `lookup.py resolve` says, which states ruling D14 and the field-by-field comparison of `paper`'s "Looking a reference up"; `### novelty` points at that bullet and does not restate it. A work that is not confirmed is not cited as a reference: the page names it under a heading of its own as found and not confirmed, with what was searched, and no verdict rests on it alone.
   - The page: per claim, the nearest works with their references (authors, year, title, venue, DOI or arXiv ID as `resolve` printed them), what each already does, what the idea adds beyond them, and a verdict, one of `new`, `partly done` or `done`, with the reason. Then the searches made, each with its query and where it ran, so that a reader sees what "nothing found" rests on. A verdict of `new` says in the same sentence that it means no closer work was found by these searches.
   - The page is written to `notes/novelty-<YYYY-MM-DD>.md` in the project folder (the folder the session runs in when none is given), `notes/` made when it is missing, with `-2`, `-3` and so on for a further page of the same day.    - It works in rounds of the interview, as `/grill` holds its rounds. The choices of the idea are the problem, the claim, the baseline, the metric, and the result that would show it works. Each round of the interview asks every choice whose prerequisites are settled, each with its options, the pros and cons of each, one recommendation and the lazy option named. Write "round of the interview" wherever the text means one, so it is never read as a repair round.
   - Each answer is written as it settles into the progress file `notes/idea-<YYYY-MM-DD>.md` of the project folder, with the choices still open, so a session that ends early loses nothing. `/researcher idea` started again on a project whose newest progress file has open choices continues from it, as `/grill`'s "An interview started again" does.
   - Between rounds of the interview it runs `novelty`, as `### novelty` gives it, once over all the candidate claims of the round, one page for the round, and shows the verdicts at the start of the next round. A claim found `done` is dropped or sharpened before the next round, and the page that shows it is named.
   - It ends when no choice is open: the research questions and the claims are written into the project's `README.md`, in the section ruling D29 opens the README with, each claim with the result that would show it and the novelty page that covers it, and the progress file records that the interview ended. A `README.md` that does not exist is made with that section; every other section of a README that exists is left as it stands. The user's words are written into the README as text. The words of the section's heading are yours to choose once and use in every place; the report names it, and step 4 writes the rest of the README's layout around it.
