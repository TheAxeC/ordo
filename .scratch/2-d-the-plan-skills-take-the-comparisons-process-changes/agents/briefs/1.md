## What to build

1. `docs/dev/skill-layout.md`, Frontmatter section:
   - A bullet: the description is at most 1,024 characters, counted as the gate's command counts it (the YAML value's length).
   - The description rules of a trigger: its first words name what the skill does, the phrase a reader or a model matches on; `Triggers on:` lists one phrase per case the skill is for, and no phrase that belongs to a neighbouring skill.
2. `docs/dev/skill-layout.md`, a new section "Writing for an agent", placed after "Lists and tables", one rule per bullet:
   - A rule states the behaviour wanted; a rule written as a prohibition names the behaviour to do instead in the same bullet, since a bare prohibition draws attention to what it forbids. The Anti-patterns table stays: each row names its "Do instead".
   - One meaning has one place: this cites "Where a rule goes" and does not restate it.
   - A sentence stays only when it changes what the reader does from what they would do without it; a sentence that restates a default, praises, or explains what the reader already knows is cut.
   - Each step of "Steps" ends on its completion criterion: what is true, or what exists, when the step is done.
   - Material a step needs only in some runs (a long format, a table of cases, a protocol) goes in a file `references/<name>.md` beside `SKILL.md`, named by its path from the step that reads it; a reference section of row 6 holds only material every run reads. `templates/` stays for files copied into a repository.
   - This page's rules apply to a skill's text when it is written or rewritten; applying them to every existing skill is roadmap entry 23, the pruning pass, and is not this step.
3. "Paths and names": a file of this skill's `references/` is named `references/<file>`, as `templates/<file>` is.
4. `skills/spec/SKILL.md`: the `description` value rewritten to at most 1,024 characters under items 1 and 2, keeping every behaviour the current one names (the authority refusal, the premise check, the library search, the brief and its parts, the path comparison, the worktree, the base binaries, the dispatch record, the step taken back out of main) and every trigger phrase. The rest of the file is not changed. `metadata.version` goes to "1.6.1".
