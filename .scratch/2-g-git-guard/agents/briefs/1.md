## What to build

1. `skills/repo-setup/templates/hooks/git_guard.py`, a Python script run as a Claude Code PreToolUse hook (`python3 <path>/git_guard.py`), standard library only, running on Python 3.9 or newer (`from __future__ import annotations` where annotations need the newer forms; no `match`, no `itertools.pairwise`, no `zip(strict=...)`). A head docstring says what it blocks and why, what it lets through, what it does not see (commands run by another program, such as a script or `python3 -c`; git aliases defined in a configuration file), what it does not block (Decisions 3), how it is run (one line naming the hook event and the command; the settings text is step 2's), and its exit statuses. What it computes:
   - **The input.** Read stdin as bytes and decode it as UTF-8 with undecodable bytes replaced. When it is a JSON object whose `tool_input` is an object holding a string `command`, that command is checked, whatever the `tool_name` (so the Bash tool, the Monitor tool and any other tool that runs a shell command are guarded by the same hook). Anything else (not JSON, not an object, no `command`, a `command` that is not a string, empty input) exits 0, as the approved line's "it exits 0 otherwise" says.
   - **The lexer.** A small lexer, written in the script, reads the command as the POSIX shell and bash read it, into a list of simple commands, each a list of words:
     - A backslash followed by a newline is removed (a line continuation). An unquoted newline, `;`, `&`, `&&`, `||`, `|`, `|&`, `(` and `)` end a simple command; a run of operator characters is split into these operators, longest first, so `;(` is `;` then `(`.
     - A redirection (`<`, `>`, `>>`, `>|`, `<>`, `>&`, `<&`, `&>`, `&>>`, with an optional file-descriptor number before it) is not a separator: it and its target word are dropped from the command's words. A here-document (`<<WORD`, `<<-WORD`, quoted or not) takes the lines after the current line up to the line `WORD` as its body; a here-string `<<< word` takes the word as its body. A body fed to a shell (the command's first word is `sh`, `bash`, `zsh`, `dash` or `ksh`, with no `-c` and no script file) is checked as a command; any other body is not. The same holds for a pipe into such a shell: when the command before the `|` is `echo` or `printf`, its arguments joined with spaces (for `printf`, the format with `\n` read as a newline) are checked as a command; the output of any other command piped into a shell is not seen.
     - Inside single quotes everything is literal. Inside double quotes `\` escapes `"`, `\`, `$` and a backtick, and a `$(...)` or a backtick substitution is found. Unquoted, `$(...)`, a backtick substitution, `<(...)` and `>(...)` are found. Each substitution's text is lexed as a command list of its own, recursively, and its simple commands are checked; the word it stands in keeps a placeholder. `$((...))` is arithmetic and is not a command.
     - Quotes are removed from words, and a backslash outside quotes escapes the next character (`\git` is `git`).
     - At the start of a simple command, the reserved words `if`, `then`, `elif`, `else`, `do`, `while`, `until`, `!`, `{` and `time` (with `-p`) are skipped; `fi`, `done`, `}` and `esac` end one; in `for NAME in WORDS` and `case WORD in`, the list words are not a command, and a `case` pattern `pattern)` is dropped before its command.
     - An unbalanced quote or substitution ends the lexing with what was read so far checked as it stands; the shell would refuse such a command and run nothing of it.
   - **The command word.** In each simple command, skip leading environment assignments (`NAME=value`) and these wrappers with their options, those that take a value consuming it: `env` (`-i`, `-u NAME`, `-C DIR`, `-S STRING` whose string is lexed as a command, assignments), `command` (`-p`), `builtin`, `exec` (`-a NAME`, `-c`, `-l`), `nohup`, `nice` (`-n N`, `-N`), `time` (`-p`), `timeout` (its options, `-s SIG`, `-k DUR`, then the duration), `sudo` (its options, `-u USER`, `-g GROUP`, `-C N`, `-D DIR`, `-h HOST`, `-p PROMPT`, `-r ROLE`, `-t TYPE`, `-T TIMEOUT`, `-U USER`), `xargs` (its options, `-I REPL`, `-L N`, `-n N`, `-P N`, `-s N`, `-d DELIM`, `-E EOF`, `-a FILE`, and `-I{}` written together), `eval` (its arguments joined with spaces and lexed as a command), and a shell with `-c` (`sh`, `bash`, `zsh`, `dash`, `ksh`, the `c` anywhere in a combined short-option word such as `-lc` or `-ec`), whose command string is lexed as a command. The command is git when the remaining first word's last path part is `git`.
   - **Git's global options and inline configuration.** After `git`, skip its global options: `-C <dir>`, `-c <key=value>`, `--git-dir <dir>`, `--work-tree <dir>`, `--namespace <name>`, `--config-env <name=envvar>`, `--exec-path`, `--super-prefix <path>`, each also as `--opt=value` where git allows it, and any other word starting with `-` before the subcommand. Keep the configuration they and the environment give: each `-c key=value`, and each `GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` pair among the command's assignments. A subcommand that an inline `alias.<name>` names is expanded: an alias starting with `!` is lexed as a command; any other has its words put in place of the subcommand, and the result checked as git (Decisions 2).
   - **The blocks** (exit 2, one line on stderr: `git-guard: blocked: <the simple command, its words joined by spaces> (<the rule>)`, where the rule names the operation and says the user runs it by hand):
     - `push`, with any arguments, `--dry-run` included;
     - `reset` with `--hard`, or with a long option that is a prefix of `--hard` at least `--ha` long (git takes a unique prefix of a long option, `git help cli`);
     - `clean` with `--force` or a prefix of it at least `--fo` long, or with a short-option word holding `f` (`-f`, `-fd`, `-xdf`, `-dfx`, `-fn`), or with the inline configuration `clean.requireForce=false` and no `-n`/`--dry-run`;
     - `checkout` with a whole-tree pathspec among its arguments, before or after `--`; `restore` with a whole-tree pathspec, unless it restores only the index (`--staged`/`-S` without `--worktree`/`-W`), which discards no work. A whole-tree pathspec is: `.`, `./`, `./.`, `*`, `**`, `..`, `../`; with top magic, `:/`, `:/.`, `:/*`, `:(top)`, `:(top).`; any pathspec with `glob` magic whose pattern is `*` or `**`; a set of pathspecs every one of which is an exclude (`:!x`, `:^x`, `:(exclude)x`), since git then excludes from the whole tree (`git help glossary`, "exclude"). The checks are on the pathspec as written.
   - **Everything else exits 0**, the plan skills' commands above included: `git branch -D x`, `git worktree remove --force x`, `git restore -- a b`, `git restore --staged --worktree -- a`, `git restore --staged .`, `git checkout --theirs -- a`, `git checkout main`, `git checkout -b x main`, `git checkout ./a`, `git -c core.excludesFile=f checkout -b x main`, `git reset --soft HEAD~1`, `git clean -n`, `git log | head`, `git diff -- .`, `echo "git push"`, `echo 'git push' | cat`, `git commit -m "do not git push"`.
   - The first blocked simple command decides; the line names it.
