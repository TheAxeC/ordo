# Step 2a, the cases ruling (round 0)

The builder's first run found two cases whose result the brief's own rules get wrong. The orchestrator rules on each below; the brief holds otherwise unchanged. The builder's final report carries these rulings in its "cases' first run" part.

1. **A21, `cd <repo>; cd - && git p` with `out` as `cwd`, allowed.** The rule changes, the case stands (the builder's option b). Section 1's directory rule reads, in place of its `cd -` clause: a literal `cd` records the directory it left, and a later `cd -` in the same scope returns to that directory, as the shell does. A `cd -` with no recorded directory, and a `cd` whose word is not a literal (a variable, a substitution), leave the directory unknown for the simple commands after it, and their lookups run from the directory before that `cd`. The docstring's "Not seen" names those two forms. Option a, the case changed to blocked, was the lazy option: it keeps a result the shell does not give.
2. **A33, the byte `\377` in an alias value.** The case changes, the rule stands (the builder's option a). The value is `alias.b = "push \377"`, written with `printf`, the byte a separate word after `push`: blocked, no traceback. The orchestrator ran real git 2.49.0 on both values in a scratch repository: `push\377` printed `expansion of alias 'b' failed; 'push<U+FFFD>' is not a git command` and ran nothing, and `push \377` ran `git push` (`fatal: The current branch master has no upstream branch.`). So `push\377` is no push and the guard allows it as git refuses it; the test also holds that value as allowed, with no traceback. Option c, the item dropped, was the lazy option.
3. **P2, not a stop.** After the change, `grep -rnI 'checkout -f' skills README.md docs` prints the docstring's lines, the test's head comment and B5's cases in `git_guard.test.sh`. "No skill" in P2 means no skill's text (`SKILL.md`, a reference or a template other than the guard and its test) runs `git checkout -f`; the report quotes every hit and says which file each is in.
4. **A13, `git Status`, not a stop.** The case stands as blocked; the docstring states that git on a case-insensitive file system refuses `git Status` itself, and on a case-sensitive one runs the alias, so the guard blocks it on both.
5. **The controls the builder added** (a near-miss that must be blocked beside an allow case) are kept, each named as a control in the report.
