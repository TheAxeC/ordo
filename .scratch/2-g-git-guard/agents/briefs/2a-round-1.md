2. **Spec 2 (a `cd` the shell does not run, or runs elsewhere).** The lookup's directory is the shell's directory where the text settles it, and a set of directories where it does not.
   - A `cd` whose target is not an existing directory changes nothing (the shell's `cd` fails and the shell stays).
   - A `cd` that is a member of a pipeline, or a command run in the background with `&`, changes nothing outside itself (the shell runs it in a subshell).
   - `builtin cd`, `command cd` and `eval cd ...` change the directory as `cd` does, and `eval`'s text is read in the scope of the `eval` for this purpose.
   - `pushd <dir>` changes it as `cd <dir>` does and pushes the directory left; `popd` returns to the last pushed directory; a bare `pushd` swaps the two top entries; a `pushd` or `popd` the text cannot settle leaves the directory unknown as a non-literal `cd` does. "Not seen" no longer names them.
   - A relative `cd` word that does not start with `.` or `..` is resolved through `CDPATH` when the guard's environment sets it (a `CDPATH` set by an earlier command of the text is named under "Not seen"), the first existing directory winning, then against the directory so far, as bash does.
   - A `cd` that may or may not run (the right side of `&&` or `||`, a `cd` inside an `if`, `while`, `until`, `for`, `case` or `{ }` body, or inside a function definition) makes the directory a set for the commands after its and-or list: the directories before it and the one it names. Within its own and-or list, a command joined after the `cd` only by `&&` sees the `cd` as done, and one joined after it by `||` sees it as not done.
   - A lookup with a set of directories runs in each directory of the set, each within the shared budget and the per-location cache; the command is blocked when the expansion found in any of them is blocked. The set holds at most 8 directories; a `cd` that would make it larger leaves the directory unknown, as a non-literal `cd` does, and "Not seen" names that.
