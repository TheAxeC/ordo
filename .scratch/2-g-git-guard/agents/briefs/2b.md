## Decisions taken in this brief (each reversible, none silent)

1. `git switch --discard-changes` of the ruling is the option under each name git gives it: `--discard-changes` or a prefix from `--di`, `-f`, and `--force` written whole. The probes show each discards the same work. The open item "Step 2b, the forced checkout and switch" asks Axel whether `git checkout -f` is blocked too; until he rules it stays allowed (B8).
2. `git send-pack` is blocked with any arguments, `--dry-run` included, as `git push` is.
3. `git subtree push` is recognised by the first word after `subtree` that is neither an option nor the value of one of the five options that take a value, so a folder or a remote named `push` does not block an `add`, a `pull`, a `merge` or a `split` (B3).
4. `git stash drop` and `git stash clear` are the first word after `stash`, written whole, since git takes the subcommand only there and takes no prefix of it (B5). `git stash pop` is not blocked: it applies the stash before it drops it, and the ruling does not name it.
5. The message of the switch rule names the option by its long name for each spelling, as the reset rule names `--hard` for `--ha`.
6. `git switch -C` and `--force-create` are not blocked: they move a branch and discard no work in the tree, and the ruling does not name them.
7. `README.md` names two of the blocked commands with "such as", and `repo-setup`'s question 10 lists all of them, since the question is where the user decides and the README row is a summary.

## What it must do

1. `send-pack`: its rule returns the text `git send-pack is run by the user by hand` for any arguments.
2. `subtree`: its rule reads the words after `subtree` in order. A word starting with a dash is an option: `-P`, `-b` and `-m` take the rest of their word as the value, or the next word when nothing is left, also at the end of a word of several short options (`-qP sub`); `--prefix`, `--branch`, `--message`, `--annotate` and `--onto`, each also as a prefix of three characters or more (`--pre`), take the text after `=` or, with no `=`, the next word. The first word that is neither an option nor such a value is the subtree command. When it is `push`, the rule returns `git subtree push is run by the user by hand`; otherwise None. After a word `--`, the next word is the subtree command.
3. `stash`: when the first word after `stash` is `drop` or `clear`, the rule returns `git stash drop discards stashed work and is run by the user by hand` or the same with `clear`; otherwise None.
4. `switch`: the rule returns `git switch --discard-changes discards work and is run by the user by hand` when one of the words before `--` that start with a dash is `--discard-changes` or a prefix of it from `--di`, is `--force` written whole, or is a word of short options that holds `f` before any `c` or `C` (the rest of the word after `c` or `C` is the new branch's name); otherwise None.
5. The rule texts are constants beside the four that exist. Each rule function has the signature of the five that exist, `(arguments: list[str], config: dict[str, str]) -> str | None`.
6. The head comment: the list under "Blocked, because the user runs these by hand" gains a bullet for each of the four subcommands, which says what is blocked in the words of items 1 to 4 (send-pack with any arguments; subtree push, found after subtree's own options; stash drop and stash clear; switch with --discard-changes or a prefix from --di, with --force, or with -f in a short-option word). The paragraph at lines 54 to 55 becomes "Not blocked: git checkout -f, with or without a branch, which discards work; git switch -C and --force-create, which move a branch; and git stash pop." Every sentence of the head comment is reread against the code, as the change standard's rule 14 asks, among them the sentence on what is allowed (lines 39 to 44).
7. The test's head comment: line 4 gains the new blocked cases and line 5 the new allowed ones, each named as the existing ones are.
