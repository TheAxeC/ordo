## Decisions taken in this brief (each reversible, none silent)

1. `git switch --discard-changes` of the ruling is the option under each name git gives it: `--discard-changes` or a prefix from `--di`, `-f`, and `--force` written whole. The probes show each discards the same work. The ruling "Step 2b, the forced checkout and switch" gives the same three names and the message.
2. `git send-pack` is blocked with any arguments, `--dry-run` included, as `git push` is.
3. `git subtree push` is recognised by the first word after `subtree` that is neither an option nor the value of one of the five options that take a value, so a folder or a remote named `push` does not block an `add`, a `pull`, a `merge` or a `split` (B3).
4. `git stash drop` and `git stash clear` are the first word after `stash`, written whole, since git takes the subcommand only there and takes no prefix of it (B5). `git stash pop` is not blocked: it applies the stash before it drops it, and the ruling does not name it.
5. The message of the switch rule names the option by its long name for each spelling, as the reset rule names `--hard` for `--ha`.
6. `git switch -C` and `--force-create` are not blocked: they move a branch and discard no work in the tree, and the ruling does not name them.
7. The forced checkout is blocked as the ruling words it: `-f` in a word of short options, before any `b` or `B` (what follows `b` or `B` is the new branch's name, as `-bfix`), or `--force` or a prefix of it from `--f`. That blocks `git checkout -f -- <path>`, which discards one file, while `git checkout -- <path>` stays allowed as it is today; and the switch rule blocks `git switch -f -c new`, which carries the force option and discards nothing. Narrowing either is the user's call.
8. The `subtree` rule is found for the subcommand in any mix of case, since git runs `git-subtree` by file name and a file system that ignores case finds it. The other rules are matched as written: git refuses a built-in command in another case.
9. A long option of `git subtree` is read at any length from one letter, as git reads it.
10. The head comment's "Not seen" list gains a git program run by its own path (`.../git-core/git-push`, `.../git-core/git-send-pack`): the guard reads git command lines, and this form was not seen before the step either.

## What it must do

1. `send-pack`: its rule returns the text `git send-pack is run by the user by hand` for any arguments.
2. `subtree`: its rule reads the words after `subtree` in order. A word starting with a dash is an option: `-P`, `-b` and `-m` take the rest of their word as the value, or the next word when nothing is left, also at the end of a word of several short options (`-qP sub`); `--prefix`, `--branch`, `--message`, `--annotate` and `--onto`, each also as any prefix of its name from one letter after the dashes (`--p`, `--pre`), take the text after `=` or, with no `=`, the next word. The first word that is neither an option nor such a value is the subtree command. When it is `push`, the rule returns `git subtree push is run by the user by hand`; otherwise None. After a word `--`, the next word is the subtree command. Words that end before a subtree command is found (`git subtree`, `git subtree -P`, `git subtree --`) give None. `_check_git` finds this rule for the subcommand in any mix of case (`SUBTREE`, `Subtree`); the other rules are matched as written. When the rule gives None and the inline configuration holds an alias named `subtree`, the alias is expanded as for a subcommand without a rule, since git runs that alias where it finds no program `git-subtree`.
3. `stash`: when the first word after `stash` is `drop` or `clear`, the rule returns `git stash drop discards stashed work and is run by the user by hand` or the same with `clear`; otherwise None.
4. `switch`: the rule returns `git switch --discard-changes discards work and is run by the user by hand` when one of the words before `--` that start with a dash is `--discard-changes` or a prefix of it from `--di`, is `--force` written whole, or is a word of short options that holds `f` before any `c` or `C` (the rest of the word after `c` or `C` is the new branch's name); otherwise None.
5. `checkout`: `_rule_checkout` also returns `git checkout --force discards work and is run by the user by hand` when one of the words before `--` that start with a dash is `--force` or a prefix of it from `--f`, or is a word of short options that holds `f` before any `b` or `B` (the rest of the word after `b` or `B` is the new branch's name). When the whole-tree rule applies too (`git checkout -f .`), the whole-tree rule's text is returned, so every existing case keeps its line.
6. The rule texts are constants beside the four that exist. Each rule function has the signature of the five that exist, `(arguments: list[str], config: dict[str, str]) -> str | None`.
7.
