## The format the check reads

```
# <title>

<paragraphs>

## New skills

| Skill | Roadmap entry |
|---|---|
| writing | 3 |

## <skill folder name>

| File | Mark | Reason |
|---|---|---|
| `SKILL.md` | rebuild: paper | <reason> |
```

- New skills: each row's entry is an entry number of the roadmap: a heading `## <n>. ` in `docs/roadmap.md` of the repository that holds the coverage file, or a Done line `- [x] <n>. `. A skill named twice, an entry the roadmap does not hold, an empty cell, is an error.
- A skill section is a `## ` heading whose name is a folder named on the command line. Every file `find <root>/<skill> -type f` lists appears exactly once in that section's table, as a relative path in backticks; a listed path that is not such a file is an error. Sections of folders not named on the command line are not read; a named folder with no section is an error.
- Mark: `rebuild: <skill>`, `rebuild later: <skill>` or `drop`, the skill a row of New skills. Reason: not empty. A pipe inside a cell is written `\|`.
- Output: one line per error as `<coverage.md>:<line>: <what is wrong>` (line 0 for an error with no line, such as a file the section does not list, which names the file), and `ok: <coverage.md>` when there is none; exit 1 on any error, 2 on a usage error (a missing argument, a root or folder that does not exist, a file that is not UTF-8).

## What it must do

- Every error the format above names is caught, and the test proves each with a failing case whose expected message it asserts, beside a passing complete file (change-standard rules 13 and 15: each case red without the rule, a control beside each silent case).
- Edge cases in the test: a hidden file (`.gitkeep`) in a folder, a nested folder, a file listed in the wrong section, a path with `..` or an absolute path, the same file under two skills' sections (each counted in its own), an empty table, a table header that is wrong, a row after the table.
- The check never writes, and never runs a command built from the file's text.
