## The inventory format

An inventory is a Markdown file:

```markdown
# Rule inventory: <skill>

- Old: `skills/<skill>/SKILL.md` at `<commit>`
- New: `skills/<skill>/SKILL.md`

| Old lines | Rule | New place |
|---|---|---|
| 12-14 | <the rule, quoted or stated> | Steps 3 |
| 20 | <the rule> | Launching a builder |
```

- `Old lines` is one line number or a range `a-b` in the old file.
- `New place` is a `## ` section name of the new file, optionally followed by an item number (the n-th numbered item, bullet or table body row of that section, counted outside fenced code), or by ` / ` and a `### ` subsection name, or both (`Steps / Mode A 2`).

## What it must do

1. Read the two header bullets. The old file is `git show <commit>:<path>`, run in the repository that holds the inventory; the new file is `<path>` in the working tree. A missing header, an unknown commit or path, or a missing new file is an error.
2. Coverage: every line of the old file that carries text must fall in some row's range. Lines that carry no text are: blank lines, the `---` frontmatter delimiters, heading lines, fence lines, and table separator rows (`|---|`). An uncovered line is an error naming its number and its text, shortened.
3. Each row: `Old lines` parses and lies inside the old file; `Rule` is not empty; `New place` names a `## ` section present in the new file, a `### ` subsection present inside it when given, and an item number no larger than the number of items there. Each failure is an error naming the row's line.
4. The check reads Markdown the way `utils/check_skill_layout.py` does: fenced code of any form is not read for headings or items.

## Decisions taken in this brief (each reversible, none silent)

1. The inventory lives in the ledger (`.scratch/1-one-layout-for-every-skill/inventories/<skill>.md`), not in the tree the skills ship in: it is a record of the restyle, and the skills CLI copies whole skill folders.
2. The check imports nothing from `check_skill_layout.py`; the fence reading is repeated, with a comment naming the file it matches.
3. A heading line in the old file needs no row: a heading is structure, and the rules under it carry the meaning.
