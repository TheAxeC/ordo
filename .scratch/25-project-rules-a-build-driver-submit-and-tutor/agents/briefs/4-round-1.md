# Step 4, repair round 1

The rules file `docs/dev/change-standard.md` and the brief `agents/briefs/4.md` govern this round as they governed the step. The round is the one repair round of the step. Each finding below is from the reviewer's report; each ruling says what to change. Nothing else is changed.

## Findings and rulings

1. Spec 1, the portal's pages read through WebFetch. Ruling: the sheet agent saves each page it reads with `curl` into a folder `portal/` of the run folder, one file per page, and reads the saved file; it reads no portal page through WebFetch. This replaces decision 1 of the brief. The sheet's first lines name each saved file beside its address, and a source or a quoted passage of the sheet names the saved file. `agents/sheet_agent.md`, "Reading the portal", `SKILL.md` (Steps 4, the Anti-patterns row on reading before the approval, the Rules bullet on the run folder, which now also holds `portal/`), the stop "A run folder that exists" (replacing removes `portal/` too) and the glossary entry follow. The form is the one `skills/academic/paper/SKILL.md` gives its citation compliance agent: saved with `curl`, read from the file. The `curl` call sends nothing but the request for the page: no cookie, no credential, no form data.
2. Spec 2, the sheet agent's page without the section "The rules hold". Ruling: the page opens with that section in the words of the agent pages of `skills/academic/referee/agents/`, and the template `submission-sheet.md` gains a section "Objections" at its end, which reads "None." when the agent has none. The session shows the objections with the sheet at the approval.
3. Standards 1, the glossary term "walk". Ruling: the entry is named **walk, of a submission**, in the form of the section's scoped entries, and the text of `submit` that names the term stays readable with that entry.
4. Standards 2, the rule for a row added during the walk. Ruling: the rule stands in `SKILL.md`, "The walk of one page" 2, and nowhere else as a rule: the added row names its page, and its last cell reads `Q<n>, added in the walk`, with the question under "Questions". The template says the same of that cell in its description of the columns, so one cell holds one form.
5. Standards 3, Steps 9 with three actions. Ruling: three items: the walk of the page that holds the final submit, items 1 to 7 of "The walk of one page"; the closing message written to `walk.md`; the closing message shown with the sentence that the user presses the final submit, which is the stop. Each ends on its completion criterion, and every place that names "Steps 9" follows the new numbers.
6. Standards 4, the fragment in the description. Ruling: it is joined to a sentence, and the description stays at or under 1024 characters.
7. Behaviour 1, a page that does not pass. Ruling: a new stop, "A page that does not pass": after the portal's control for the next page, the tab still shows the same page with a message of the portal, such as a required field left empty, a value the portal refuses or an upload it refuses. The session shows the message and the row of the sheet it concerns, and waits; the user answers with a change to the sheet or does it in the tab and says so; the session then fills what the changed sheet holds and uses the control once more. The session never types a value the sheet does not hold to make a page pass, and never uses the control again without a change to the sheet or the user's word. "The walk of one page" 8, the Stops table and the Anti-patterns gain it.
8. Behaviour 2, the way from the URL to the first page of forms, and controls that are neither a field nor the next page. Ruling: Steps 7 says that the session may use the portal's controls that lead to the form, such as the one that starts a new submission, and during the walk the controls that add an entry the sheet holds, such as one more author for an author's row. A consent the portal asks for, a cookie banner included, is an agreement: it is left to the user as the controls of the Rules are, and the Rules bullet on agreements names it. A control that is none of these and that the sheet does not cover is not used: it is shown to the user as a question, as a field the sheet lacks is.
9. Behaviour 3, "the same site". Ruling: the agent reads the page at the URL and the pages it links on the host of the URL, and no other host. Each link to another host that looks like an instruction page is listed in the sheet's first lines as a page not read, with its address, for the user to read. The example of two hosts of one domain is taken out, and the case "An instruction page that links to another site" stays met.
10. Behaviour 4, the material. Ruling: the material leaves out, beside `submit-runs/`, every file and folder whose name starts with a dot, and, when the folder stands in a git repository, every file git ignores there, found with `git check-ignore`. The message that names the material says how many files it holds.
11. The seventh stop, "Which config", is kept, as the report's judgment call gives it.
