## What to build

1. `skills/explain/tutor/SKILL.md`, version 1.0.0, with `disable-model-invocation: true`, in the sections and frontmatter of `docs/dev/skill-layout.md`. Its content is the source's `SKILL.md`: every instruction, every workspace file (`MISSION.md`, `RESOURCES.md`, `lessons/`, `reference/`, `learning-records/`, `assets/`, `NOTES.md`), the lesson's form, the philosophy and the two stops (the mission interview, and the confirmation before the mission is changed) are carried over, each placed in the layout's section that holds its kind, worded to the prose standard, in ASCII. Where the layout has no section for a part of the source, the part goes to a page under `references/` that the skill names. The calls are `/tutor [<topic>]`, the source's skill under the new name, with no topic the next lesson chosen from the learning records as the source says; `/tutor explain <concept>`; and `/tutor explain <concept> --page`. The explain mode has its own subsection under Steps. The frontmatter key `argument-hint` is dropped, since the layout's frontmatter has none. The Stops table holds four rows: the source's mission interview, the source's confirmation before the mission is changed, the offer of a learning record in the explain mode, and the question for the page's path; each stop stands before the step that writes. The step of the skill that writes a glossary among the reference documents names `references/glossary-format.md`, and no `GLOSSARY.md` is added to the workspace.
2. The four format pages, `skills/explain/tutor/references/glossary-format.md`, `learning-record-format.md`, `mission-format.md` and `resources-format.md` (or the folder the layout gives a format page), each the source's page word for word apart from ASCII, the one-line-per-paragraph source form and the paths of the links between pages. The prose standard is applied to `SKILL.md` and not to these four pages, which are the source's formats.
3. The mode `/tutor explain <concept>`, as ADR 0048 words it: one concept explained in the conversation, tied to the work at hand (what the session is doing and where the concept came up, such as a method `/grill` offered as an option); from sources fetched in the run and named in the answer, as the source requires of a lesson; no file written. In a teaching workspace (a folder that holds the source's `MISSION.md`), it offers a learning record, in the source's learning-record format, for what the user showed they understand, and writes it only on the user's yes.
4. `--page`: the explanation is also written as one HTML page in the lesson's form, to `reference/` in a teaching workspace, and elsewhere to a path the user gives or is asked for. The page's file name is made from the concept's words, in lower case with hyphens, and holds no `/` and no `..`. A file that already stands at the path is not replaced without the user's yes. `/tutor explain` with no concept asks for it, and `--page` without `explain` is refused with the three calls named.
5. `skills/ordo/wait-what/` is moved to `skills/explain/wait-what/` with `mv`, its `SKILL.md` unchanged apart from any sentence in it that names its own folder or group.
6. `README.md`: the row of `tutor`; the group sentence, which then names five group folders with `skills/explain/` holding `tutor` and `wait-what`, and `skills/ordo/` without `wait-what`; `explain/wait-what` and `explain/tutor` in the install loop; the count of skills raised by one on both lines that give it.
7. The deviations, as the section "Deviations" of the report, which the orchestrator writes as `.scratch/25-project-rules-a-build-driver-submit-and-tutor/deviations.md` at landing: every difference between `tutor` and the source, one row each: what the source has, what `tutor` has, the reason, and the ADR 0048 point or the ruling that approved it. The differences the layout, ASCII and the prose standard force are listed by kind with each section of the source and where it went. A difference that no point of ADR 0048 and no ruling covers is not built: it is handed back in the report.
8. Every other place the change makes false is changed in the same step, found by grepping `wait-what`, `skills/ordo`, `four group`, `twenty-one` and the list of group folders across `skills/`, `utils/`, `docs/`, `agents/` and `README.md`: a page that lists the groups or counts the skills. A hit under `docs/adr/` or `docs/roadmap.md` is left as it is. The note of `pipeline()` in `docs/figures/gen_figures.py` that lists the skills starting no agent names `/tutor` among those that have a stop; `python3 docs/figures/gen_figures.py` writes `docs/figures/pipeline.svg` again and no other figure changes; the alt text of that figure in `README.md` follows.
9. `docs/glossary.md`, "Ordo's own terms": the terms the skill brings (teaching workspace, lesson, learning record, mission), each in the source's sense and naming `tutor`, in the form of the section's other entries.

## Cases

Each case is checked by reading, unless it names a command.

- Each heading of the source's `SKILL.md`, its frontmatter keys and each of its format pages: expected: the section "Deviations" names where its content stands in `tutor`, and a read of both finds that content there.
- `/tutor <topic>` in an empty folder: expected: the mission interview, the source's first stop, before any lesson.
- `/tutor <topic>` in a workspace whose mission the request would change: expected: the confirmation, the source's second stop.
- `/tutor explain <concept>` in a code repository with no `MISSION.md`: expected: an answer in the conversation that names its fetched sources and ties the concept to the work at hand, and no file written.
- `/tutor explain <concept>` in a teaching workspace: expected: the same, then the offer of a learning record, written only on a yes.
- `/tutor explain <concept> --page` in a teaching workspace: expected: one HTML page under `reference/` in the lesson's form.
- `/tutor explain <concept> --page` elsewhere with no path given: expected: the user is asked for the path.
- The model deciding by itself that a lesson is due: expected: not possible, since the frontmatter holds `disable-model-invocation: true`.
- `grep -rn 'skills/ordo/wait-what' README.md docs skills utils agents`, from the repository root: expected: no line outside `docs/roadmap.md` and `docs/adr/`.
- `/tutor` with no topic in a workspace that holds learning records: expected: the next lesson is chosen from them, as the source says.
- `/tutor explain` with no concept: expected: the session asks for the concept.
- `/tutor --page` without `explain`: expected: a refusal that names the three calls.
- `/tutor explain "a/b ../c" --page` in a teaching workspace: expected: one file directly under `reference/`, its name holding no `/` and no `..`.
- `/tutor explain <concept> --page` elsewhere, with a path at which a file stands: expected: the user is asked before it is replaced.
- `for s in $(grep -o 'for skill in [^;]*' README.md | head -1 | cut -d' ' -f4-); do test -f skills/$s/SKILL.md || echo "missing $s"; done`: expected: no line.
- `diff <(git show HEAD:skills/ordo/wait-what/SKILL.md) skills/explain/wait-what/SKILL.md`: expected: no line, or only the lines item 5 allows, each quoted in the report.

The builder's first task, before any change, is the first run of every case above on the unchanged tree, with each case's result noted: the skill does not exist there, so each reading case is "no skill", and the commands are run and quoted.

When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing anything, and hands back that case, with the rule and the result it gives.
