The builder's first task, before any change, is the first run of every case above on the unchanged tree, with each case's result noted.

- A case of a code step (a script, or a product's code) becomes a test of the step only when the rules file's test rule calls for a test of it.
- A case kept as a test is run on the unchanged tree first.
- No prototype script stands in for such a test.
- Every other case of a code step is checked by a run the report quotes, and no test is kept for it.
- A case of a text or judgment step is checked by reading the unchanged tree.
- The first read of a text or judgment case is noted.

When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives. The orchestrator rules on the case and resumes the builder with the ruling, and the final report carries it.

## Decisions taken in this brief (each reversible, none silent)

1. Item 2's command writes the approved filter "only files that exist on disk" as `if [ -e "$f" ]; then printf "%s\0" "$f"; fi` in place of the proposal's `[ -e "$f" ] && printf "%s\0" "$f"`. The proposal's form makes `sh -c` exit 1 when the last listed file is missing, and the pipeline then fails under `pipefail`. Run in a scratch repository holding `a.md` and `z.md` with `z.md` deleted after the commit: the proposal's form printed `a.md` and exited 1; the `if` form printed `a.md` and exited 0. The list computed is the same.
2. The placement of each shared-rules bullet: "No breakage testing." after "A failing check is a finding.", "A proposal says what exists now." after "Reports state the end state.", "A decision is written down when it is given." after "Every question is answered in full". In the two change standards, "No breakage testing." is the next numbered rule of "The rules".
3. The round's delta (item 12) is read from a saved `git diff <base>` of the worktree, `agents/reviews/<step>-round-<n>-sent.diff`, since the builder commits nothing in the worktree and no commit marks where a round began.
4. Item 5 reads the worktree's page, since the step's work is uncommitted at `land` Steps 2 and the range holds none of it until `land.sh`'s Steps 3; this is ruling D13's "the page as the cherry-pick brings it".
