## Judgment calls the brief left open

- The flag on `Client` is the keyword argument `cache` of `Client(environment, cache=False)`; `main` passes `cache=argv[0] in CACHED_COMMANDS`. `get_parsed` uses the cache only for a `Client` (`isinstance(client, Client)`), so `StubClient` and `RecordingClient` stay as they are.
- `arxiv_turn(call)` stays a module-level function and now calls `host_turn(lock_name, gap, call)`, which `once` also calls for Crossref, OpenAlex and Semantic Scholar. `ARXIV_LOCK_NAME`, `ARXIV_SPACING` and `RETRIES` keep their names; `RETRY_WAIT` is replaced by `RETRY_WAITS = (2.0, 4.0, 8.0)`, and no other file names `RETRY_WAIT` (`grep -rn RETRY_WAIT skills utils docs README.md` prints nothing outside `lookup.py`).
- `Reply` gets the field `reason`, empty by default; `status_reason` returns it when set. A 429 after three retries still carries no reason and prints "HTTP 429 after 3 retries", which the existing `RATE_LIMITED` cases need.
- The skip file is read in `Client.once`, before the turn, so a skipped request takes no turn and no request reaches `send`; this covers the status request of `check-urls` and the URLs of `fetch` on an API host, and a redirect hop to an API host.
- A skip file that cannot be written (an `OSError`) is not written and the request is still left out with its reason. The brief names no behaviour for it; it is the behaviour the lock file has.
- A cache entry is one JSON file with the keys `url`, `stored` and `body`, ASCII. An entry is used when its URL equals the request's and `stored` is less than 30 days before now; the pruning removes an entry by the age of the file (`os.path.getmtime`), which is the time it was stored.
- Temporary files of the cache and of the skip files are made by `tempfile.mkstemp` with the prefix `tmp.`, so no name of an entry (64 hexadecimal digits) can be one. The pruning touches only names of 64 hexadecimal digits and names that start with `tmp.`, so a file the cache did not name stays.
- A home folder that cannot be resolved (`os.path.expanduser("~")` returns a relative path) leaves a cache folder that is not absolute; the cache then stays off so that it never writes into the working directory.
- A `Retry-After` of digits too long for `int` (more than 4300 digits) is read as no value, which gives the 2, 4, 8 schedule.
- P2 checks each gap by the wait a second request causes with the fake clock, which is a proof that the gap is used, not an audit over the table. It sums the waits because a clock of floats near the epoch can add a wait of a few millionths of a second.
- K1, K2, K3 and the others run through `lookup.main` with a scripted `Client.send` and, for the second process, a child process with a scripted `send`, so the cases need no new name on the unchanged tree. Only the K2 case for a host that is not one of the four calls `Client(os.environ, cache=True)` and `get_parsed` directly, since no command reaches such a URL.
