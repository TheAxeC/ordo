## What in the brief was wrong

Case T4 told the builder to set `XDG_CACHE_HOME` to a new empty folder for both runs, and the prompt forbids touching any `ordo-lookup-*` file in `TMPDIR`. Setting `XDG_CACHE_HOME` isolates the reply cache only. `lookup.py` writes its pacing lock files `ordo-lookup-{crossref,openalex,semanticscholar,arxiv}` in `tempfile.gettempdir()`, which is `$TMPDIR`. After the T4 runs, `ls -lT "$TMPDIR"/ordo-lookup-*` listed those four files with modification times between 12:30:22 and 12:30:26, the time of the runs, and listed no skip file. Whether the four files existed before the runs is not verified. A lock file holds only the time of the last request to its host, so the files change the pacing of the next real run by at most one interval. They were not removed, since removing a real file the brief forbids touching would be a second change to it. The fix for later briefs: a `lookup.py` network run sets `TMPDIR` to a scratch folder as well as `XDG_CACHE_HOME`.
