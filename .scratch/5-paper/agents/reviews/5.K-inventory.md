## What paper's lit-review becomes

1. The literature strategist's page is academic-paper's `literature_strategist_agent.md`, with no rule added to it or beside it.
2. The run is academic-paper's lit-review mode: intake with its confirmation; the literature strategist; the stop "User reviews sources (optional add/remove)" (`workflow_phase_details.md:37`); with what academic-paper's own lit-review run did: one strategist per theme cluster of the request's method areas, all at once, each brief giving the theme's scope and the literatures it names, a target range, the search with WebSearch and WebFetch, a live lookup confirming each included source exists, the annotation fields, the BibTeX entries from the confirmed page, and theme notes; the session's one identifier check over every entry, which blocks under strict and marks under mark-only (`intake_agent.md:274`); then one merge run that removes duplicates, resolves the identifier check's title differences, writes the report, the matrix, the gaps, the skew advisory and the synthesis, runs the gates and searches only where a gate fails ("Where a gate fails, apply the agent file's Failure Handling Strategies yourself"), and writes the merged `.bib` in ASCII with every cited key in it.
3. The strategist writes each `.bib` entry from the record or the page it read.
4. Given a `.tex`, the run adds its entries to that manuscript's `.bib` by patch.

Everything else on the lit-review path goes.
