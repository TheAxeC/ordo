## What to build

When the part is done, `paper`'s literature strategist searches the primary databases of the request's discipline through their own interfaces, reads each candidate's abstract and key sections from what it can reach, keeps only references `lookup.py` confirms, and gives a preprint that has a published version the published version's entry, written by `lookup.py bibtex`; the run's records (`review.md` and the session's transcript) show every search and every address read.

### 1. The search (`references/literature-strategist.md`, "What the agent reads", "The search design", "Criteria", "The four searches", "Source counts and gates"; `SKILL.md`)

- The page gains academic-paper's database selection: a table of primary databases by discipline with the rows of academic-paper's "Step 2" table except the Taiwan HEI row, which the coverage inventory drops (`docs/academic-coverage.md:124`, "Taiwan databases ... have no user"). For each database the table says how the agent reaches it, from these ways, chosen by what the database offers without a login, a payment or a bot check:
  - its own public interface, named with its address (for example PubMed's E-utilities, Europe PMC's REST service, ERIC's API, Semantic Scholar's search, OpenAlex's search with its `filter` parameter, Crossref, arXiv's query interface), queried with `curl` from the shell;
  - a web search limited to the database's site (`site:<host>`), for a database whose interface needs a login, a subscription or a key the environment does not hold (for example JSTOR, Scopus, Web of Science, IEEE Xplore);
  - not reached, named in `review.md` with the reason.
- The agent selects two or three primary databases by the Discipline row, as academic-paper's layer 1 does. A Discipline row that names more than one field, or a field and the field it is applied in (such as "Machine learning, with medical image analysis as the application setting"), takes the rows of each field it names, so that each field's literature is searched in its own databases. A Discipline row the table does not list takes the General row, and an empty one the General row with the search broadened, as academic-paper's "Discipline not specified" line (`agents/literature_strategist_agent.md:575`) says.
- The agent never signs in, never passes a bot check or a CAPTCHA, never pays, and never uses a key the environment does not hold. A key the environment holds for an interface (such as `NCBI_API_KEY`) is used, and its value is written `<REDACTED>` in every line of `review.md` and of the report.
- A value that reaches `curl` (a search string, an identifier, an address) is sent as one argument in single quotes, as `SKILL.md`'s Steps 2 says for every value, and a query value is percent-encoded (`curl -G --data-urlencode 'term=<string>'`).
- The search string has academic-paper's form with its `Filters:` line (peer-reviewed, year range, language). The language and the year range are applied in the query where the interface supports them; the publication-type and peer-review filters apply at screening, so that a source type the profile admits is never removed before screening (the page's rule "A filter never removes a source that the screening tree would admit", line 66, stays). Seminal works older than the year range enter through layers 2 and 3, which take no year filter, and the seminal rule of node 2 decides them. `review.md` says which filters each search applied in its query.
- Line 41's sentence and line 42's sentence are replaced by these rules. Line 54's "it never changes which indexes are searched" reads "databases". The gate "Search documented" (line 196) names the databases and interfaces. `lookup.py search`, `refs` and `cited-by` stay among the agent's means.
- Layer 1's decision follows academic-paper: under 20 records the agent relaxes the search (the NOT term removed, the year range widened), over 500 it tightens it (qualifiers, a narrower year range). The count is the total the interface reports, such as PubMed's `count` or OpenAlex's `meta.count`. A database reached only by a web search reports no total; its search is recorded with "no count", and layer 1's decision uses the totals of the interfaces that report one. Line 111's reading of "first 100, more exist" stays for `lookup.py`'s listings.
- Layers 2 and 3 use `lookup.py refs` and `cited-by`, or a database's own reference and citing links (such as PubMed's `elink` or Europe PMC's references and citations). Layer 4 is a semantic search, as academic-paper's layer 4 is: Semantic Scholar's search, or `lookup.py search` with the question as a sentence.
- The search record in `review.md` ("Search strategy") names for each search the database, the interface (the request address with the query, or the command), the string, the filters applied in the query, the date, the total count reported or "no count", and the records taken into screening. A database left out or not reached is named with its reason.

### 2. The reading (`references/literature-strategist.md`, lines 3 and 11, "Screening", "Reading a candidate", "A candidate that cannot be read", "The annotated bibliography")

- The agent reads the abstract and key sections of each Include and Maybe candidate, as academic-paper's "Phase B" does, from every file and page it can reach without a login, a payment or a bot check, trying in this order and stopping at the first that gives the abstract (for the stage "Title and abstract") or the text (for the stage "Full-text assessment"):
  - the file `lookup.py fetch` writes, as now;
  - PubMed (`efetch.fcgi?db=pubmed&id=<PMID>&rettype=abstract&retmode=text`) or Europe PMC (`resultType=core`) for the abstract, and PMC or Europe PMC for the open-access full text;
  - the page at the DOI, at the venue (the proceedings site, the publisher), and each open-access address `fetch` printed and did not take (such as a PMC page that is not a PDF): its abstract section, or its `citation_abstract`, `dc.description` or `og:description` tag;
  - a page a web search finds for the work's title, such as an author's copy or a repository record.
- Each text or page is saved with `curl -sSL --fail -w '%{http_code} %{url_effective}\n' -o '<temporary folder>/<stem>.read-<n>.<ext>' '<address>'`, `<stem>` as `lookup.py` makes it from the key, `<n>` counting the pages saved for that candidate from 1, `<ext>` `html`, `pdf`, `txt` or `xml` as the reply is, and read with the Read tool. The printed status and final address go in `review.md` beside the candidate.
- The agent never reads a source's text through WebFetch, whose output is a model's processing of the page. Web search finds pages; it is not a reading of one.
- "A candidate that cannot be read" applies only after these ways are tried, and `review.md` names, for each such candidate, each address tried with its status.
- An annotation names the address its text was read from, since the temporary folder is removed at the run's end (ADR 0020); the session's transcript keeps the text read.
- Lines 3 and 11, the files the agent writes, add the texts and pages it saves into the run's temporary folder; it changes no other file.

### 3. The check of every kept reference, and the published version of a preprint (`references/literature-strategist.md`, "The BibTeX entries" and "Starting from the manuscript's `.bib`"; `templates/lookup.py`; `templates/lookup.test.sh`; the pages that call `bibtex`)

- A source the agent finds by any interface is included only after `lookup.py resolve` (by its DOI, its arXiv ID, or its title with its year) prints a record that matches it; one no index prints a record for is listed under "No entry written" and not cited, as line 294 says now. Every entry `refs.bib` keeps prints `CONFIRMED` under `resolve --entry`, as now.
- `lookup.py bibtex` prints the entry on standard output and every other line on standard error, so that "as the script printed it" (line 288) means the standard output, which is the entry alone. Its exit status stays 0 when an entry is printed and 1 when none is.
- `bibtex <arXiv ID>` (and a DOI `10.48550/arXiv.<id>`) gives the published version's entry when an index names one:
  - It asks Semantic Scholar and OpenAlex for the arXiv ID's record, with the fields it needs (Semantic Scholar's `publicationVenue`; OpenAlex's `doi` and `locations`), in requests of its own; the requests of `resolve`, `search`, `refs`, `cited-by` and `fetch` stay as they are, so their cached replies stay valid.
  - The published DOI is a DOI that is not of the form `10.48550/arXiv.<id>`, named by Semantic Scholar's `externalIds.DOI`, by OpenAlex's `doi`, or by a doi.org `landing_page_url` of an OpenAlex location. When one is named and its record, resolved as `resolve` resolves a DOI, has a title ratio of 0.70 or more against the title of the arXiv ID's record (from arXiv, or from Semantic Scholar or OpenAlex when arXiv is left out), `bibtex` prints the BibTeX entry `https://doi.org/<that DOI>` returns, as it does for a DOI, and exits 0.
  - When doi.org gives no entry for that DOI, or every index is left out when its record is resolved, `bibtex` prints the `@misc` entry and on standard error `published DOI <doi>: doi.org <reason>` or one `<index>: left out, <reason>` line per index, and exits 0.
  - Otherwise, when Semantic Scholar's record names a `publicationVenue` of type `conference` or `journal` whose name and alternate names do not contain "arxiv" in any case, `bibtex` prints the `@misc` entry and on standard error `published in <venue name> (<type>) per Semantic Scholar, with no DOI named by Semantic Scholar or OpenAlex: lookup.py bibtex <arXiv ID> --page <the venue's page of the work>`, and exits 0. A venue of another type, or with no type, gives no such line.
  - Otherwise it prints the `@misc` entry as now. An index that is left out is printed on standard error as `<index>: left out, <reason>`, so the agent knows the published version was not checked there. With arXiv left out and no published DOI found, `bibtex` prints `arXiv: left out, <reason>` and exits 1, as now.
- `lookup.py bibtex <arXiv ID> --page <url>` builds the entry of the published version from the venue's page of the work:
  - It fetches the page (an http or https address, after redirects on a host other than `doi.org`, `dx.doi.org`, `www.doi.org`, `arxiv.org`, `www.arxiv.org` and `export.arxiv.org`) and reads its `citation_*` meta tags, the standard tags of a scholarly page: `citation_title`, each `citation_author`, the year of `citation_publication_date` or else of `citation_date`, and `citation_conference_title` or else `citation_journal_title`, with `citation_volume`, `citation_firstpage` and `citation_lastpage` when present.
  - The probes of 2026-11-16 show these tags on PMLR (`proceedings.mlr.press/v97/lee19d.html`: `citation_title`, `citation_publication_date` "2019/05/24"), NeurIPS (`proceedings.neurips.cc/.../f22e4747...-Abstract.html`: `citation_journal_title` "Advances in Neural Information Processing Systems", `citation_publication_date` "2017") and the ACL Anthology (`aclanthology.org/N19-1423/`: `citation_publication_date` "2019/6"). OpenReview answers a challenge page (`api2.openreview.net`: "Challenge verification required"), so an OpenReview-only paper has no page `--page` can read.
  - The entry is `@inproceedings` with `booktitle` when Semantic Scholar's `publicationVenue` type is `conference` or the page has `citation_conference_title`, and `@article` with `journal` otherwise; it holds `title`, `author`, `year`, the volume and pages when present, `url` = the page's final address, and `eprint` and `archivePrefix = {arXiv}`. Its key is built as the `@misc` key is.
  - It refuses (standard error, exit 1, no entry) when the page cannot be fetched, has no `citation_title` or no year tag, or its `citation_title` has a title ratio below 0.70 against the arXiv ID's record, each with its reason.
- `lookup.py resolve --entry <file.bib> <key>` confirms such an entry:
  - For an entry whose type is not `@misc`, that has no `doi`, holds an arXiv ID as now, and whose `url` is an http or https address whose host after redirects is not one of the six above: when no record confirms it as now, the script fetches the `url` page and reads its `citation_title` and year tags as `bibtex --page` does. The entry is confirmed when the page's `citation_title` has a title ratio of 0.70 or more against the entry's title, the year tag's year equals the entry's year, and a record of the arXiv ID has a title ratio of 0.70 or more against the entry's title.
  - The last line is then `<key>: CONFIRMED against <index>, ratio <r>, year <record year>; year <entry year> found on <url>`, and exit 0.
  - Otherwise the verdict stays `NOT_CONFIRMED` as now, the line ending `; <url>: no citation_title tag`, `; <url>: no year tag`, `; <url>: citation_title ratio <r>`, `; <url>: year <y> on the page` or `; <url>: <reason>` for a page that fails, the first that applies in that order of fetching and reading.
  - Every other entry is resolved and confirmed exactly as now, with no page fetched; an entry with a `doi` is resolved by its DOI as now.
- The strategist page: for an entry whose `bibtex` printed the "published in" line, the agent finds the paper's page at the venue (the proceedings site, the ACL Anthology, the publisher) by a search, and writes the entry `lookup.py bibtex <arXiv ID> --page <url>` prints.
