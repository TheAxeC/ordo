## What to build

The ruling "The standards stop" of `plan.md` is the requirement. The items below state it and close the gaps the first run showed. All of them are changes to `skills/code/codebase-design/SKILL.md`, except item 16.

1. The comparison sorts every rule of every default page of a subject that applies into exactly one of these: present, or one of the five groups. The skill's text defines each so that a session can tell them apart, tries them in the order below, and does not use the word "kind" for them, which the glossary defines otherwise:
   - present: the repository's pages hold a rule on the same requirement, wherever it stands;
   - group 1, a contradiction: the repository's pages hold a rule that says otherwise on the same requirement;
   - group 2, a rule of the default pages about how work is done: a rule whose following cannot be read from the repository's code, such as a rule of the change standard, which the repository's pages lack;
   - group 3, a rule the code already follows: a rule whose following can be read from the code, which the pages lack and the code follows in more than half of the places it applies to;
   - group 4, a rule the code does not follow: the same, where the code follows it in half of the places or fewer;
   - group 5, a rule about a tool the repository lacks: a rule that names a tool (a formatter, a linter, a type checker) for which the tree holds no configuration. A default bullet that names such a tool and also states a requirement the code shows without the tool is split: the requirement is sorted on its own into present or groups 1 to 4, and only the sentence about the tool goes to group 5.
   - A rule whose following could be read from the code and that applies in no place of the code is left out, and is listed in the audit file.
2. The skill says what one rule is: one numbered item or one bullet of a default page, split only as item 1 says for a tool. A default item that holds more than the repository's item on the same requirement is present; the sentences it holds beyond the repository's are not drafted and not asked about.
3. The stop "The draft" shows the groups in this order and these forms, and nothing else of the comparison:
   - group 1, each in full: what the repository's page says now, quoted, with the page and the section named in words; what the default says, quoted; what goes wrong under each, in one plain sentence each; the choice put to the user. Nothing is added for a contradiction unless the user chooses the default's rule, and the skill then says that the repository's rule needs the user's own rewrite, which this mode does not make.
   - group 2, in one line per default page: the rules named by their titles or opening words as the default page has them, not reprinted, with one yes or no for the whole group.
   - group 3, one line each, numbered, the numbers running on through groups 3 and 4 so that each number names one rule: the rule in the words it would be added in, then the count read from the code as "<n> of <m>". Each is added unless the user strikes its number.
   - group 4, one line each, numbered: the rule in a few words, then what adopting it would break, with its count. None is added unless the user names its number.
   - group 5, one line for all: the tools named. None is added.
   - then each new page for a subject or a language the repository lacks, shown as it would be written, and each change to `plan.yaml`. The rules of a new page are sorted like any others: the page holds its rules of groups 2 and 3, its rules of group 4 stand as lines of group 4 and enter the page only when the user names them, and its rules of group 5 are left out.
   - then one sentence that says how many default rules were found present, and the absolute path of the audit file of item 5.
4. No line of the stop locates a rule by a line number alone: a place is named by its page and its section in words, and a line number may follow it. The stop does not show where an addition will be placed; the skill places it (Steps / standards 6) and names the place in its last message, after the writing.
5. The audit file: the skill writes one Markdown file outside the repository, in the operating system's temporary folder as "Steps / review" 8 finds it, named `standards-audit-<timestamp>.md`. It holds each default rule found present with the page, the section and the line where it stands, each rule of groups 3 and 4 with the command that produced its count, and where each addition will be placed. The user is not asked to open it.
6. A placeholder the code does not settle stays a question in the draft, written as one plain sentence that says what is not known and what each answer would write. It stands directly under the line of the group that holds its rule.
7. A conditional default rule ("Where the repository uses ...") whose condition the code shows to be false is left out and not shown.
8. A default sentence that points at something the repository lacks, such as a glossary page, is drafted without that pointer. An example in a default rule that names a thing of another kind of repository is replaced by an example from the repository's own pages or code.
9. The languages are read from the files git tracks, leaving out vendored third-party folders (a folder named `third_party`, `vendor` or `node_modules`) and the ledger folders. The skill states the file extensions of each language itself and cites no section of another skill for them.
10. A repository uses Svelte or SvelteKit when it tracks a `.svelte` file. The question on the user interface is asked after the repository's pages are read, and is not asked when a page of the repository holds a UI standard, which means it has a user interface.
11. A language's page of the coding standards is present only when the repository's pages hold a page or a section for that language. Sentences about that language's files inside rules of another subject do not make it present; the language then lacks its page, and the mode drafts that page as a new page, as item 3 says.
12. A new page for a subject the repository lacks: with a `plan.yaml`, it stands beside the repository's pages and is added to the `standards` list; without one, it takes the fixed name under `docs/dev/`. The two sentences of Steps / standards 6 that now contradict each other on this are replaced by this rule.
13. The skill says that only the pages of places 1 and 2 of the search order are compared, so a rule standing on a page the repository's `plan.yaml` does not name counts as missing, and that the stop says so in one sentence when the repository holds other pages of rules it did not read.
14. After the user's answer, the skill writes the approved additions and its last message names every file written and, for each addition, the page and the section it now stands in. No commit is made.
15. When nothing is in groups 1 to 4 and no page is new, the stop is not raised: the skill says that the repository's pages hold every default rule that applies, gives the audit file's path, names in one line the tools of group 5 when there are any, and ends.
16. Where the skill names the `repo-setup` skill or its folder, it names the `ordo-init` skill and its folder: the default pages stand in `templates/docs/dev/` of the `ordo-init` skill's folder beside this skill's folder, the ADR templates in its `templates/docs/adr/`, the refusal is "No ordo-init folder", and the row of "Use instead" for a new repository names `/ordo-init`. This reaches the lines of "Steps / review" and of the Stops table that name the folder. The skill cites no numbered item or section of the `ordo-init` skill, whose text step 5 rewrites: the fixed names under `docs/dev/` are already listed in "What it reads" 4 and stand there on their own.
17. The frontmatter's `description` and the README's row of the skill (line 30) say what the stop now shows, in the row's present length or shorter (`awk 'NR==30{print length($0)}' README.md` prints 1161 now, and at most that after), the description keeping every trigger and at most 1024 characters: the draft is shown in groups, a rule the code already follows in one line with its count.

The Stops table's row "The draft" and the Anti-patterns table are brought in line: the row says what the stop shows by the groups; one anti-pattern row is added for a draft that lists placements and line numbers in place of what a rule says, with why it fails (the user cannot judge a rule without opening the pages) and what to do instead.
