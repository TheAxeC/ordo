## What to build

1. `skills/session-retro/templates/transcript_window.py`: a Python script, standard library only, running on Python 3.9 or newer (`from __future__ import annotations` at the top, so the `X | None` form of `python.md` "Typing" is written and checked under `--target-version py39`), with a head docstring stating usage, what it prints, the redaction patterns, every error and the exit statuses. It computes the approved list and nothing else:
   - **Usage.** `transcript_window.py <transcript folder> <start> <end>` or `transcript_window.py <transcript folder> --session <session id>`. `<start>` and `<end>` are ISO 8601 times with a zone (`Z` or `+02:00`, with or without a fraction of a second), parsed on 3.9 too (where `datetime.fromisoformat` does not take `Z`); an entry is in the window when `start <= timestamp < end`, compared as times. Errors, each one line `error: <what>` on stderr, exit 2, nothing on stdout and no file read: no arguments, too many, or `--session` together with times; a time without a zone or unparsable; an end not after the start; a folder that does not exist or is a file; a session id that is empty or holds anything but letters, digits, `-` and `_` (so no `/`, `..` or glob character reaches a path); a session id with no `<session id>.jsonl` in the folder.
   - **The files.** With a window: every `*.jsonl` directly in the folder and every `*/subagents/agent-*.jsonl`. With `--session`: `<session id>.jsonl` and `<session id>/subagents/agent-*.jsonl`, every entry of them. A folder with no such file prints nothing. Each file is read in binary, line by line, never whole.
   - **What is printed.** For each entry in the window, one item per piece:
     - `user`: a user's message. A `user` entry whose content is a string, unless the entry has `isMeta` or `isCompactSummary` true or the string starts with `<task-notification>`; each `text` block of a `user` entry whose content is an array, unless the entry has `isMeta` true; an `attachment` entry whose `attachment.type` is `queued_command` and `attachment.commandMode` is `prompt`, unless `attachment.isMeta` is true, its `attachment.prompt` as the message.
     - `text`: each `text` block of an `assistant` entry.
     - `tool <name>`: each `tool_use` block of an `assistant` entry, with the first line of its input: the value of the first field of `input`, in the entry's key order, whose value is a string, taken to its first newline. An input with no string field prints the prefix and `tool <name>:` with nothing after it.
     - Nothing else: no `thinking`, no `tool_result`, no other type, no other attachment.
   - **The prefix.** Each item starts on a new line with `<id> <line> <timestamp> <kind>: `, where `<id>` is the session id for a main-session file and `agent-<agent id>` for a subagent file (taken from the file name), `<line>` the 1-based line number in its file, `<timestamp>` as the entry has it, and `<kind>` one of `user`, `text`, `tool <name>`. A text of several lines prints its further lines indented by two spaces, so each item's first line is the only one that starts with an id.
   - **The order.** All items of all files sorted by timestamp as a time, then by file path, then by line number and the block's place in the entry, so the output is the same on every run.
   - **Redaction.** Before printing, every match of these patterns is replaced by `<REDACTED>` (every name matched regardless of case):
     - key and token shapes, each not preceded by a letter or digit: `sk-ant-[A-Za-z0-9_-]{8,}`, `sk-[A-Za-z0-9_-]{20,}`, `[sr]k_(live|test)_[A-Za-z0-9]{16,}`; `gh[pousr]_[A-Za-z0-9]{20,}`, `github_pat_[A-Za-z0-9_]{20,}`, `glpat-[A-Za-z0-9_-]{20,}`, `npm_[A-Za-z0-9]{36}`, `hf_[A-Za-z0-9]{30,}`; `AKIA[0-9A-Z]{16}`; `xox[abprs]-[A-Za-z0-9-]{10,}`, `https://hooks.slack.com/services/` and what follows up to whitespace; `AIza[0-9A-Za-z_-]{35}`; a JWT `eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`;
     - a PEM private key block, from a `-----BEGIN ... PRIVATE KEY-----` line to its `-----END ... PRIVATE KEY-----` line;
     - the rest of the line after `Authorization:`, `Proxy-Authorization:`, `Cookie:` or `Set-Cookie:`, and the word after `Bearer ` or `Basic `;
     - the value of a name that is, or ends in, `password`, `passwd`, `secret`, `token`, `api_key`, `api-key`, `apikey`, `access_key`, `access-key`, `private_key` or `credentials` (so `AWS_SECRET_ACCESS_KEY`, `MY_API_KEY` and `x-api-key` match, `max_tokens` does not), written `name=value`, `name: value`, `"name": "value"`, `name="value"` or `name='value'`: the value inside the quotes when quoted, and otherwise up to whitespace, a comma or a quote;
     - the password of a URL `scheme://user:password@host`.
     - Commit hashes, UUIDs, agent ids and other hex strings are not redacted, since the report quotes them as places.
   - **Lines skipped.** A line that is not UTF-8 or not JSON, and a `user`, `assistant` or `attachment` entry whose `timestamp` is missing or unparsable, is skipped; after the output, one line per such file on stderr, `skipped <n> lines of <file>`. An entry of another type without a `timestamp` (`mode`, `ai-title` and the rest) is not an item and is passed over without being counted.
   - **Files not read.** A file that cannot be opened or read (no permission, removed between listing and reading) is reported on stderr as `error: cannot read <file>: <reason>`, the other files are still printed, and the exit status is 1.
   - **Exit statuses:** 0 the output printed (an empty window prints nothing and exits 0), 1 a file could not be read and the output lacks it, 2 a usage error.

Its head comment lists every case. Last line `PASS: transcript_window.py scratch tests`.

## Decisions taken in this brief (each reversible, none silent)

1. The window is half-open (`start <= t < end`) and needs a zone, so a window written in local time cannot silently shift by the zone's offset (the plan's commit times are +0200, the transcripts' UTC).
2. "Each user message" of the approved line is read as each message the user typed, wherever the transcript writes it: the `user` strings and `text` blocks that are neither meta nor a compaction summary nor a task notification, and the `queued_command` prompts that are not an agent's hand-back; in a subagent file, the prompt it was started with, which is that transcript's user message. Harness text (skill bodies, reminders, summaries, task notifications, hand-backs) is not a user message. Booked in 2.H's Rulings as "Step 1, what a user message is".
3. "Its first line of input" is the first string field of the input in its key order, to its first newline. On the real calls (the survey) it gives the command of `Bash`, the path of `Read`, `Write` and `Edit`, the message of `SubagentHandback`, the description of `Agent` and the recipient of `SendMessage`; a call with no string field prints the tool's name alone.
4. "Looks like a key or a token" is the fixed list of patterns above, covering the change standard's secrets in quoted output (a password, an API key, an access token, a private key, a session cookie, a credential in a URL); hex strings are left, since commit hashes are the places a report quotes.
5. A multi-line text keeps its lines, indented, so a quote in the report can be copied from the output.
6. A line that cannot be read is skipped and counted, since one torn line at the end of a file being written must not stop a read of 100 MB; a normal entry without a timestamp is not counted, so the count names only real damage. A file that cannot be read makes the exit status 1, since the output then lacks it.
