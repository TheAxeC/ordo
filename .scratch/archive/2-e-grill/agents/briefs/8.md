## What to build

The ruling (O5 (a), plan.md Rulings): a new or changed test is run once on the unchanged tree and must fail there; the report quotes that failure; no revert is named per test; `/refute` finds, by reading, a test that cannot fail.

1. Rule 13 in `docs/dev/change-standard.md:39` and `skills/repo-setup/templates/docs/dev/change-standard.md:39`, the same line in both, becomes exactly:

   "13. **A test proves the change by failing on the unchanged tree, and the report quotes the failure.** The unchanged tree is the tree before the change; for a plan step it is the tree at the step's base. Every new test, and every test changed for a behaviour the change adds or changes, is run once on the unchanged tree and fails there, except a case asserting that a rule stays silent. The report quotes that failing output verbatim beside the test's name. No revert is named per test. A test changed only for a behaviour the change preserves passes on the unchanged tree and after the change, and the report quotes both runs. A test that cannot fail, whatever the code under it does, is an audit, not a proof: an assertion over source text, over a name alone, over a constant, or over a path the suite never executes. The reviewer finds such a test by reading it. A case asserting that a rule stays silent carries a control, the near-miss the same rule must report, and the report quotes beside it the failure on the unchanged tree of the case or of its control, whichever fails there. Each behaviour the change adds or changes whose failure costs something, as "Scripts compute facts; judgment is read" says, has a case, and the report lists them in a table: the behaviour, the case and the failing line that the case, or for a silent case its control, printed on the unchanged tree. The table covers those behaviours, not every branch or every rule a head comment states."

2. `skills/spec/templates/brief.md:62` becomes exactly:

   "4. Each new test, and each test changed for a behaviour the change adds or changes, is run once on the unchanged tree and fails there, or, for a case asserting that a rule stays silent, the case or its control fails there; the report quotes that failure. A test that cannot fail, whatever the code under it does, is an audit, not a proof, and this brief says which it is."

## Decisions taken in this brief (each reversible, none silent)

1. The two texts beyond the step line's four, `common.md:13` and `plan-retro/SKILL.md:67`, are changed in this step, since rule 14 carries a change to every place that names it and each of them names the old rule or its wording.
2. The table's columns become "the behaviour, the case and the failing line that the case, or for a silent case its control, printed on the unchanged tree", in place of "the behaviour, the case, the revert and the red line it produced", since no revert is named.
3. A case that asserts a rule stays silent usually passes on the unchanged tree (the rule does not exist yet), and when the change fixes a false report it fails there while its control passes. So the rule excepts the silent case from "fails there", the control keeps its place, and the report quotes whichever of the two fails on the unchanged tree. Five real cases from the tree, each read under the new rule:
   - Step 3 of this plan (`agents/reviews/3-report.md:21`), "First pin links ordo-a.md and ordo-b.md": on the unchanged tree it printed `FAIL: <T>/my home/.claude/agents/ordo-a.md does not link into the pin`. Under the new rule that line is the quoted failure, and it is enough.
   - Step 3 (`3-report.md:35`), "`agents/notes.txt` and `agents/sub/x.md` neither linked nor counted": it passed on the unchanged tree, since nothing is linked there, and the report then named reverts M03 and M03b. Under the new rule it is a silent case: its control is the near-miss the rule must report (an `ordo-*.md` agent file beside it, linked and counted), and the control's failure on the unchanged tree is quoted beside it.
   - Step 2 (`2-report.md:62`), `projects-five` passed on the unchanged tree and its control `projects-five-control` failed there with no `tool-b: worker_effort not set` note. The new rule gives the same reading as the old: the control's failure is quoted.
   - Step 2 (`2-report.md:64`), `adr: docs/decisions` absent refused: on the unchanged tree it printed `error: unknown key: adr`. A test asserting only a non-zero exit would have passed there for the wrong reason; under the new rule it must fail on the unchanged tree, so it asserts the line the change adds, and the reviewer finds by reading one that asserts the exit alone.
   - Step 3 (`3-report.md:40`), "Check mode, no agent folder: folder not created": its "not created" part passed on the unchanged tree, since the unchanged tree creates nothing. Under the new rule that part is a silent case, and it needs a control that fails on the unchanged tree; its missing agents line is one.
4. `/refute`'s line 100 ("a "seen failing first" claim with no quoted failing check") stays: it covers a "seen failing first" claim about a check that is not a new or changed test, such as a verification command, which the first new bullet does not reach.
5. "The unchanged tree" is defined once in rule 13 as "the tree before the change; for a plan step it is the tree at the step's base", so the template copy reads correctly in a repository where a session works inline with no plan step; `skills/spec/templates/brief.md:20` already uses it that way.
6. Decided by the orchestrator overnight (ruling "Overnight work" 5), booked for Axel: a test changed only for a behaviour the change preserves (a refactor) cannot fail on the unchanged tree. Options: (a) the rule names it: it passes on the unchanged tree and after the change, and the report quotes both runs; (b) the rule stays literal ("every new or changed test ... fails there"), which a refactor step cannot meet. Taken: (a). The old text had the same gap (no revert turns such a test red). (b) is the lazy option, leaving a rule a step cannot follow.
7. For a new script, every test fails on the unchanged tree because the script is missing, and that missing-script failure is the quoted failure. The per-behaviour proof then rests on `/refute`'s reading for a test that cannot fail, which is what the ruling chose. A test asserting only a non-zero exit passes there (a missing script exits 127), so it is caught by the first sentence.
8. A test changed in a repair round is a changed test: it is run on the unchanged tree again, and the round's report quotes that run.
