## What to build

The three pages are templates `repo-setup` copies into a repository and adapts to its names (step 7). A place the repository fills in is written as `<...>` inside backticks, with the default inside where there is one; a repository choice is written `<yes or no>`. No project name and no name of a library or tool of the source repositories appears in any page (cathedra, rite, curia, monastery, game-engine, missal, oculus, cockpit, research-hub, Ordo), and no ADR number: the skills carry no project name (`README.md`, first paragraph).

Each page is titled `# Coding standards: <language>` and opens with one sentence saying it adds to `common.md` beside it and to `../design-principles.md`, and repeats neither. Sections follow in the order below, each rule a bullet in the concrete form it takes in the language, in short sentences joined by full stops. A tool that enforces a rule is named inside the rule's own sentence (for example "ruff's `B` rules refuse it"), and only a rule of the page's own starting configuration is named so; a rule no configured tool enforces is written without a tool and is checked by reading. No trailing field repeats on every bullet (the prose standard's section 0, repeated construction). Each page is under 90 lines.

1. `skills/repo-setup/templates/docs/dev/coding-standards/cpp.md`:
   - **Language and tooling.** The standard is `<C++20>`. clang-format formats every source file from a `.clang-format` in the repository: 4-space indent, braces on the same line, left-aligned pointers `T* p`, a column limit of `<120>`. clang-tidy runs from a `.clang-tidy` with the groups `bugprone-*`, `modernize-*` (without `modernize-use-trailing-return-type`), `performance-*` and `readability-*`, and `readability-identifier-naming` set to the cases of "Naming".
   - **Errors.** Errors are values: a fallible function returns a result type marked `[[nodiscard]]`, and the caller branches on it. When the repository builds with `-fno-exceptions` (`<yes or no>`), a throwing standard operation is not used where input can reach it: `.at()` gives way to `find()` and a defined fallback, `std::stoi` to `std::from_chars`, the `std::filesystem` overloads without `std::error_code` to those with it, `optional::value()` and `std::get<>` by type to a checked access. When it builds with `-fno-rtti` (`<yes or no>`), no `dynamic_cast` and no `typeid`.
   - **Construction.** A constructor establishes the class's invariant from its arguments, and the destructor releases what the class owns (RAII). Where the repository uses two-phase setup (`<yes or no>`), a constructor takes nothing and does nothing, setup that needs a collaborator lives in `initialize(<context>)`, and teardown that touches a collaborator lives in `shutdown()`.
   - **Headers and includes.** A public header lives under `<include/<lib>/>` and ends `.hpp`; every other header ends `.h`. A public header hides third-party types behind PIMPL or an opaque handle, and names no private header of another library. `#pragma once` in every header. A `.cpp` includes its own header first, then the standard library, then third-party headers, then the project's own. A `.cpp` that exports a symbol declares it in a header it includes itself. File names are lowercase.
   - **Naming.** One project namespace, `<name>`, nested only to avoid a real collision; a free function carries its module in a compound name. Types `PascalCase`; functions, methods and variables `lowerCamelCase`; members `m_name`; namespace- and file-scope `constexpr` constants `SCREAMING_CASE`. `enum class` always, with an explicit underlying type when the value is serialised, sized an array or crosses an ABI. Where the repository defines fixed-width aliases (`<u32 and the like, or none>`), declarations and members use them.
   - **API shape.** A stateful type is constructed by a static factory on the type, and an operation on it is a member. A free function stays for a passive value type (math on plain aggregates) and for a file-local helper with internal linkage.
   - **`struct` and `class`.** `struct` for a passive aggregate with public members and no invariant. `class` with private state for a type that keeps an invariant.
   - **Members and accessors.** No `this->` on member access. An accessor takes no `get` prefix (`size()`, `width()`), and a mutator keeps a verb (`setWidth()`). `[[nodiscard]]` on accessors and on every function that returns a result (clang-tidy's `modernize-use-nodiscard`).
   - **Containers and memory.** `std::span` and `std::string_view` at boundaries. No node-based map or set (`std::map`, `std::unordered_map`, `std::set`, `std::unordered_set`) on a hot path; a flat open-addressing table instead. A value type with many instances on a hot path lives in an index or a pool, never in one heap allocation each. When the repository is allocator-aware (`<yes or no>`), code under `<src>` calls no `new`, `delete`, `malloc` or `free` and holds no default-allocator owning container, `std::string` excepted; allocation goes through a memory resource passed in explicitly, never the process default resource, and a member's resource is set in the member-initialiser list, never in a constructor body.
   - **Documentation comments.** A public declaration carries a Doxygen `///` brief, with `@param` and `@return` only where they add what the signature does not say. Everything else is plain `//`.
2. `skills/repo-setup/templates/docs/dev/coding-standards/python.md`:
   - **Language and tooling.** Python `<3.10>` or newer, set as `requires-python` in `pyproject.toml`. ruff formats and lints every module from `pyproject.toml`, line length `<100>`, with the rule groups `E`, `F`, `W`, `I`, `B`, `UP`, `SIM`, `N`, `PTH`, `ANN`, `BLE` and the rule `S602` as the starting set. pyright type-checks every module with `typeCheckingMode = "standard"`.
   - **Naming.** Modules and functions `snake_case`, classes `PascalCase`, module constants `SCREAMING_CASE`, a leading `_` for what is private to its module (ruff's `N` rules).
   - **Typing.** Every function and method annotates its parameters and its return type (ruff's `ANN` rules). Built-in generics (`list[str]`, `dict[str, int]`) and `X | None` (ruff's `UP` rules). `Any` appears only where a value is parsed from outside, and it is narrowed before use.
   - **Errors.** A failure raises a specific exception class, a built-in one or the module's own subclass of `Exception`. No bare `except:` (ruff's `E722`) and no `except Exception` that swallows the failure (ruff's `BLE001`). A command-line script prints its error to stderr and exits non-zero.
   - **Module layout.** Module-level code only defines: imports, constants, functions and classes. Work starts under `if __name__ == "__main__":` or an entry point. Imports sit at the top, grouped standard library, third-party, first-party (ruff's `I` rules sort them).
   - **Files and processes.** Paths are `pathlib.Path` (ruff's `PTH` rules). A file is opened with an explicit `encoding="utf-8"`. A subprocess runs with a list of arguments, never `shell=True` (ruff's `S602`).
3. `skills/repo-setup/templates/docs/dev/coding-standards/typescript.md`:
   - **Language and tooling.** `tsconfig.json` sets `"strict": true`. ESLint runs from a flat config with `@eslint/js` recommended and typescript-eslint `strictTypeChecked` and `stylisticTypeChecked`, with type information (`projectService: true`). An unused disable comment fails the lint (`reportUnusedDisableDirectives: 'error'`). A rule turned off in the config names why beside it, and a disable comment at a site names its reason. Prettier formats every source file from a `.prettierrc`: `tabWidth: 4`, `useTabs: false`, `singleQuote: true`, `printWidth: <100>`, `trailingComma: "none"`.
   - **Types.** A shape is declared with `type` (`@typescript-eslint/consistent-type-definitions` set to `type`). An `interface` stays only where declaration merging needs one, with a disable comment saying so. No `any` (`no-explicit-any`); a value parsed from outside is `unknown` and narrowed. No non-null assertion `!` (`no-non-null-assertion`).
   - **Names and unused values.** Types `PascalCase`, functions and variables `camelCase`, constants `<SCREAMING_CASE or camelCase>`. A binding the syntax requires and the code does not read is named with a leading `_` (`@typescript-eslint/no-unused-vars` with `argsIgnorePattern: '^_'` and `varsIgnorePattern: '^_'`).
   - **Errors and promises.** A promise is awaited, returned or marked `void` (`@typescript-eslint/no-floating-promises`). A thrown value is an `Error` or a subclass of it (`@typescript-eslint/only-throw-error`). No empty `catch` block (`no-empty`).
   - **Modules.** ES modules only, and no `var` (`no-var`). A module exports named values, not a default export where a named one serves. No import cycle, refused by `<the import-cycle check>`.
   - **Svelte and SvelteKit (only in a repository that uses them)**, its own section at the end:
     - eslint-plugin-svelte `flat/recommended` lints `.svelte` files, parsed by `svelte-eslint-parser` with the TypeScript parser inside script blocks. `prettier-plugin-svelte` formats them.
     - `svelte/prefer-const` replaces the core `prefer-const`, with `excludedRunes` set to `$derived`, `$props` and `$state`. An unused disable comment in markup fails (`svelte/comment-directive` with `reportUnusedDisableDirectives: true`).
     - An async handler on a control is allowed (`@typescript-eslint/no-misused-promises` with `checksVoidReturn: false`).
     - A component file stays under `<600>` lines, and `<the size check>` flags it at `<540>`.
     - A view draws its controls with the repository's shared components, never a raw `button`, `input`, `select` or `textarea` (`svelte/no-restricted-html-elements` under `<the views folder>`).
     - A route reaches the server's objects through the request's locals (`event.locals`), never through a module global.

## Decisions taken in this brief (each reversible, none silent)

1. Rules of the C++ sources that exist only for a VM or an engine are left out: determinism of simulation time and fixed-point simulation quantities, the in-house container names, the four buckets of standard facilities, the measured `std::function` capture size, the heap-per-VM rules, and the member-count limit per subsystem. Their general forms stay: errors as values, allocator awareness as a repository choice, no node-based maps on a hot path, indices or pools for many small values.
2. `-fno-exceptions`, `-fno-rtti`, allocator awareness, two-phase setup and fixed-width aliases are repository choices (`<yes or no>`), since a default page cannot impose them on every C++ repository. RAII is the default construction rule, since it is the standard C++ form; game-engine's two-phase setup is the alternative the choice names.
3. The column limit defaults to `<120>` (cathedra's measured limit) over game-engine's "about 100", since a default is a number a check can hold.
4. The clang-tidy and ruff starting sets are named groups, so a repository has a concrete configuration to start from. `modernize-use-trailing-return-type` is left out, since neither source writes that style. `PTH`, `ANN`, `BLE` and `S602` are in the ruff set so that the rules the page states are enforced by it. The explicit `encoding=` rule is checked by reading, since ruff's rule for it (`PLW1514`) runs only in preview.
5. The Python content, having no written source, is drawn from the tools' own rules as the plan section names them, plus files and processes.
6. The TypeScript rules beyond oculus's config (no `any`, no non-null assertion, floating promises, thrown values, no empty `catch`) are rules `strictTypeChecked` or `@eslint/js` recommended already run; the default-export and import-cycle rules name no tool of the configured sets, so the first is checked by reading and the second by a placeholder the repository fills. Names leave the constant case to the repository, since oculus states no naming rule.
7. oculus's three rules tuned to its own tree (`restrict-template-expressions` with `allowNumber`, `no-confusing-void-expression` with `ignoreArrowShorthand`, and `no-misused-promises` outside Svelte) are left out; `checksVoidReturn: false` moves to the Svelte section, where its reason (async handlers on controls) holds.
