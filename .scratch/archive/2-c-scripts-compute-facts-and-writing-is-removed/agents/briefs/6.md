# Brief: 6, the tests of the kept scripts held to the rule

Read `docs/dev/change-standard.md` first; its rules govern this step unchanged. Then, in full: `docs/dev/skill-layout.md` and `skills/repo-setup/templates/docs/dev/prose-standard.md`.

## What is on the tree (read on main at 42439a3)

- The four test files and their line counts (`wc -l`): `utils/pin.test.sh` 548, `skills/ordo-init/templates/check_config.test.sh` 159, `skills/repo-setup/templates/sync_rules.test.sh` 272, `utils/check_coverage.test.sh` 486. Each prints `PASS: <script> scratch tests` as its last line and exits 0 on main (the verify list, `sh skills/land/templates/checks.sh .scratch/2-c-scripts-compute-facts-and-writing-is-removed/orchestrator-state.md`, `checks: 7 commands passed`).
- The scripts they test and what each is for:
  - `utils/pin.sh`: links the installed Ordo skills to a tag of this repository, in `~/.claude/skills` and the other skill folders, and checks the links. A failure breaks the user's installation or removes a folder that is not Ordo's.
  - `skills/ordo-init/templates/check_config.py`: validates a repository's `.agents/plan.yaml`. A failure accepts a wrong configuration that every plan skill then reads.
  - `skills/repo-setup/templates/sync_rules.py`: compares a repository's shared-rules block in `CLAUDE.md` with the template and, with `--write`, rewrites the block. A failure rewrites or loses the user's text outside the block, or reports a drifted block as equal.
  - `utils/check_coverage.py`: checks that every file of the academic skills is listed once in `docs/academic-coverage.md` with a mark and a reason. A failure accepts a list that misses a file, so the file's content is lost when the academic skills are removed at roadmap entry 16.
- The rule the step applies, in the user's global rules (`~/.claude/rules/scripts-compute-facts.md`): "A test exists only for a script, and only for behaviour whose failure costs something: lost work, a broken installation, a wrong configuration accepted." Step 5 of this plan writes the same rule into `docs/dev/change-standard.md`; this step applies it as stated here.

## What to build

For each of the four test files, read every case and keep it only when the behaviour it proves, failing, would cost one of: lost work (the user's text, files or links destroyed or silently not written), a broken installation (the installed skills linked wrong or not at all), or a wrong configuration or coverage list accepted (a check that passes what it exists to refuse). Remove every other case: a case that proves only the wording of a message beyond what a person needs to act on it, a formatting detail of output nobody acts on, an edge no user reaches that loses nothing, or a duplicate of another case. A kept case keeps its assertions; nothing is loosened.

- A fixture used only by removed cases is removed with them.
- Each test file's head comment is rewritten to list what the file proves after the removals, one paragraph per line.
- No script changes. No case is added.

## Cases

- `sh utils/pin.test.sh 2>&1 | tail -1`, `sh skills/ordo-init/templates/check_config.test.sh 2>&1 | tail -1`, `sh skills/repo-setup/templates/sync_rules.test.sh 2>&1 | tail -1`, `sh utils/check_coverage.test.sh 2>&1 | tail -1`: each prints its `PASS:` line and exits 0, before and after (tests of `pin.sh` run under `env -u CLAUDE_CONFIG_DIR -u ORDO_SKILL_DIRS -u ORDO_STABLE`).
- For each kept case, the revert of the behaviour it guards (named in the report) turns it red; for at least one kept case per file, that revert is run in a scratch copy outside the worktree and its FAIL line quoted.

The builder's first task, before any code changes: run the four tests against the unchanged tree and note each result. No prototype script stands in for the tests.

When a case cannot be sorted under the rule above without a decision the brief does not give (its failure costs something only under an assumption about how the user runs the script), the builder keeps the case, lists it under "Cases kept on an assumption" with the assumption, and goes on.
