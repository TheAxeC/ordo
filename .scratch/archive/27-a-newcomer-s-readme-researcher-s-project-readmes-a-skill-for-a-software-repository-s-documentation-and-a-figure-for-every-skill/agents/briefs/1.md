## What to build

1. Every figure moves by the rule of D5: `docs/figures/<group>/<skill>.svg` for a skill with one figure, `docs/figures/<group>/<skill>/<name>.svg` for a skill with several, and `docs/figures/<group>/<name>.svg` for a figure over several skills, `<group>` being a folder of `skills/`. The moves are the table under "Decisions taken in this brief", item 1, and nothing else moves. The old folders `docs/figures/paper/` and `docs/figures/academic-pipeline/` are gone from disk afterwards.
2. `docs/figures/academic-pipeline/gen_academic_pipeline.py` moves to `docs/figures/academic/researcher/gen_academic_pipeline.py` and writes `academic-pipeline.svg` beside itself there.
3. The layout code of `gen_figures.py` moves to a new file `skills/code/handbook/templates/figures.py`, its surface as "Decisions taken in this brief" items 4 to 7 give it:
   - It holds every part that draws a figure from a graph and no label, no figure, no legend wording and no name of a skill: the constants, the classes, the wrapping, the canvas, the layout, the legend drawing, `compose`, `describe`, the lanes, and the writing and reading back of a file.
   - It imports only the standard library.
   - It names no path of this repository, since `handbook` copies it into other repositories (ADR 0060); `write_figures` takes the root its output lines are written relative to as a parameter.
   - Its head comment says what the module draws, the kinds of box, arrow and loop it draws, how a script uses it (a graph of nodes and edges, then `compose` and the write, and how a script adds a kind of its own), its errors as the current head comment lists them, that it imports only the standard library, and that it needs Python 3.10 or later.
   - The moved code keeps its behaviour and its messages: each definition is the code at ee15921 with only the changes of items 4 to 7 of "Decisions taken in this brief".
4. `docs/figures/gen_figures.py` keeps every figure and imports the engine from `skills/code/handbook/templates/`, found from its own location, with `sys.dont_write_bytecode` set before the import, so no bytecode is written under `skills/` or `docs/figures/`. It holds no class or function of the engine. Its `figures()` names each output by its new path under `docs/figures/`. Its head comment:
   - lists each figure by its new path, in place of "Writes, beside this file:";
   - states the folder rule of D5 in one sentence;
   - says it imports the engine from `skills/code/handbook/templates/figures.py`, in place of the sentence of line 55;
   - lists among its errors the engine not found, an `ImportError` that exits 1.
5. `gen_academic_pipeline.py` imports the engine the same way and nothing from `gen_figures.py`. Its head comment says so in place of lines 3 and 4, gives its new run command in place of line 12, names the engine in place of `gen_figures.py` at line 19, and lists the engine not found among its errors.
6. Each figure the two scripts write is byte for byte the file it was before the move: the split and the moves change no figure's text.
7. The pages follow:
   - each image path in `README.md` lines 72 to 132 names the new path, with the line otherwise unchanged;
   - `docs/dev/building.md` line 41 names each script and each figure at its new path, by path or by its name inside its folder, and says the figures stand in the folders of `skills/`;
   - `docs/dev/scripts.md` gives `gen_figures.py` and `gen_academic_pipeline.py` their new paths and outputs, says each uses the engine `skills/code/handbook/templates/figures.py`, states the folder rule of D5 in one sentence, and lists `skills/code/handbook/templates/figures.py` under "User scripts" as the drawing engine `handbook` copies into a repository and both figure scripts import;
   - ADR 0043 line 106 and ADR 0049 line 18 name the new paths.
