## What to build

When the step is done, `/wizard` writes a script whose stages can also run commands, such as the install of a tool, and no command runs unless the person has seen it and answered yes.

### 1. The library, `skills/code/wizard/templates/template.sh`

1.1 Every function the library defines now stays byte for byte as it is. The comment of the array `SKIPPED` (line 43) is rewritten to cover a command the person declined. The additions stand together in one place, after `set_var` and before `finish`, each with a comment in the style of the comments around it.

1.2 `WIZARD_OS`: a variable set once when the script starts, from `uname -s`. Its value is `macos` for `Darwin`, `linux` for `Linux` (WSL included), `windows` for a name starting `MINGW`, `MSYS` or `CYGWIN`, and `unknown` for anything else or when `uname` is missing or fails. A missing `uname` does not end the script, though the library runs under `set -e`.

1.3 `have TOOL`: succeeds when `command -v TOOL` finds the tool, fails otherwise, and prints nothing. It is written to stand in the condition of an `if`, since a failing bare statement ends a script under `set -e`.

1.4 `run_cmd COMMAND [ARGUMENT ...]`: runs one command.
- Before it asks anything, it prints the command on a line of its own, each word quoted as `printf '%q'` quotes it, so that the line, pasted into a shell, runs the same command and a word with a space or a `;` shows as one word.
- It asks through `confirm` whether to run it.
- On a yes it runs the command with its words as given, never through `eval` or a second shell. The command reads the script's standard input and writes to its standard output and standard error, so an installer that asks a question asks the person.
  - When the command exits 0, it prints one line that says the command ran and returns 0.
  - When the command exits with another status, it prints through `warn` that the command failed, with the status, and ends the script with that status. No later stage runs.
- On anything other than a yes, the end of input included, it does not run the command, adds one entry to `SKIPPED` that names the command so that `finish` lists it under "still to do by hand:", prints through `warn` that the command was skipped, and returns 0.
- It never prints or records more than the command's own words.

1.5 The head comment's block gains what the additions read, print and return: `uname` as an input, the two new warnings with their conditions, and the exit status of a failed command. Its line on "still to do by hand:" (line 17) also names each command the person declined.

1.6 The example stage below the marker stays as it is, and so does every line from `run_wizard() {` to the end.

## Cases

- test, a yes: a stage with `run_cmd touch "<scratch>/made"` and `y` on standard input. The file exists afterwards, the output holds the command's line before the question, and the script exits 0.
- test, a no: the same stage with `n`. The file does not exist, the output holds the command's line before the question, the output of `finish` lists the command under "still to do by hand:", and the script exits 0.
- test, the end of input: the same stage with empty standard input. The file does not exist, the output of `finish` lists the command under "still to do by hand:", and the script exits 0.
- test, a failing command: `run_cmd sh -c 'exit 7'` with `y`, followed by a second stage that would create a file. The script exits 7 and the second stage's file does not exist.
- test, one word stays one word: `run_cmd touch "<scratch>/a b; touch <scratch>/c"` with `y`. One file with that whole name exists, `<scratch>/c` does not, and the printed line holds that argument as one quoted word, with the space and the `;` escaped.
- test, `have`: in a scratch script, `if have sh` takes its branch, `if ! have <a name no tool has>; then run_cmd ...` reaches `run_cmd`, and `have` prints nothing.
- test, `WIZARD_OS`: with a scratch `uname` first on `PATH` that prints `Darwin`, `Linux`, `MINGW64_NT-10.0`, `MSYS_NT-10.0`, `CYGWIN_NT-10.0` and `FreeBSD` in turn, the value is `macos`, `linux`, `windows`, `windows`, `windows` and `unknown`; with a `PATH` that holds no `uname`, the value is `unknown` and the script goes on to its stage.
- run: `bash -n skills/code/wizard/templates/template.sh` exits 0 and prints nothing.
- run: the functions of the library before the step are unchanged: for each of them, the lines from its name to its closing `}` on the base (`git show 4d63a7f:skills/code/wizard/templates/template.sh`) equal the lines in the worktree.
- run: the lines of the template from `run_wizard() {` to the end equal the base's.
- read: the head comment against the additions: each input they read, each warning they print with its condition, and the exit status of a failed command.
- read: `SKILL.md` against 3.1 to 3.10, each item present once, and the two sentences of 3.10 word for word.

## Decisions taken in this brief (each reversible, none silent)

1. The names `have`, `run_cmd` and `WIZARD_OS`. The last is not `OS`, which Windows sets in the environment and build files read.
2. A command the person declines is recorded and the script goes on; it does not end the script. The person may have the tool already or want to install it another way.
3. A command is given to `run_cmd` as separate words and run without a shell. A stage that needs a pipe writes `run_cmd bash -c '<the pipeline>'`, and the person sees that whole line.
4. WSL counts as `linux`, since its commands are Linux's.
5. The test is kept because a `run_cmd` that runs a command without a yes, goes on after a failed install, or splits a word into a second command changes a person's machine in a way the person did not choose. The cases of `have` and `WIZARD_OS` are kept because a wrong answer runs an install that was not needed or the command of another system.
6. `metadata.version` stays `1.0.0`: the plan that adds the skill raises its version once, at its creation.
7. `finish` is not changed, so its summary counts no commands that ran.
