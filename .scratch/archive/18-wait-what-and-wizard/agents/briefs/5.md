## What to build

A run of the skill on a real setup showed seven places where the skill left the agent to guess, or where the library was short. When the step is done, each is settled in the skill's text or in the library.

### 1. The library, `skills/code/wizard/templates/template.sh`

1.1 Every function stays byte for byte as it is, except line 134 (1.2) and the text of lines 64 to 66 (1.3). The comment of `SKIPPED` on line 49 names the third kind of entry, what `by_hand` records. The two additions stand together after `run_cmd` and before `finish`, each with a comment in the style of the comments around it.

1.2 `ask`, line 134: the expansion in front of `[Enter keeps current]` is braced, so that `shellcheck` reads no array there. What the line prints does not change.

1.3 `banner`, lines 64 to 66: the text no longer says the person drives the browser and the wizard captures values only. It says in the same two or three printed lines that the wizard tells the person what to do, runs each command only after the person has confirmed it, and keeps the values the person copies back; the sentence on Ctrl-C and a second run stays.

1.4 `version_at_least CURRENT MINIMUM`: succeeds when the version `CURRENT` is the version `MINIMUM` or a later one, and fails otherwise. Both are dotted numbers such as `3.28` or `4.0.1`; a missing part counts as 0, so `3.28` equals `3.28.0`; parts compare as numbers, so `3.9` is before `3.28`. A part with leading zeros is read in base 10, so `09` is 9 and `010` is 10, and bash 3.2 prints no "value too great for base" error. An argument that is empty or absent, or that holds a part that is empty (`3..28`, `3.`, `.5`) or is not a number (`3.x`, `v3.28`, `3.28-rc1`), fails; a call with one argument or none fails the same way and does not end the script under `set -u`. It prints nothing on standard output or standard error and uses bash alone, with no `sort -V`. It is written to stand in the condition of an `if`.

1.5 `by_hand TEXT`: records `TEXT` in `SKIPPED`, so that `finish` lists it under "still to do by hand:", prints `left to do by hand: TEXT` through `warn`, and returns 0. A call with no text or an empty text prints a warning that names `by_hand` and ends the script with status 2, as `run_cmd` does on a call with no command. `run_cmd` stays as it is and does not call it.

1.6 One `shellcheck` directive at the top of the file, with its reason in the comment, silences SC2329 for the whole file: the library defines helpers that a given script's stages may not call. After 1.2 and this directive, `shellcheck skills/code/wizard/templates/template.sh` prints nothing and exits 0.

1.7 The head comment's block of inputs, warnings and exit status names what 1.4 and 1.5 read and print.

1.8 The example stage gains one line, a `pause` as its last call before `finish`, so that the one model of a stage in the file follows 3.1. Every other line from `run_wizard() {` to the end stays as it is.

### 3. The skill, `skills/code/wizard/SKILL.md`

Each rule is written once, in the section where it applies, one requirement per bullet, each Steps item ending on its completion criterion.

3.1 Steps 5: a stage ends on `pause`, since the next `stage` clears the screen and what the stage printed, a command's output included, is gone.

3.2 Steps 5: a stage whose command needs a tool that an earlier stage installs checks for that tool with `have` first. When it is missing, the stage calls `by_hand` with what is left and the stage to run first, runs none of its commands and reads none of its values; the text given to `by_hand` names each value left unread.

3.3 Steps 5: a command that needs a shell (a pipe, a redirection, `$(...)`, a variable the command itself must expand) is written as `run_cmd bash -c '<the line>'` with the line in single quotes, so that bash expands nothing before the command is shown. `run_cmd` prints each word quoted for the shell, so the line appears with a backslash in front of each space and each shell character; the stage therefore prints the plain line with `say` right above the `run_cmd`.

3.4 Steps 5: line 63 is rewritten, with no second bullet beside it: the check of a stage skips its commands and their instructions only. A value the stage reads is asked for and written whether or not the commands were skipped.

3.5 Steps 1 and Steps 5: where a tool must be at least a given version, the check of the stage compares the installed version with `version_at_least`. The stage calls `have` first and reads the version only when the tool is there, since reading the version of a missing tool ends the script. It cuts the tool's output down to the dotted number before the call, since any other text fails the comparison. Reading a version is part of the check: it reads and changes nothing, is no command of the stage and does not go through `run_cmd`; the bullet of Steps 1 that lists the allowed checks names it. In Steps 1 the minimum is part of the command's note on its check, so each command keeps its three notes.

3.6 Steps 6: `shellcheck <script>`, when it is installed, prints nothing; a finding is fixed in the stages, since the library gives none. The item's "Done when" names it.

3.7 Steps 5's list of helpers names `version_at_least` and `by_hand`, and "The template" names them among what the library does.

## Decisions taken in this brief (each reversible, none silent)

1. The names `version_at_least` and `by_hand`.
2. A minimum version is compared by a helper that takes the installed version as text. The stage reads that text from the tool itself, since each tool prints its version differently.
3. A stage that lacks a tool from a declined stage records what is left and goes on. It does not end the script, as a declined command does not.
4. SC2329 is silenced for the whole file by one directive. The other route, calling every helper in the example stage, would put calls with no purpose into every script.
5. The tests of the two helpers are kept because a wrong comparison installs over a new enough tool or leaves an old one in place, and a `by_hand` that drops its text reports a setup as complete with a step undone.
6. `metadata.version` stays `1.0.0`, raised once by this plan at the skill's creation.
7. A version read stands in the check of a stage and outside `run_cmd`: ADR 0046's "No command runs without being shown and confirmed" is about the commands a stage runs, and Steps 5 already says the check "is not a command of the stage".
8. A shell line is printed plain with `say` above its `run_cmd`, so that the person reads the line without the backslashes `run_cmd` prints.
9. The example stage gains a `pause`, so that the template's one example follows the skill's rule.
10. A stage whose tool is missing reads no value, since a value that depends on the install is not known yet.
11. `by_hand` with no text ends the script with status 2, as `run_cmd` with no command does.
