# Brief: 2, the layout check for SKILL.md files and its test

Read `docs/dev/change-standard.md` first; its rules govern this step unchanged. Then, in full: `docs/dev/skill-layout.md`.

## What is on the tree (read on main at 971121b)

- `utils/` holds `pin.sh` and `pin.test.sh` only (`ls utils`); `utils/check_skill_layout.py` does not exist.
- `docs/dev/skill-layout.md` states the frontmatter (lines 5 to 18), the section order as a table (lines 20 to 34) and the table columns for Use instead, Stops and Anti-patterns (`grep -n '^## \|^| ' docs/dev/skill-layout.md`).
- Every `skills/*/SKILL.md` opens with frontmatter holding `name:`, `description:` and `version:` (a count of 3 per file). None follows the new section order yet; steps 4 to 13 restyle them, and step 14 adds this check to `docs/dev/building.md`.
- PyYAML 6.0.3 is installed (`python3 -c "import yaml; print(yaml.__version__)"`).

## What to build

1. `utils/check_skill_layout.py`: checks one or more `SKILL.md` files, or every `skills/*/SKILL.md` when given no argument, against `docs/dev/skill-layout.md`. Prints one line per error as `<path>:<line>: <what is wrong>`, and `ok: <path>` for a file with none. Exits 1 when any file has an error, 0 otherwise. ASCII only.
2. `utils/check_skill_layout.test.sh`: builds fixtures in a scratch folder and runs the check on each; prints `PASS: check_skill_layout.py scratch tests` or a `FAIL:` line and exits 1.

## What it must do

The check, per file:

1. Frontmatter between the first two `---` lines parses as YAML; `name` equals the folder's name; `description` is a non-empty string containing `Triggers on:`; `metadata.version` is a string of the form `<n>.<n>.<n>`.
2. After the frontmatter, the first non-blank line is a `# ` title, followed by at least one paragraph line before the first `## ` heading.
3. The `## ` headings, outside fenced code blocks, are in this order: `Quick start`, `Use instead`, `What it reads`, `Steps`, then any number of reference sections, then `Stops`, `Anti-patterns`, `Rules`, and nothing after `Rules`. A required heading missing, a required heading out of order, or any other heading before `Steps` or after `Stops` is an error naming the heading.
4. `Quick start` holds a fenced code block. `What it reads` holds a numbered list. `Steps` holds a numbered list, directly or under its `### ` subsections. `Rules` holds a bulleted list.
5. The first table row in `Use instead` is `| When | Use |`; in `Stops`, `| Stop | When | What it shows | What resumes it |`; in `Anti-patterns`, `| Anti-pattern | Why it fails | Do instead |`. Cell text is compared with surrounding spaces stripped.
6. Bold (`**`) appears only as a list item's label, at the start of a bullet or numbered item; bold anywhere else, tables included, is an error. Text inside code spans and fenced code blocks is not checked.
7. A heading holding a version tag (`v` followed by digits and a dot) is an error.

## Decisions taken in this brief (each reversible, none silent)

1. The check is Python, like the other scripts that parse files (`check_config.py`, `collect_findings.py`), and reads the headings and tables line by line rather than through a Markdown library, so it needs nothing beyond PyYAML.
2. The test is a POSIX `sh` script beside the check, the form every other test in the repository has.

## Conventions

- ASCII only; no history in comments; a docstring that states the usage and what is checked.
- The test builds each fixture from one complete, passing `SKILL.md` and changes one thing per case.

## Verify before you report

Run from the worktree's root:

1. `sh utils/check_skill_layout.test.sh 2>&1 | tail -1` prints `PASS: check_skill_layout.py scratch tests`.
2. The test has one case per rule 1 to 7 above, each asserting the error line, plus the complete fixture passing; each case names the change to the check that turns it red, and at least two of those reverts are run with their red output quoted in the report.
3. `python3 utils/check_skill_layout.py` on the current skills exits 1 and names errors in all ten (they are not restyled yet); the report quotes the error count per file.
4. Every command of the configuration block's `verify` list passes.
