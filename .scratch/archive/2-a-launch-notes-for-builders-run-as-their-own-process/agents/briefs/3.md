## What to build

1. "Launching a builder": the two `nohup sh -c` blocks are replaced by one `launch.sh` call each, with the options the script takes (`--cwd`, `--model`, `--prompt`, `--report`, `--stderr`, `--exit`, `--pid`; `--events` and `--effort` for codex; `--network` when the verification commands bind a port; `--note <launch_note> --id <file> --label <step> --parent <session id>` when the configuration block's `launch_note` is set). The script is named as this skill's `templates/launch.sh`, run from the orchestrator's shell. The codex bullets that describe what the script now does stay true of it.
2. The same section gets a numbered list for a shell launch, in order: the launch through `launch.sh`; the builder's identity written into the dispatch block and committed; the transcript call, `launch.sh transcript --note <launch_note> --id <id file> <path>`, once the path is known (for a `claude -p` builder, the `.jsonl` the builder writes under the runner's projects folder for the worktree's directory; for a Codex builder, the rollout under `~/.codex/sessions/` whose name ends with the `thread_id` of the event log's `thread.started` event); a monitor on the exit file. With `launch_note` empty, the note options are left out and the transcript call is skipped.
3. The native Agent-tool recipe stays the first bullet and the default for a Claude builder under Claude Code, its text unchanged.
4. `--parent` is the orchestrating session's id: the file name of its session log without `.jsonl` under Claude Code, the rollout's session id under Codex (the Usage section says where each is).
5. `launch.sh` gains `--resume <session id>` for the `claude` and `codex` modes: the claude builder runs `claude -p --resume <id>` with the recipe's other flags; the codex builder runs, in `--cwd`, `codex exec resume <id>` with `-c sandbox_mode="workspace-write"`, the network setting when given, the effort, `-m`, `-o` and `--json -`. The transcript mode refuses `--resume`. With a note set, a resumed run makes a record of its own (start, the builder, end) under the same `--label`.
6. Steps, item 8, "How.": a `claude -p` or Codex worker is resumed through `launch.sh` with `--resume <session_id>` and the options of its launch, and the resumed run takes the numbered list of item 2 from the identity on.
7. `launch.test.sh`: cases for a claude resume and a codex resume (with and without the network setting) showing the exact arguments and the working directory, a resumed run with a note (start, builder, end), and `--resume` refused in transcript mode (exit 64). The header comment names the new cases.
8. `launch-note.md`: says that a repair round's resume is launched through `launch.sh` too and is a record of its own under the step's label.

## Decisions taken in this brief

- The codex resume's sandbox is set by `-c sandbox_mode="workspace-write"` in the working directory, since `codex exec resume` takes no `-s` or `-C`.
