## What to build

1. **`agents/reviews/closure.md`**, in the worktree's copy of the ledger. It opens with one sentence that names the six reports and states the row count, followed by one Markdown table with one row per finding, in report order and then in the report's own order. The columns are:
   - **id**: `<report>-<n>` for reports 1, 4 and 5 (`1-12`, `4-3`); `<report>-<heading>-<n>` for reports 2 and 3, with the heading as the skill or tool name (`2-land-4`, `3-pin.sh-3`); `6-F<n>` for report 6; and `1-V1` to `1-V5`, `1-P1`, `1-P2`, `1-H1` and `3-H1` for the unnumbered findings, in the order listed above.
   - **where**: the report file and the line of the finding's first line (`3-checkers.md:85`).
   - **finding**: the finding's bold title, or its first clause when it has none, verbatim, cut to at most 15 words with `...`.
   - **disposition**, in one of these forms:
     - `closed <hash> (step <n>)`: a landing commit of this plan made the change the finding asks for, or a change that ends the defect another way. More than one commit are listed in order.
     - `closed <hash> (step <n>), removed <hash> (step <n>, ruling <name>)`: fixed, and later removed with the thing it was in.
     - `removed <hash> (step <n>, ruling <name>)`: the defect's file or feature was removed from the tree by a ruling's step before or without a fix.
     - `ruled: <ruling name>`: a ruling of the user decides the finding: it accepts it, declines it, or says it stays with the user. The ruling is named as the tag of a step line names it (`U`, `CC`, `The plan cut to its goal`), and the name of the first ruling line is `the audit's recommendations 2a to 2h`.
     - `no defect reported`: the item reports no defect.
     - `outside Ordo`: the finding is about a file outside this repository (the research hub's configuration or ledger). The evidence cell names the ruling or the plan text that places it there. If there is none, the row is `open`.
     - `open`: no commit closes it and no ruling decides it.
   - **evidence**: what shows the disposition holds. For a closure, the file and line on main at the base that now carries the fix (`skills/land/SKILL.md:36`), or the commit message bullet that names it, quoted. For a removal, the command that shows the file is gone (`ls utils` has no `check_skill_layout.py`). For a ruling, the `plan.md` line of the ruling. For `no defect reported`, the report's words that say so, quoted. For `open`, what is missing.
2. **A finding is closed only by evidence the builder checked on the tree.** It is never closed from a step's title alone. For each closure, the builder reads the fix on the tree at the base, or the commit's diff (`git show <hash> -- <path>`), and confirms it does what the finding's "Fix" line asks for or ends the defect. A finding whose fix a later step removed or changed is closed by the later commit, and the row says so.
3. **Every `open` row** is listed again in the report's first line, with its id. The builder takes no ruling and writes no fix: an open finding is for the orchestrator to raise to the user.
4. **The report** gives the counts by report and by disposition, and every judgment call, as "Report" says.
