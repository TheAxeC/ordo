## What to build

1. A new script `tests/guide.test.sh`, a POSIX `sh` script run as `sh tests/guide.test.sh [<file>]` from the repository root.
   - Input: one optional argument, the path of the file to check; with none it checks `docs/guide.md`.
   - It prints `PASS: <file>` and exits 0 when the file's first line starts with `# ` and no line of the file holds a tab character.
   - Otherwise it prints one line `FAIL: <file>: <reason>` and exits 1.
   - Its whole output is that one line, on standard output; no command it runs prints to the terminal, so a missing file shows no message of `head`, `grep` or the shell before the `FAIL:` line.
   - Every line of the file is checked for a tab: the first, a later one, a line that starts with a tab, and a last line with no newline after it.
   - `<file>` is the path as given, or `docs/guide.md` when none is given.
   - The path is quoted wherever it reaches a command, so a path holding a space is checked as one file.
   - The path is printed as given, byte for byte: it is never a format string, never read for backslash escapes, and a path starting with `-` is never read as an option of the command it reaches.
   - An empty argument is a given path that is not a readable file (Decision 3).
   - A path that is not a readable file prints `FAIL: <file>: <reason>` and exits 1; it never prints `PASS`.
   - Its head comment says what the script checks, its input, each line it prints and each exit status, as the rules file's rule 14 asks; no history in it.
   - ASCII only, no tab in the script itself.
2. `docs/dev/building.md`: the line `sh tests/guide.test.sh 2>&1 | tail -1` is added to the `sh` command block, after the character-set check, as its own line. The page's paragraph stays true: every command of the block passes from the repository root.
