## What to build

When the part is done, `tests/guide.test.sh` checks the form of a guide file and `docs/dev/building.md` runs it, so the verify list at landing holds it.

1. `tests/guide.test.sh`, a new POSIX `sh` script, run as `sh tests/guide.test.sh [file]` from the repository root.
   - Its one input is an optional file path; with no argument it checks `docs/guide.md`.
   - It prints `PASS: <file>` on stdout and exits 0 when the file's first line starts with `# ` (a hash and a space) and no line of the file holds a tab character.
   - Otherwise it prints one line `FAIL: <file>: <reason>` and exits 1. The reasons are: `no such file` when the path is not a readable regular file; `the first line is not a title` when line 1 does not start with `# `, an empty file included; `line <n> holds a tab` for the first line that holds a tab, `<n>` its line number.
   - When both rules fail, the title rule is reported.
   - `<file>` is printed as given on the command line, or `docs/guide.md` when none was given.
   - The path is always quoted where it reaches a command, so a path with a space is read as one path.
   - A head comment, in plain prose under the prose standard, states what the script checks, its input, each line it prints and each exit status (0 for PASS, 1 for FAIL).
   - The path reaches `head` and `grep` after `--`, so a path that starts with a dash is read as a path.
   - The path is printed with `printf '%s'`, never as a format string and never through `echo`, so a path holding `%` or a backslash is printed as given.
   - A file whose last line has no newline is read whole, that line included.
   - Arguments after the first are not read.
   - The `PASS:` and the `FAIL:` line both go to stdout.
   - ASCII only, and no literal tab character anywhere in the script, since the verify list's character-set check rejects a tab in a file that is not Markdown: the tab the script looks for is made with `printf '\t'`, and the script is indented with spaces.
   - No dependency beyond the POSIX tools `head`, `grep` and `printf`.
2. `docs/dev/building.md`, the command block: one line `sh tests/guide.test.sh 2>&1 | tail -1` added after line 6, inside the fence, so it becomes line 7, the closing fence line 8, and `grep -c -F 'sh tests/guide.test.sh 2>&1 | tail -1' docs/dev/building.md` prints 1. No other line of the page changes; its line 3, `The green check is every command below passing, each run from the repository root.`, stays true and is reread after the change.

## Cases

Each case is a run from the worktree root that the report quotes with its output and its exit status. The rules file calls for no separate test of this script: the script is itself the check, and its cases are quoted runs.

- `sh tests/guide.test.sh` prints `PASS: docs/guide.md` and exits 0.
- `sh tests/guide.test.sh docs/guide.md` prints `PASS: docs/guide.md` and exits 0.
- A file whose first line is not a title, made in a temporary folder outside the worktree as `printf 'Guide\n\ntext\n'`: prints `FAIL: <path>: the first line is not a title` and exits 1.
- A file with a title line and a tab, `printf '# Guide\n\ntext\twith a tab\n'`: prints `FAIL: <path>: line 3 holds a tab` and exits 1.
- An empty file: prints `FAIL: <path>: the first line is not a title` and exits 1.
- A path that does not exist: prints `FAIL: <path>: no such file` and exits 1, and never `PASS`.
- A path with a space, a copy of `docs/guide.md` at `<tmp>/a guide.md`: prints `PASS: <tmp>/a guide.md` and exits 0.
- A first line `#Guide` with no space: prints `FAIL: <path>: the first line is not a title` and exits 1.
- A first line `#<tab>Guide`, `printf '#\tGuide\n'`: prints `FAIL: <path>: the first line is not a title` and exits 1.
- A tab on line 1 after a title, `printf '# Guide\ttitle\n'`: prints `FAIL: <path>: line 1 holds a tab` and exits 1.
- A tab on line 2, `printf '# Guide\n\tx\n'`: prints `FAIL: <path>: line 2 holds a tab` and exits 1.
- Both rules failing, `printf 'Guide\n\ntext\twith a tab\n'`: prints `FAIL: <path>: the first line is not a title` and exits 1.
- A last line with no newline that holds a tab, `printf '# Guide\n\ttext'`: prints `FAIL: <path>: line 2 holds a tab` and exits 1.
- A one-line file with no newline, `printf '# Guide'`: prints `PASS: <path>` and exits 0.
- A path that is a directory, such as `docs`: prints `FAIL: docs: no such file` and exits 1.
- A path that starts with a dash, a copy of `docs/guide.md` named `-x` in a temporary folder and given as `-x` from that folder (with the script given by its absolute path): prints `PASS: -x` and exits 0.
- A path holding `%` and a backslash, a copy of `docs/guide.md` at `<tmp>/100%s\n.md`: prints `PASS: ` followed by that path exactly as given, and exits 0.
- On the unchanged tree, `sh tests/guide.test.sh` fails because the script does not exist; the report quotes that run.
- `grep -c -F 'sh tests/guide.test.sh 2>&1 | tail -1' docs/dev/building.md` prints `0` on the unchanged tree and `1` after the change; after the change `sed -n 7p docs/dev/building.md` prints the command, `sed -n 8p` prints the closing fence ```` ``` ````, and `wc -l < docs/dev/building.md` prints `8`.
- `sh tests/guide.test.sh 2>&1 | tail -1` run from the root, as the verify list runs it through `bash -o pipefail -c`, prints `PASS: docs/guide.md` and exits 0.

5. `docs/dev/change-standard.md` is not changed: its block shows the form of a filtered command, not the list of the verify commands.
6. Both result lines go to stdout, and the verify command's `2>&1` keeps any error of the shell in the filtered output as well.
7. Arguments after the first are not read, since the script takes one optional path and no caller passes more.
