### The script `skills/literature/templates/lookup.py`

9. Python 3, the standard library only, a head comment that lists every input it reads, every error it prints and every exit status it returns (rule 14). It computes only what D11, D27 and open item D state; nothing else is added (rule 11). Its commands:
   - `resolve <DOI | arXiv ID | title> [--year <year>]`: queries the four indexes; for each, one record (title, authors, year, venue, DOI, arXiv ID, OpenAlex ID, Semantic Scholar ID, open-access URLs) with its title ratio, or one line saying why the index is left out, or "not found".
     - The title similarity is `difflib.SequenceMatcher(None, a, b).ratio()` on both titles lowercased, every character other than a letter, a digit or a space removed, and runs of spaces made one. A candidate matches at 0.70 or more. Of several matching candidates, the one whose year equals `--year` is taken, otherwise the one with the highest ratio.
     - For a DOI or arXiv ID, the first record found, in the order Crossref, OpenAlex, Semantic Scholar, arXiv, is the reference, and each other index's title is compared with it; a record below 0.70 is printed with `DOI_MISMATCH`.
     - A DOI given as `https://doi.org/...`, `http://dx.doi.org/...` or `doi:...` is stripped to the DOI. A DOI `10.48550/arXiv.<id>` is also read as the arXiv ID `<id>`. An old-style arXiv ID (`math/0601001`, `hep-th/9901001v2`) is read as an arXiv ID. A DOI or a title reaching a URL is percent-encoded (`#` as `%23`) (rule 15).
     - An index's 404, or a 200 with no result, prints "not found" for that index. A 400, a 401, a 403, a body that does not parse, or any other failure leaves the index out with its status. Crossref's year is read from `issued`.
   - `search <query> [--limit <n>]`: each index's search, `--limit` 20 per index by default; records merged only when they share an identical DOI (compared lowercased), arXiv ID (without its version suffix) or Semantic Scholar ID; a merged record keeps the fields of the record with more fields filled, the other filling its empty fields (row 185).
   - `refs <id>` and `cited-by <id>`: from Semantic Scholar and OpenAlex, merged as `search` merges.
   - `bibtex <DOI | arXiv ID>`: for a DOI, the body `https://doi.org/<doi>` returns with `Accept: application/x-bibtex`, or the status and exit 1 when the body is not a BibTeX entry; for an arXiv ID, an `@misc` entry built from the arXiv record with `eprint` and `archivePrefix = {arXiv}`, each run of whitespace in its title and authors made one space.
   - `check-urls <report>`: reads the `references.bib` in the report's folder; for each key the report cites, its `doi` (as `https://doi.org/<doi>`), `eprint` (as `https://arxiv.org/abs/<id>`) or `url`, printed with its HTTP status after redirects; a cited key with none of the three printed as "no identifier", and a cited key absent from `references.bib` printed as such; exits 1 when any URL does not end in a 2xx status or any key is printed as having no identifier or no entry.
   - `fetch <id> <folder> <key>`: tries, in order, the arXiv HTML and PDF, OpenAlex's `open_access.oa_url`, and Semantic Scholar's `openAccessPdf.url`. From OpenAlex and Semantic Scholar only a body starting `%PDF-` counts; HTML counts only from `arxiv.org/html`. It writes the first that counts as `<folder>/<key>.pdf` or `<folder>/<key>.html`, and its text as `<folder>/<key>.txt`, by `pdftotext <pdf> <txt>`, run with its arguments as a list and never through a shell, for a PDF, or with the HTML tags removed by `html.parser`; a PDF whose text is empty or only whitespace counts as no text, and the next URL is tried. Each `/` and `:` of the key is written `_` in the file names, which never leave `<folder>`. When no full text is found, it writes the abstract the indexes return (arXiv `summary`, Semantic Scholar `abstract`, or OpenAlex `abstract_inverted_index` put back in word order) as `<folder>/<key>.abstract.txt`. It prints each URL tried with its status, and exits 1 when no full text was found.
   - `quote-check <report> <folder>`: reads the `references.bib` in the report's folder and the report. For each line `> [@<key>, <locator>]: "<passage>"`, the passage is the text between the first `"` after `]: ` and the last `"` of the line; it reads `<folder>/<key>.txt`, or `<folder>/<key>.abstract.txt` for the locator `abstract`, and prints found or not found after both texts are normalised: every hyphen at a line end removed with its line break, every hyphen between two letters removed, then each run of whitespace made one space.
