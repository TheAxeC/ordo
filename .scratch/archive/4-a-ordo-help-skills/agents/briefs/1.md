## What to build

When the part is done, `/ordo-help skills` prints, for every folder of the skills folder that holds `ordo-help` itself and that holds a `SKILL.md`, a line `/<name>` followed by that skill's Quick start code block exactly as its `SKILL.md` has it, the skills in folder-name order (ruling D1), and prints nothing else: no sequence, no choices awaiting review, no position (ruling D2). The two modes `/ordo-help` and `/ordo-help <entry>` behave exactly as before. The skill's text calls each invocation a mode, the word `docs/dev/skill-layout.md` uses, and uses no other word for it.

1. **Frontmatter.** `description` says the skill also prints, for `skills`, every skill's name and Quick start block, and `Triggers on:` gains phrases for that case, such as `ordo-help skills`, `which skills are there`, `list every skill and its modes`, `what modes does a skill have`. It stays one paragraph, names no neighbouring skill, and stays at most 1,024 characters by the layout's command. `metadata.version` goes from `3.1.0` to `3.2.0`: the skill accepts an input it did not accept, and every run that worked before still works (`docs/dev/skill-layout.md`, "Frontmatter").
2. **Title paragraph.** It says what the skill does in all three modes, in one to three sentences.

## Decisions taken in this brief (each reversible, none silent)

1. The `skills` mode reads no `.agents/plan.yaml` and no ledger: what it prints comes from the skills folder alone, so it works in any repository, the way a list of a tool's commands does.
2. A Quick start block is printed with its two fence lines, as the file has it, so the printed block is the file's block byte for byte and step 2's `diff` compares the same lines.
3. A `SKILL.md` with no Quick start code block prints `no Quick start block` under its name line, so a skill is never silently missing from the count.
4. The pipeline figure's `/ordo-help` box and the README row are part of this step: both describe what `ordo-help` prints, and a mode left out of them would make them wrong.
5. Every folder with a `SKILL.md` in the skills folder is printed, an Ordo skill or not, as the goal's folder rule says ("every skill in the `skills/` folder that holds `ordo-help` itself"); under the skills CLI and copy installs that folder can hold other skills, which are then printed too.
6. The existing Steps list moves under `### The sequence and the plans`, so each mode has its subsection, and the three places that name its steps by number are rewritten to the subsection form.
