## What to build

The executor is the orchestrating session itself (`inline`): only a session that loads the installed skill through the Skill tool can make the gate's run. It works in the step's worktree, except for `utils/pin.sh`, which runs from the main checkout's root as its own path requires. When the part is done, the run's record and its report stand in the worktree's ledger copy, from which the session saves them into the main ledger as a builder's report is saved, and the gate's facts are shown by commands:

1. **The tag.** A lightweight tag `v8.3.0-rc.2` on a6c643f, the landing commit of step 1 (decision 1).
2. **The pin.** `utils/pin.sh v8.3.0-rc.2` run from the main checkout's root, its output quoted. It prints `pinned: v8.3.0-rc.2` with the commit and the same three skill folders and three agent folders as now, and no `pin: replaced` or `pin: removed` line. Then `utils/pin.sh` with no argument exits 0, and `git -C ~/.local/share/ordo-stable rev-parse HEAD` prints the commit `git rev-parse 'v8.3.0-rc.2^{commit}'` prints. A pin that exits non-zero stops the step: no Skill run, its `pin: ` lines quoted in an open item (decision 4).
3. **The run.** First, from the worktree, `git diff --quiet v8.3.0-rc.2 HEAD -- skills; echo $?` prints `0`. Then `/ordo-help skills` is invoked once through the Skill tool. The text it loads must hold `### skills`; a text without it stops the step before `2-run.txt` is written (decision 4). The session then does the skill's steps with its own tool calls and prints the output as its message.
4. **The record.** `agents/reviews/2-run.txt` is taken from the transcript by a typed `jq` command: the text of the session's assistant message that prints the output, written byte for byte. The report names the transcript file, that message's `uuid`, and the command. It also quotes, from the transcript, the run's own tool calls after the Skill call: the `pwd -P` of the base directory and its result, the listing of the resolved parent, and the 15 `SKILL.md` paths read, all under `/Users/axelfaes/.local/share/ordo-stable/skills/` (decision 2).
5. **The count.** A name line is a line matching `^/[a-z][a-z-]*$` outside a fenced block. `2-run.txt` holds as many name lines as `ls skills/*/SKILL.md | wc -l` prints, and the name lines in order equal `LC_ALL=C ls -1 skills/` with a `/` before each.
6. **The diffs.** For each skill, the block under its name line in `2-run.txt`, from its opening fence to its closing fence, is cut out with `awk` into a file in the session's scratch folder, and the Quick start block of `skills/<name>/SKILL.md` in the worktree is cut out the same way; `diff` of the two prints nothing, for each of the 15.
7. **Nothing else.** A fence-aware `awk` over `2-run.txt` prints every line outside a fenced block that is not a name line, a `no Quick start block` line or the one blank line between a closing fence and the next name line, and every blank line at the start or the end; it prints nothing. This is the print rule of `skills/ordo-help/SKILL.md`, "Steps / skills" 3 and its Rules bullet on the `skills` mode, and ruling D2.
8. **The report.** `agents/reviews/2-report.md` in the brief's report shape, quoting every command above with its output.
