## Conventions

- ASCII only in `.py` and `.sh`; `.md` files to the verify list's character set (ASCII plus the check mark).
- No history in any page, comment or status line beyond the status form of Decisions item 1: no step numbers, dates or "before this change".
- The new strategist page is one page; it is not split.

## Verify before you report

Run from the worktree's root, each must hold, each output piped through the filter the rules file names:

1. The checks of the verify list that cover the files the step changes:
   - `sh skills/paper/templates/lookup.test.sh 2>&1 | tail -1` prints a line starting `PASS:`.
   - `python3 skills/repo-setup/templates/sync_rules.py . --only glossary` exits 0.
   - The character-set check over the changed files: `printf '%s\0' <the files the step changes> | xargs -0 perl -CSD -ne 'my $bad_char = $ARGV =~ /\.md\z/ ? qr/[^\x20-\x7E\x{2705}\n]/ : qr/[^\x20-\x7E\n]/; if (/$bad_char/) { print "$ARGV:$.: $_"; $bad = 1 } close ARGV if eof; END { $? ||= 1 if $bad }'` prints nothing and exits 0.
   - The report quotes the lines they print.
   - The plan's whole verify list runs once, at landing on main.
2. The greps of cases T5, T6 and T10 give what each case expects.
3. `python3 docs/figures/gen_figures.py` and `python3 docs/figures/academic-paper-comparison/gen_comparison.py` exit 0, and `git status --short docs/figures` lists only SVGs the scripts wrote.
4. Each new or changed test is run once on the unchanged tree, before the code is changed, and again after the change.
   - A test of a behaviour the change adds or changes fails on the unchanged tree, that run is its proof, and the report quotes the failure.
     - An edit to the test after that run is checked by reading it, with no further run on the unchanged tree.
   - A test of a behaviour the change preserves passes on the unchanged tree where it can run there, and passes after the change, and the report quotes those runs.
   - A test that would still pass with the behaviour it is written for taken out of the code is an audit, not a proof, and this brief says which it is.
   - The reviewer finds such a test by reading it.
   - A case checked by a quoted run is no test and is not judged as one.
5. Each new or changed list item and sentence is read against the standards pages' rules on list items and sentence length, and each place it departs from them is named in the report with why it needs its form.

## Report

Write it to `.scratch/5-paper/agents/reviews/5.K-report.md`, in the rules file's character set, a character outside it in quoted output written by its name in angle brackets, such as `<tab>` or `<em dash>`, with these parts in this order.

- The first line: anything NOT done, or "Everything in the brief is done".
- The open items of the state file, verbatim, which hold only what the user must rule on.
- The cases' first run: every case of "Cases" by its name, none left out, each with the command or the reading that checked it and its output as printed, and each case the brief's rules got wrong with the rule, the result and the orchestrator's ruling.
- The DONE / NOT DONE table with the checks above and their output as printed, the character-set check's line and its exit status included, over the files the step changes.
  - A line shortened with "..." is not verbatim.
- The section map of T1, and each adaptation of item 1 with its academic-paper line.
- The terms: each term of `docs/glossary.md` the diff adds, changes, removes or uses in a new place, each use read against the entry, and each changed entry's "Stated in" checked by `grep -n` of the term in the section it names.
- The files with line counts.
- Every judgment call the brief left open.
- Every host- or user-visible change with its before and after.
- Anything in the brief that was wrong or impossible, with the evidence.
