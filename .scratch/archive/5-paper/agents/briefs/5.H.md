## What to build

1. **The parts of the research question fix the run's shape** (ruling BS item 1).
   - In full, outline-only and lit-review mode, at intake, the session splits the research question into its parts, each a sub-question in one sentence, numbers them once as P1 to Pn, and for each part sets a short closed list of the answers a source can give on it, ending with "other" (as AP's sessions did: "one of: assumes aligned mode / registration to common space / ... / other"). They go in a new intake row "Parts of the research question", which the session fills from the question and does not ask, shown at the stop "The intake confirmation", where the user may correct them, and written in `config.md`. A question that asks one thing has one part. Revision mode keeps its items in place of the parts, as now.
   - Every start of the strategist is given the parts as recorded and uses them as they stand: it never renumbers, merges, splits or adds a part. A theme run states which recorded parts its search theme covers, by their numbers.
   - Each part becomes, in every file the strategist writes:
     - a field of every annotation, `- **P<n>**: <a value of the part's list>. <one sentence on what the source says or does on that part>`, one field per recorded part, in their order; "not addressed" when the text read settles that the source does not bear on the part, and `[GAP: P<n>]` when the text read (an abstract alone, say) does not settle it;
     - a column of the literature matrix, beside the topical theme columns, holding for each source the value of the part's list from its field, or `GAP`, or empty for "not addressed";
     - a check of the gaps: each gap names the part or parts it concerns, and every part is checked for a gap;
     - a part of the synthesis (as now).
   - The merge run reads each `review-theme-<k>.md` against the parts of `config.md`. A theme report that numbers or words the parts otherwise is refused: the merge run stops before merging and reports which theme run and how; the session resumes that theme run with the recorded parts, it rewrites its fields and matrix, and the session starts the merge run again. This happens at most once per theme run; a second refusal is named in the final message and the merge run maps that report's parts onto the recorded ones, saying so in `review.md`'s limitations.
   - The relevance line of an annotation no longer carries part labels; the part fields carry them.
   - The planner reads the recorded parts: "The parts of the question without a result" (`planner.md:359`-`:361`) checks each recorded part against the materials in place of a split of its own, and the stop "A research question the materials do not answer" (`SKILL.md:329`, `:835`) names the part by its number.
2. **The judged defects** (ruling BS item 2).
   - **Gaps with their evidence.** Each gap names at least one search run for it that found nothing, by the string (or its number in the search record), the database and the record count; where none was run, the agent runs one aimed at the gap before it writes the gap. Each gap also names the matrix evidence on each side: the keys of the works that come closest to it, and the count of works in the parts or themes it lies between.
   - **The synthesis compares.** Each paragraph group compares results across the sources it cites: where they agree, where they differ, and why where the sources say. A comparison sets only like measures against each other (an F1 against an F1, a count against a count of the same thing). A "divergent finding" is two results that conflict on the same question; two results under different assumptions are stated as such, not as a debate. Each part's synthesis names the searches that found nothing (`literature-strategist.md:356`, a dropped rule of the check).
   - **A readable copy before "unfindable".** A work the search needs (a "must include", a seminal work, a core paper's reference) that no index holds is searched for a readable copy: a web search on its exact title, and the pages of its authors and their institutions. `review.md` then names the copy's address, or the searches made that found none. A work no index confirms still gets no entry and no citation (ADR 0032); its copy's address and the reason stand in "No entry written" and in the gaps or limitations it affects. The words "no readable copy was found" are written only after those searches, which are named beside them.
   - **Included only with at least the abstract read.** An included source has at least its abstract read in the run. A candidate none of the ways of "Reading a candidate" gave the abstract for is not included, whatever layer 2 or the seminal rule says of it; it is listed under a new heading of `review.md` section 3, "Not included: not read", with the indexes and pages tried named in words ("Crossref, OpenAlex, Semantic Scholar, the publisher's page, a web search on its title") and the reason it mattered (must include, seminal); the addresses tried with their statuses go to `search-log.md`. A "must include" work so listed is named in the limitations. "A candidate that cannot be read" (`literature-strategist.md:216`-`:221`) says the same.
   - **The disclosure line states only what took place.** `references/ai-disclosure.md` "The line of a review" and its template: the line names the tool and the categories as now; it says whether a person reviewed the sources, true only when the user answered the stop "The sources' review" in the run (the session records this in `config.md`), and otherwise that no person has reviewed the review; it says that the authors who use it are responsible for what they take from it. It claims no oversight, check, audit or verification that did not take place. The draft writer's and the formatter's use of the same page for a manuscript is unchanged unless a sentence there makes the same false claim.
   - **Tool names and run records out of the review** (ruling BU, choice C125). `review.md`'s search record keeps, for each search, the database, the string, the filters applied, the date, the count and the records taken into screening, and the passes with the conditions that held. The commands, the script names, the request addresses, the reply statuses, the `curl` lines, the notes `lookup.py` prints, the file names and the names of screening nodes go to `search-log.md` in the run folder; a theme run writes `search-log-theme-<k>.md`. `review.md` names `search-log.md` once, in section 1. `review.md` may name the run folder's own files (`refs.bib`, `screened-<list>.txt`, `search-log.md`); it names no file of the temporary folder. The merge run's `search-log.md` opens with the name of each theme run's `search-log-theme-<k>.md`, which stays in the run folder, and then holds the merge run's own log. The annotation's "Read from" gives the address of the text read (a URL, a DOI's address, a PMC address) or "the .bib entry's abstract field", never a command or a file. The final message lists `search-log.md`; `SKILL.md` Rules lists it among the run folder's files.
   - **The final message.** `final.md` holds the final message word for word (`SKILL.md:287`), and every report line of a strategist start that returns something to the user is in it (`SKILL.md:172`); both were dropped in rc.8. The sentences stay as they are unless the dropped-rule treatment of item 4 changes them.
3. **The role pages read for fixed shapes** (ruling BS item 3). Read every page under `skills/paper/references/` for a place where a fixed shape stands where the request or the manuscript should set it: a fixed list of columns, fields, sections, types or headings that a reader of that request would expect to follow the question, the paper type or the manuscript. A rule is never removed only because the run dropped it. The report gives a table: row number of the check, the rule's place, what the run did, the change (with `file:line` after the change), and for a reword the difference and the reason.
   - The rules of the search and reading sections that rc.8 dropped across most agents are made concrete where the agent applies them: each search string on each selected database with a record of each pair run (`literature-strategist.md:156`); relaxing a web search under 20 records (`:170`); `lookup.py search --limit 100` (`:159`); the full-text stage trying the second way (`:195`, `:205`); reading through the Read tool (`:204`); the `curl` form (`:208`); the currency passes over each database and index the search used with each string (`:280`); the merge run writing `refs.bib` from `bibtex`'s output (`:370`); the blank line between entries (`:372`); no script of the agent's own (`SKILL.md:792`), with what the agent does instead for the jobs rc.8's agents scripted (parsing a search reply, extracting an abstract from a page, counting records): read the saved reply or page with the Read tool, or `lookup.py text` and `text --abstract` on a saved page, which the Agent prompts sentence on `text` (`SKILL.md:797`) then allows the strategist as well as the citation compliance agent.
