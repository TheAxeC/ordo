## What to build

Eight parts. Each changed line is judged against the ruling sentence given with its part. A place the same rule reaches that this brief does not name is changed too and named in the report; a narrower change than the part asks for is a finding.

### 1. Agent starts (ruling 5.Q-agent-starts)

`paper` starts and resumes its agents as academic-paper does. A role's later task goes to the agent that holds the role's work, resumed with a message:

- the draft writer for each revision loop of full mode, the results-check issues (part 4), the reference fix, the compile fix, the findings pass and, when it ends a revision run, the response letter;
- the citation compliance agent for its format work after the stop "The citation style to confirm" and for each incremental check;
- the Phase 6b peer reviewer for each later round of full mode; revision's peer reviewer for the round-2 re-review and, when it ends a revision run, for the letter's check.

A new agent starts only for the first start of a role in a run, for Phases 4a, 4b, 6a and 6b, and when the agent to resume is gone; the new agent is then given the files the gone agent wrote. Steps 8 states this rule once, and each line that sends a later task says the agent is resumed. Every line of `SKILL.md` and `references/*.md` that starts an agent for a later task is changed, whether it holds the word "fresh" or reaches the start through "(Steps 8 and 9)" or "(Steps 8)". The skill's description, its opening paragraph and Steps 4 speak of a role's first start and stay true.

ADR 0043 states the rule under Decision 3 and its Decision 5 says the letter and its check go to the resumed draft writer and peer reviewer in a revision run, and to first starts in the mode `response-letter`. ADR 0029's Status line names its fresh-agent words as superseded by 0043, in the form the folder's other Status lines use (`superseded by NNNN in <the part>`). The reason, for ADR 0043: a same-role fresh start makes the output no better and costs a re-read of every input and a re-fetch of every source.

### 2. The check loop (ruling 5.Q-check-loop)

The incremental citation check of each writer patch stays. A finding of an incremental check never starts a writer pass. It is closed by the citation compliance agent's own `C<m>` patch, which gets no further check, or it is listed in the agent's report: a drift item gets suggested wording and no patch. `SKILL.md`, Steps 12, and `references/citation-compliance.md`, "The incremental check", say so in words that leave no reading under which a check starts a patch whose check starts another. The session sends no item of an incremental check's report to the draft writer; items left are named in the final message.

### 3. The citation restart (ruling 5.Q-citation-restart)

On a format error in most entries (`citation-compliance.md`, "A format error in most entries"; `SKILL.md`, Steps 12 and the Stops row "The citation style to confirm"):

- The claim and source checks of the first start stand, and the agent writes its patches for the claims in that start in every case. No source is read again because of a format error.
- When the entries are in the style the Citation Format row names, no stop is raised. The agent corrects the entries in the same start, as one patch, and logs each correction.
- When the entries are in another style than the row names, the agent leaves the entries' format uncorrected in its first start and the stop "The citation style to confirm" is raised. After the answer the same agent is resumed for the format work only, given the confirmed style: it corrects the entries as one patch and reads no source again.

ADR 0043 records this under Decision 3, in place of its bullet on the stop, as a deviation from academic-paper's failure path F5, with the reason: the restart repeated every claim and source check of the first start. The question it answered concerns the entries' format only.

### 4. The results check (ruling 5.Q-results-check)

In full, revision and citation-check, when the user's materials include result files or code, the citation compliance agent also reads:

- each statement the manuscript makes about the study's own results (single numbers, counts, lists and bounds) against the result files;
- each description of how the data were handled (missing values, imputation, recoding, cohort selection, what each variable is) against the code and the result files it rests on.

Its index is the draft writer's trace table. In full mode the draft writer writes the table as a section "Trace table" of `draft-report.md`: one row per statement about the study's own results and per description of the data handling, with the file, and the row or line, it rests on. A patch of the draft writer that adds or changes such a statement adds or changes its row. In revision and citation-check, and for a statement with no row, the agent finds the file itself.

Each statement or description the files do not bear out is an issue in the agent's report. In full and revision the session resumes the draft writer once with those issues, as a patch with the ids `R<m>`, and a patch that adds or changes a cited sentence gets the incremental check. In citation-check mode, which has no draft writer, the issues stand in the report and the final message names them. With no result files and no code, the report says these statements were not checked and the final message names it. The peer reviewer is not given the files. The check runs whatever the intake row Claim check says (part 6).

It is written in `references/citation-compliance.md` as a section of its own, in `references/draft-writer.md` for the table and the `R<m>` patch, in the patch-id table of `references/revision-patch-protocol.md`, and in the citation compliance agent's inputs in `SKILL.md` for full, revision and citation-check. The two pointers of `SKILL.md` at `references/anti-leakage-protocol.md` for a number traced to a saved run point at this rule. ADR 0043 records it under Decision 3 as a deviation, corrects its Consequences sentence on ADR 0028, and gives the reason: two full runs described the handling of missing covariates in words the cohort file contradicts. No check of academic-paper reads the study's own files.

## Cases

Each is checked by reading the skill's text; this is a text step, except the two scripts' runs.

1. A full run's peer review returns `request_revision`: the same draft writer is resumed for the rewrite, and the Phase 6b peer reviewer is resumed for the next round. On the unchanged tree both are started fresh.
2. An incremental check of a writer patch finds a drift item: the report lists it with suggested wording, no writer pass starts, and the final message names it. On the unchanged tree nothing forbids the session sending it to the draft writer.
3. A compile log holds `Overfull \hbox (4.2pt too wide)` and no error: no compile fix. `Overfull \vbox (12.0pt too high)`: a compile fix. `LaTeX Warning: Float too large` alone: no compile fix.
4. `check-urls` prints a failure for a publisher page that refuses automated requests: no reference fix; the final message names it.
5. Revision's round-2 re-review names two items as not resolved: no writer pass; both are listed as acknowledged limitations.
6. More than half the cited entries lack a DOI, in the style the Citation Format row names: no stop; one patch in the same start; no source read again.
7. More than half the cited entries are in another style than the row: the claim patches are written in the first start; the stop is raised; after the answer the same agent is resumed, corrects the entries and reads no source again.
8. The manuscript says missing covariates were imputed with the training mean, and the cohort file the user's materials hold has rows with an unrecoded missing-value code: in full mode the citation compliance agent reports it and the draft writer is resumed with it; in citation-check mode the report and the final message name it.
9. The user's materials hold no result file and no code: the report says the statements about the study's own results were not checked, and the final message names it.
10. Claim check no, in full mode: Phase 5a reads no source's text, no incremental check runs, a sentence that states a claim of Claims not to make is still flagged, and the results check of case 8 still runs.
11. Incremental checks no and Closing review yes: the intake question says the `/writing` pass's patches get no check; none runs.
12. The visualization agent meets an ambiguous figure selection: it takes the option that follows from the run's goal and records it in `config.md`; no stop.
13. The user replies to the closing review with finding numbers: the draft writer of the run is resumed with them; no new draft writer starts.
14. Every line of `skills/paper/SKILL.md` and `skills/paper/references/*.md` that starts or resumes an agent, found by `grep -n -i 'fresh\|Steps 8\|resum'` and read: each new start is a role's first start, Phase 4a, 4b, 6a or 6b, or the agent-gone fallback.
15. `python3 docs/figures/gen_figures.py` exits 0 and writes `docs/figures/paper/lifecycle.svg` and `docs/figures/paper/run-folder.svg`; each mode, call, request and file the two figures name is read against `SKILL.md` and `references/mode-selection-guide.md`.
16. The README description of `run-folder.svg` shows each name that holds angle brackets, such as `paper-runs/<mode>-<date>/`, whole in the rendered page: the brackets are written so that Markdown does not read them as a tag.
17. `python3 docs/figures/academic-paper-comparison/gen_comparison.py` exits 0 after the change, and `git status --short docs/figures/academic-paper-comparison` lists the figures whose labels changed.

## Conventions

- ASCII only, no tab, no hard wraps inside a sentence, no em dash.
- A rule file states the rule: no date, no run, no ruling name, no history in `SKILL.md`, a reference page or the glossary. Reasons and rulings go into ADR 0043.
- No comment in a script says what the code did before.
- The words "fresh agent" are used only for a start this brief allows.
