# Step 5.O, rulings on the cases of the first run

The builder of step 5.O handed back three cases of the brief that its first run showed wrong. This file rules on each. The brief `.scratch/5-paper/agents/briefs/5.O.md` holds whole except where a ruling below changes it. Under `.scratch/` you read the brief and this file.

## A. DBLP

The `dblp` command stays: the ruling The lit-review run under the rules names a work's DBLP venue record, and dropping the command would undo that ruling.

- The search interface `https://dblp.org/search/publ/api` answers a client with no browser by an HTML page with status 202. The session's run: `curl -s -o dblp.html -w '%{http_code} %{content_type}\n' -A 'lookup.py' 'https://dblp.org/search/publ/api?q=attention+is+all+you+need&format=json'` printed `202 text/html; charset=utf-8`, and the page's title is "Making sure you&#39;re not a bot!".
- DBLP's SPARQL endpoint `https://sparql.dblp.org/sparql` answers. The session's run, a POST of the query with `Accept: application/sparql-results+json`, printed `200 application/sparql-results+json` and the binding `https://dblp.org/rec/conf/nips/VaswaniSPUJGKP17` with venue `NIPS` for the exact title "Attention is All you Need.". A query with `FILTER(CONTAINS(LCASE(?t), "attention is all you need"))` over `dblp:title`, `dblp:publishedIn`, `dblp:yearOfPublication` and the record's type returned its bindings in 3.6 s.
- Build `dblp` on the SPARQL endpoint: for each title, one query on the title's words, lower-cased; the hits filtered by the title ratio of 0.70 or more after they are read; each hit printed with its venue, year, pages where the record has them, type and DBLP key; a CoRR record marked as such.
- The pacing host, the lock file `ordo-lookup-dblp`, the skip file `ordo-lookup-skip-dblp` and the gap of 2 s are those of the brief, for the host `sparql.dblp.org`.
- Case N17 becomes: when DBLP answers an HTML page with status 202, DBLP is left out with "HTTP 202", as the existing rule for a status other than 200 or 404 prints it. Add a case where the endpoint answers 200 with a body that does not parse: DBLP left out with "HTTP 200, the body does not parse".
- The head comment says that `dblp` asks DBLP's SPARQL endpoint, since its search interface answers no client without a browser.

## B. A DOI holding `|` or `,`

OpenAlex reads `|` as OR inside a filter value even when it is sent as `%7C`. The session's run of `https://api.openalex.org/works?filter=doi:10.1103/physreve.69.066138%7C10.1038/nature14539&select=doi` returned count 2 with both DOIs.

- A DOI holding `|` or `,` is never put in a batch filter. It is asked alone: OpenAlex `works/doi:<encoded DOI>`, Crossref `works/<encoded DOI>`.
- Every record of a batch reply is matched to its input by its DOI, compared without regard to case.
- Case N9 (a SICI DOI in a batch) stays as the brief writes it. Add a case: a DOI holding `|` among two others is asked alone and its record printed in its own block.

## C. Parentheses

- `(` and `)` are percent-encoded inside the new batch filters only, as case N9 asks.
- `quote_doi` and its test "DOI in a URL keeps its parentheses" stay unchanged, for the requests of a single identifier.
- The brief's sentence "An identifier with a character a URL or a filter reads ... is percent-encoded in every request it reaches" is read with this ruling and B.

## The wording the tests fixed

The lines the new tests expect are taken as the build's wording:

Each is written into the head comment as the command's output.
