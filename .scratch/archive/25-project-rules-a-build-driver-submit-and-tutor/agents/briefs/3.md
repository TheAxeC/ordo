## What to build

1. The template `skills/ordo/ordo-init/templates/utils/build.py`, on the Python standard library only, for Python 3.10 or later, written to `templates/docs/dev/coding-standards/python.md`. Its first line is `#!/usr/bin/env python3` and the file has mode 755, so that `./utils/build.py gate` runs. Near its top it holds three lists of shell commands, one each for `build`, `test` and `check`, and one value that gives the repository root as a path relative to the script's own folder; the mode fills the four, and the template's own lists are empty and its root value is the folder above the script's folder. Each command in a list may have a comment beside it. Its subcommands:
   - `build`, `test`, `check`: run that list's commands in order. Each command runs as the list of arguments `bash -o pipefail -c <command>`, never with `shell=True`, from the repository root, with standard input from `/dev/null`, and is echoed before it runs. The first command that exits non-zero ends the run: the driver's last line names the command and its exit status, and the driver exits non-zero. All passing, the driver's last line says how many commands of that subcommand passed, and it exits 0.
   - `gate`: runs `build`, then `test`, then `check`, and stops at the first that fails, with that exit. `gate` skips a list that is empty, and with all three lists empty it says that no command is named and exits non-zero.
   - `build`, `test` or `check` called on an empty list says that no command is named for it and exits non-zero.
   - No subcommand, an unknown one, or an extra argument prints the usage and exits 2.
   - A command ended by a signal gives a non-zero exit.
   - The driver imports no file of the repository and writes no file, a bytecode file included.
   The script has a head comment that says what it does and how a command is added, and no history.

## Cases

Each case is a case of `build.test.sh` unless it says "by reading".

- `gate` on a scratch tree whose three lists each hold a passing command: expected: exit 0, each command echoed in the order build, test, check.
- `gate` where the `test` list's second command is `sh -c "exit 3" 2>&1 | tail -1`: expected: a non-zero exit, the last line naming that command and its status, and no `check` command run.
- `test` on a list of two commands, the first failing: expected: non-zero, the second not run.
- A command `false && echo reached`: expected: non-zero, and `reached` not printed.
- A command with a trailing `# comment`: expected: run, the comment ignored by the shell.
- `build` on an empty list: expected: the line that no command is named for `build`, non-zero.
- `gate` with `build` empty and `test` and `check` passing: expected: exit 0.
- `gate` with all three lists empty: expected: non-zero, the line that no command is named.
- No subcommand; `frobnicate`; `gate extra`: expected: the usage, exit 2.
- A command that holds a pipe and a quoted argument with a space: expected: run as written.
- A command that holds `'`, `"`, `$`, and the backslash sequences `\0` and `\x20` inside a single-quoted argument, printed by the command to a file: expected: the file holds the argument's characters as the command wrote them.
- A command that changes directory: expected: the next command still runs from the repository root.
- The driver called from another working directory by its path: expected: the commands run from the repository root.
- A driver in `tools/a/utils/` of the scratch tree, its root value filled for that place: expected: the commands run from the scratch tree's root.
- A command that reads standard input (`cat`): expected: it ends at once with no input.
- A command ended by a signal (`kill -TERM $$` in a subshell): expected: non-zero.
- `./utils/build.py gate`, the copy called by its path with no `python3` in front: expected: it runs.
- After any run: expected: the scratch tree holds no `__pycache__` folder.
- By reading: `/ordo-init build` in a repository with no `plan.yaml`: expected: the refusal that names `/ordo-init`.
- By reading: `/ordo-init build` on a page with no command: expected: the refusal that names the page.
- By reading: `/ordo-init build` run a second time: expected: the lists are read from the driver, and no list names `utils/build.py`.
- By reading: `/ordo-init build` where a `utils/build.py` of another kind stands: expected: the stop, and no write before the user's answer.
- By reading: `/ordo-init ./build`: expected: the folder `build` is the path, and no mode runs.
- By reading: a page command that holds `\0` and quotes: expected: the read-back holds it equal to the page's text, or the run stops with the difference.
- By reading: a new-repository run where the user answers that no driver should be written: expected: no `utils/build.py`, and the verification page holds the commands themselves.
- By reading: an existing-repository run: expected: no driver, the mode named.

## Decisions taken in this brief (each reversible, none silent)

1. The commands live in three lists at the top of `utils/build.py`, with no configuration file beside it.
2. The driver stops at the first failing command, and its last line is the failure line, or on a pass the count of commands passed.
3. Usage errors exit 2; a failing command gives the command's own status where that is between 1 and 125, and 1 otherwise.
4. The repository root is a value the mode fills, relative to the script's folder, so the driver needs no git and works in the `projects:` form.
5. The page's lines read `python3 utils/build.py <subcommand>` with no filter of their own, since each command keeps its own filter inside the driver.
6. The read-back after the write is a parse of the file, never a compile, so no bytecode file is written.
7. The question on the driver is added after the last of "The questions".
