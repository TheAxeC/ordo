## Decisions taken in this brief (each reversible, none silent)

1. `self_rule` and `next_entry` are checked as booleans, since PyYAML reads `on` and `off` as `True` and `False`; `yes` and `no` therefore pass too, as they do for `refute_after_repair`. The error names `on` and `off`, the words the skills use.
2. The template writes `repair_reviewer: claude:opus` with the comment `optional, default the reviewer value.`; `example_keys` then reads the default as the text `the reviewer value`, and `check_config.py` replaces the generic note for this key with one naming the configured `reviewer`; the key is value-checked, so its default's kind is never compared. Real cases from the templates' comment form, input and output of `example_keys`'s pattern: `repair_rounds: 1  # optional, default 1. ...` gives `1`; `look: ""  # optional, default "". ...` gives `''`; `adr: docs/adr  # optional, default docs/adr. ...` gives `'docs/adr'`; `design_references: []  # optional, default []. ...` gives `[]`; `repair_reviewer: claude:opus  # optional, default the reviewer value. ...` gives `'the reviewer value'`, a string, so the kind check against a configured `claude:sonnet` passes.
3. `next_entry` on with `self_rule` off is a note, not an error: the configuration is valid, and the key simply has no effect, as the goal's "with `next_entry: on` as well" says.
4. The state file template's values are `off`, `off` and `claude:<model>`, in the block's placeholder style for a model.
