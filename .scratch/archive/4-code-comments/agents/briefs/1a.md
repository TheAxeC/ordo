## What to build

When the part is done, `/code-comments` never asks the session to type file text into an agent's prompt. The session builds each agent's prompt as a file with shell commands, and gives the agent a short prompt that names that file. A reviewed file over 256 KB reaches the agents as its diff hunks with 40 lines on either side, and the report names it.

1. **The prompt folder.** After the last refusal of the review (Steps 4, the effort check), the session makes a prompt folder with `mktemp -d "${TMPDIR:-/tmp}/code-comments-prompt.XXXXXX"`, the first write of the review. Each review agent gets one prompt file in it, `finding.md` and `checking.md`. The rewrite makes its own prompt folder the same way at "The rewrite" 4, after the refusals of its items 1 to 3, beside its scratch folder, and its agent gets `rewrite.md` there. The scratch folder of the copies stays a folder of its own, so no prompt file can stand at a repository path.
2. **The session does not read the files.** Steps 3 lists the files and raises its refusals as it does now, but the session no longer reads each file's text into its own context: the text goes from the commands straight into the prompt file. Steps 3's "Done when" and Steps 5's "Hold the output" say the text is written into the prompt file.
3. **How a prompt file is written.** The session writes the pieces with shell commands that append to the file (`>>`), so it never retypes a file's text:
   - the diff, by the `git diff` command Steps 3 gives, with `--no-color`;
   - each reviewed file under a heading line that names its path, by `cat -n -- '<path>'` or `git show '<head>:<path>' | cat -n`, or by the hunk command of item 4 for a file over 256 KB;
   - for an untracked file of the default call, a heading line that says the file is untracked and added whole, written by `printf`, then the file whole;
   - the non-ASCII output of Steps 5, by the same commands; for a file given as hunks, only the hits on its hunks' lines;
   - the rules of "Rules of a comment", the prose standard's sections 0, A, B, C and E, and the agent's bullets, each copied unchanged from the skill's own file and the prose standard's file by a command that prints the section, such as `sed -n` over the lines between two headings, with the absolute path of each file single-quoted;
   - for `checking.md`, the list of the files given as hunks with each one's size in bytes, or that none was; the finding agent's final message; and the text of each rule a finding names;
   - for `rewrite.md`, the picked findings with their numbers.
   - The finding agent's final message and the picked findings are the only text the session writes itself, with its file-writing tool, copied whole from the agent's completion notice and from the report shown; every other piece is written by a command the skill gives.
4. **A file over 256 KB.** A reviewed file whose size is over 262144 bytes, measured by `wc -c < '<path>'` or `git show '<head>:<path>' | wc -c`, is given as its hunks: for each hunk header `@@ -a,b +c,d @@` of `git diff --no-ext-diff --no-color --find-renames --unified=40 <the diff's ends> -- '<old path>' '<new path>'` (the one path when the file was not renamed), a heading line `lines <c>-<c+d-1> of <path>` and those lines of the file as `cat -n` numbers them. A count left out of the header (`+c`) is 1. git joins two hunks whose 40-line margins touch, so no line stands twice. The same rule holds for the rewrite agent's files. A file added whole by the diff, and an untracked file, has one hunk, the whole file, and is given whole. A file over 256 KB with no hunk, as a pure rename or a mode change, is named in the list of item 3 with no lines.
5. **The report names the large files.** The checking agent's report opens with a line that names each file given as hunks, with its size in bytes, or says no file was, from the list in `checking.md`; the "Checking agent" bullets ask for the line.
6. **The agent's prompt.** Each agent's prompt, the text the session types, is: the agent's role, the absolute path of its prompt file, that the agent reads that file whole, every line, in parts when its read tool cuts it, and that the file is the only file it reads. The rewrite agent also reads and edits the files its picked findings name, since it edits them. The pieces lists of Steps 6, 7 and "The rewrite" 5 become the pieces of the prompt file.
7. **The bullets.** In "Finding agent" and "Checking agent", the bullet "Work from the prompt alone: edit no file, start no agent, invoke no skill, run no command and read no file." becomes five bullets, one rule each, as `docs/dev/skill-layout.md`, "Lists and tables", asks: the agent reads its prompt file and no other file; it edits no file; it starts no agent; it invokes no skill; it runs no command. The first bullet of "Finding agent" ends "read in the file as the prompt file gives it". The two bullets of "Finding agent" that say "given in the prompt" and "as the prompt names it" say "the prompt file". "Rewrite agent" says it reads its prompt file whole, and reads and edits only the files the picked findings name.
8. **Removing the prompt folder.** The session removes the review's prompt folder with `rm -rf '<prompt folder>'` after the checking agent ends and before the report is shown, and on the stop "A model other than the configured one". The rewrite removes its prompt folder with its scratch folder at "The rewrite" 8, and at the stop of "The rewrite" 5. The rewrite's final message, the stop's message of "The rewrite" 5 and the first Stops row's "What it shows" name both folders removed.
9. **Every other place.** "What it reads" 4, Steps 3, 5 and 8, the Rules bullets "Each review agent gets each reviewed file whole with its line numbers, since a comment is judged against the code around it." and "The rewrite agent gets each file its picked findings name whole with its line numbers, for the same reason.", the Rules bullet "The review writes no file and changes nothing.", the description in the frontmatter and the opening paragraph say the same as items 1 to 8 where they speak of files reaching the agents or of what the review writes. The Rules say the review writes only its prompt folder, outside the repository, and removes it. An Anti-patterns row names the session typing a file's text into a prompt: a typed copy can drop or change a line, and a large diff cannot be typed at all; the remedy is the prompt file of item 3.
10. **ADR 0014.** The first clause of its Decision, "A fresh agent that changes nothing reads the diff, each changed file whole and the rules, and reports findings", says the agent reads them from a prompt file the session writes with shell commands, each changed file whole, or as its diff hunks with 40 lines on either side when it is over 256 KB. No dated note, as `docs/adr/README.md` says. Its title and the rest stay.

## Decisions taken in this brief (each reversible, none silent)

1. The size limit is "over 262144 bytes", 256 KB being 256 times 1024, measured with `wc -c`.
2. The 40 lines on either side come from `git diff --unified=40`, so git computes the margins and joins hunks that touch; the hunk's lines are taken from the `cat -n` text so that each line keeps its number in the file. Five real cases from the gate's range, each run with the command of item 4 (the heading lines it printed, then `wc -c` of the part):
   - `docs/user/manual.html`: `lines 1160-1264`, `lines 1433-1513`, `lines 1827-1907`; 128091 bytes.
   - `src/core/include/missal/core/collections/hashmap.hpp`: `lines 86-166`, `lines 182-271`, `lines 309-404`; 13219 bytes.
   - `src/engine/tests/src/main.cpp`: `lines 89-170`, `lines 2728-2809`; 11094 bytes.
   - `src/engine/groups/CMakeLists.txt`: `lines 1-40`; 2475 bytes.
   - `src/engine/save/include/save/save_container.h` (added): `lines 1-176`, the whole file; 10704 bytes.
   Each part reads as the file's own numbered lines under a heading that names them; only `manual.html` is over the limit, and the other four show the format on code.
3. A file added whole, and an untracked file, is given whole, since its one hunk is the whole file, as ruling C's words give it.
4. Each agent gets its own self-contained prompt file, so the checking agent's file holds the diff and the files again; this keeps each agent's input in one file it reads whole.
5. The prompt folder is separate from the rewrite's scratch folder, so a prompt file never shares a path with a copy.
6. The report's line naming the large files is written by the checking agent from a list the session puts in `checking.md`, since the report is the checking agent's final message, shown whole.
7. `metadata.version` stays `"1.0.0"`, since this plan created the skill and `docs/dev/skill-layout.md`, "Frontmatter", raises a version once per plan.
8. The rewrite agent reads and edits the files its picked findings name besides its prompt file, since it edits them; ruling C's "the only file it reads" holds for the review agents.
9. The finding agent's final message and the picked findings are written into the prompt files by the session's file-writing tool, copied whole: they are short, they exist only in the runner's notice and in the report shown, and the checking agent checks each finding's quote against the file text the commands wrote.
10. "Prompt folder" and "prompt file" are plain words the skill defines where it makes them, as it does "scratch folder", and get no glossary entry.
11. For a file given as hunks, the non-ASCII output keeps only the hits on its hunks' lines, since a hit outside them stands on no line the agent has.
