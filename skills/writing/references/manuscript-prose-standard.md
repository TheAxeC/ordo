# The manuscript prose standard

The prose of a manuscript is held to the prose standard, read where `SKILL.md` "What it reads" 2 finds it, with the differences this page lists. The prose of a manuscript is the text of a paper, its abstract, its statements and its cover letter. The page holds no copy of the prose standard's rules. A rule of the prose standard that this page does not name holds for a manuscript as the prose standard states it.

## Rules left out

These rules of the prose standard concern software documentation, a terminal, a diff or Markdown source, and they do not hold for a manuscript:

- Section A, Vocabulary: "sub-second" and "most requests" in the list of vague qualifiers.
- Section B: ASCII throughout.
- Section E: Spec-sheet voice.
- Section E: Personified artifacts.
- Section E, Sentence length: the exception for a sentence in the reason cell of a coverage table. The rest of the rule holds.
- Section F: Inline code.
- Section F: Source formatting.

## Rules replaced

- Section 0, Arrows: arrows stand only inside mathematics, never as prose punctuation. A sentence that uses one is rewritten.
- Section D, Paragraphs: a paragraph covers one idea and runs about 120 to 200 words. It may run past four sentences, and each sentence keeps the limit of section E, Sentence length. A paragraph that covers two ideas is split, and a paragraph far outside that length is split or joined with its neighbour.

## G. The project's own software

- **No software wording.** The text of the manuscript names no file, script, program of the project, path, folder, code identifier, job, run, exit code or log. It uses no wording of software operations about the project's own work, such as "ran successfully", "exited with code 0", "crashed", "stdout" or "the pipeline". A result is worded as a statement about the study: "all nine subjects were evaluated under the same leave-one-subject-out procedure", never "all 9 run folders exited with code 0".
- A name the paper's field uses for a method, a dataset, a tool or a library is a term of the field. It is written as the field writes it. A repository URL in a data or code availability statement is a statement's content.
